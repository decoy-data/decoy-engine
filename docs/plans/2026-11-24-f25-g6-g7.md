## 2. Guarantee and non-goals

Guarantee, after this plan and the open 4c slices:

1. Every engine scratch directory is made under one root, which one function in `fileaccess` names. The disk preflight and the runtime disk cap measure that same root. If `TMPDIR` is set but unusable, the run refuses; it does not fall back to `/tmp`.
2. On POSIX, every engine scratch directory that holds table data is a child of a `ScratchArena`: owner-only, flock-held, marker-proven. A killed run leaves only arenas, which the row 74 sweep can prove and reclaim. On Windows, the same producers keep working through a named fallback until 4c slice S1w (H1).
3. Transport bound (H5): no profile reader asks a cloud store for more than 8 MiB in one response, except one Parquet column chunk or footer, and no reader makes an unsized read. The parsed frame is the caller's; this plan does not bound it.
4. The isolated route reads staged outputs back into the parent only up to a cap on decoded Arrow bytes, checked as it reads. It overshoots by at most one staged row group (H2).
5. The at-rest state of each scratch path is written down: protected by mode and ownership, not encrypted.

Non-goals:

- Byte quotas (row 58b, release 1.3).
- The orphan sweep (row 74, F26 E3) and publication-stage reclaim (row 74b).
- Encryption of spill (owner question Q2).
- An SFTP table reader (owner question Q3).
- `to_frame` still returns a whole frame. That is its contract.
- A native arena on Windows (4c slice S1w). This plan does not break Windows either: see B3a.
- The DuckDB spill directory. `untrusted_session` (`fileaccess/adapters/duckdb.py:45-50`) sets no `temp_directory`, so DuckDB defaults to `.tmp` in the working directory. 4c slice S3b (T17) closes that; this plan depends on it for guarantee 1 and does not duplicate it (M4).

Size: about 16 source files change. New public names in `decoy_engine.__all__`: none. New engine-internal names: `fileaccess.scratch_root()`, `fileaccess.stage_scratch()`, `ISOLATED_READBACK_MAX_BYTES`, the kwarg `readback_max_bytes` on `run_pipeline_isolated`, the field `IsolatedRunResult.outputs_withheld`, and three reason codes. `run_pipeline_isolated` is exported from `decoy_engine.execution` (`execution/__init__.py:90`, :179); its signature only grows a keyword with a default. `protected_scratch_dir` stays exported (`__init__.py:128`, `__init__.py:559`), but engine code outside `fileaccess` stops calling it.

Behavior after G6:

- B1. `fileaccess.scratch_root()` returns the one base directory. `_parent_base(None)` and `default_ooc_temp_root()` both return it. Nothing else in engine source calls `tempfile` or reads `TMPDIR`, `TEMP` or `TMP`.
- B1a. If one of `TMPDIR`, `TEMP` or `TMP` is set and names a path that is missing, not a directory, or not writable, `scratch_root()` raises `FileAccessUnavailable` with the new value-free reason `runtime.scratch_root_unusable`. The message names the variable, not its value. It does not fall back to `/tmp` (M3).
- B2. `resolve_temp_disk_budget(root)` takes the root the run spills under. The route passes the arena's parent, and `run_fk_out_of_core` measures its given `temp_dir` the same way. The cap stays 0.9 of the free bytes at that root (`execution/_pipeline_route_exec.py:64`), or `None` when `disk_usage` fails.
- B3. `fileaccess.stage_scratch()` is a context manager. On POSIX it opens one `ScratchArena.fresh()` and yields it. Each pipeline stage opens it once at stage entry and hands `create_dir(name)` children down to its producers (4c rule I2), using `create_dir(...).local_path()`, the transitional arm (a) the out-of-core runner uses (`execution/out_of_core/_runner.py:275`). There is one arena per stage entry, not one per producer (M5). The stage entries are: the post-scan stage (covering `_post_scan.py:249`, :360 and :411, `verification/postmask/runner.py:119` and `verification/postmask/fk_preservation.py:71`, which take the child they are given) and the subset stage (`_subset_stage.py:149`). `engine_scratch_root` is deleted. 4c slice S4b later ends arm (a) everywhere.
- B3a. On win32, `stage_scratch()` yields a fallback with the same `create_dir(name).local_path()` surface, built on `protected_scratch_dir` under `scratch_root()`. It lives in `fileaccess/_scratch_win32.py` and is deleted by 4c slice S1w. Windows keeps today's behavior: owner-only directories, no marker, no lock (H1).
- B4. The Parquet transactional sink gets `open_spill_scratch`, the hook the callable adapter already has (`execution/_transactional_sink.py:114-130`), backed by `stage_scratch()`. Its hold-back spills into an arena child, not beside the target (owner question Q1). The `output_dir(... "_hold")` arm in `_make_stage` goes. The `hold` label leaves `STAGE_PREFIX` if no user is left.
- B4a. Policy change, stated (M11): the hold-back was a policy-issued `TARGET_OUTPUT` stage. After B4 it is engine scratch under the scratch root, which the file-access policy does not issue, the same as every other spill (4c E5b states the same for the out-of-core spill). A strict policy that names only the output directory no longer sees the hold-back. A test pins this.
- B5. Disk cap: the hold-back spill is checked against the same `resolve_temp_disk_budget` as the out-of-core spill. Over the cap, the run refuses with the existing `runtime.hold_back_spill_unavailable` (`reasons/runtime/_part1.py:213`).

### 4.2 G7: bounded cloud reads and the isolated cap

Behavior after G7:

- B6. Parquet `to_frame` (S3 and GCS) opens `pq.ParquetFile` over `_RangeFileReader` with `pre_buffer=False`, reads it with `iter_batches`, and builds the frame with `pa.Table.from_batches(batches, schema=pf.schema_arrow).to_pandas()`. Passing the schema keeps an empty file valid (`iter_batches` yields no batch) and keeps the pandas index metadata, categoricals and timezones, so the frame matches `pd.read_parquet` (M10). Each range request covers one column chunk or the tail and footer.
- B6a. `_RangeFileReader.readinto` refuses a short read: if `fetch` returns fewer bytes than asked inside the object size, it raises `source_changed`. Every range in one read is pinned to the version its size came from: S3 passes `IfMatch=<ETag from the HEAD>`, GCS passes `if_generation_match=<generation>`. A 412 or a precondition failure becomes `source_changed` (M2).
- B7. CSV `to_frame` (S3 and GCS) passes a buffered stream to `pd.read_csv`. S3: a `RawIOBase` over `iter_chunks(1 MiB)` from one `get_object` with `IfMatch`. GCS: `gcs_open(blob, "rb", chunk_size=8 MiB, if_generation_match=...)`; `gcs_open` (`connectors/_clients.py:236`) gains the two keyword arguments.
- B8. The CSV sample keeps its doubling windows, but the total bytes fetched for one sample are capped at 64 MiB (M1). Windows are 1, 2, 4, 8, 16 and 32 MiB (63 MiB), then one last window up to the 64 MiB total. If `n + 1` rows are not in those bytes and the object is larger, the sample refuses with the new value-free reason `connector.sample_window_exceeded` in the existing `connector` namespace (M8). Today it reads the whole object.
- B9. `_s3_full` and the range-less `gcs_download` call go. `gcs_download` keeps its name, and a range becomes required.
- B10. The isolated read-back cap (H2). `collect` (`execution/_isolated_commit.py:188-211`) opens every admitted staged file once, on one `ExitStack` of N file-access handles, and never reopens a file by path (M11). It then:
  1. Pre-check: sums the footer `total_byte_size` over all row groups. If the sum alone is over the cap, it stops before reading any row group. This is a fast refusal only; the footer is written by the child and is not trusted.
  2. Reads each file with `ParquetFile(handle).read_row_group(i)`, one row group at a time, and adds each row group's `Table.nbytes` to a running total. When the total passes the cap, it drops what it has read and stops. The overshoot is at most one row group.
  3. To bound that row group, the child's staging writer (`execution/_isolated_common.py:503-509`) writes row groups of at most 65,536 rows.
- B10a. The cap is `readback_max_bytes` if given, else `mem_cap_bytes` if given, else `ISOLATED_READBACK_MAX_BYTES = 2 GiB` (owner question Q4). `readback_max_bytes=0` means "do not read back": the result is `completed`, `outputs={}`, `outputs_withheld=True`, with or without an `output_dir` (H3).
- B11. Over a cap above 0, with an `output_dir`: the publication commits as today, and the result is `completed` with `outputs={}` and `outputs_withheld=True`. Over a cap above 0 with no `output_dir`: the stage is discarded and the result is `crashed` with the new reason `decoy.isolated_readback_over_cap`, next to the other isolated reasons (`reasons/decoy/_core.py:138-150`, M8). Both messages name the cap and the byte count only, never a table value. The error has `__cause__` and `__context__` set to `None`.
- B11a. The probe (`execution/_probe.py:283-292`) measures the child's peak and never uses `outputs`. It treats any outcome other than `completed` as inconclusive. It passes `readback_max_bytes=0`, so a large probe stays `completed` and auto-routing does not lose its measurement (H3).
- B12. The SFTP connector keeps its 1 MiB read. A connector test pins it. `build_profile_source` keeps refusing `sftp`, already pinned by `tests/unit/profile/test_bounded_profiling.py:271` (L3).

## 6. Design notes

- One root, one function. The bug class here is two places deriving one fact. `scratch_root()` sits in `fileaccess/_protected_dir.py` beside `_parent_base`, which already owns root creation, so the dependency points from `execution` into `fileaccess`, as the import layers require.
- One stage scratch entry point. `stage_scratch()` is the only way engine code outside `fileaccess` gets scratch. It hides the win32 fallback, so the producers do not branch on the platform, and S1w deletes the fallback in one place.
- Producers take a child, not an arena. One arena per stage entry, children handed down (4c rule I2), so a killed stage leaves one arena to sweep.
- The cloud fix reuses `_RangeFileReader`, the connectors' read sizes and the S3 `IfMatch` pattern. The only new class is one `RawIOBase` adapter over an S3 body, about 30 lines, in `profile/_cloud_readers.py`.
- The isolated cap counts what it actually holds (Arrow bytes), not what the child claims.
- No new storage, cache or setting. `TMPDIR` stays the only override for where scratch goes.
