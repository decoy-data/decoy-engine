## 2. Guarantee and non-goals

Guarantee, after this plan and the open 4c slices:

1. Every engine scratch directory is made under one root, which one function in `fileaccess` names. The disk preflight and the runtime disk cap measure that same root.
2. Every engine scratch directory that holds table data is a `ScratchArena`: owner-only, flock-held, marker-proven. A killed run leaves only arenas, which the row 74 sweep can prove and reclaim.
3. No profile reader holds a whole cloud object in RAM as bytes. The extra RAM a read needs is bounded by one Parquet row group or one 8 MiB read buffer, not by the object size.
4. The isolated route does not read staged outputs back into the parent above a stated cap.
5. The at-rest state of each scratch path is written down: protected by mode and ownership, not encrypted.

Non-goals:

- Byte quotas (row 58b, release 1.3).
- The orphan sweep (row 74, F26 E3) and publication-stage reclaim (row 74b).
- Encryption of spill (owner question Q2).
- An SFTP table reader (owner question Q3).
- `to_frame` still returns a whole frame. That is its contract. The bound is on the raw bytes held next to the frame.
- Windows (4c slice S1w).

Size: about 14 source files change. New public names in `decoy_engine.__all__`: none. New engine-internal names: `fileaccess.scratch_root()`, `ISOLATED_READBACK_MAX_BYTES`, the kwarg `readback_max_bytes` on `run_pipeline_isolated`, and two reason codes. `protected_scratch_dir` stays exported (`__init__.py:128`, `__init__.py:559`), but engine code stops calling it.

## 3. Established solutions

Surveyed before design. The plan adopts each one rather than writing a new mechanism.

| Need | Established method | Source | What we take |
|---|---|---|---|
| One temp root, user-overridable | `tempfile.gettempdir()` honors `TMPDIR`, `TEMP`, `TMP` | Python stdlib docs | Keep it as the base, call it in one place only. `TMPDIR` is the override; no new setting. |
| Scratch dirs a crash can leave | marker plus lock, then sweep (systemd-tmpfiles with flock; Postgres removes `pgsql_tmp` at start) | systemd-tmpfiles(5); Postgres `RemovePgTempFiles` | Already built as `ScratchArena` (`fileaccess/_scratch.py:212-238`). Convert the remaining producers to it. |
| Ranged Parquet reads | `pyarrow.parquet.ParquetFile` over a seekable file reads the footer, then column chunks by range; `iter_batches` goes one row group at a time; `pre_buffer=False` stops coalesced read-ahead | Apache Arrow Python docs | Reuse `_RangeFileReader` (`profile/_cloud_readers.py:52-96`) for `to_frame`, not only for the sample. |
| Streamed CSV over a network body | `pandas.read_csv` on a file object reads in buffered blocks; gcsfs, s3fs and smart_open all pass a stream, never whole bytes | pandas IO docs; fsspec (default 5 MiB block) | Pass a `RawIOBase` over the stream to `read_csv`. |
| GCS stream | `Blob.open("rb", chunk_size=...)` returns a `BlobReader` with a fixed read-ahead | google-cloud-storage `fileio.py:25`, `DEFAULT_CHUNK_SIZE = 40 * 1024 * 1024` | Pass `chunk_size=8 MiB` so the buffer is stated, not the 40 MiB default. |
| S3 stream | botocore `StreamingBody.iter_chunks(chunk_size)` | botocore `response.py` | Already used by the connector (`connectors/s3.py:56`). Reuse the same 1 MiB size. |
| SFTP stream | paramiko `SFTPFile.read(n)`, optional `prefetch()` | paramiko `sftp_file.py` | Already used (`connectors/sftp.py:321-334`). No change; a test pins it. |
| Decoded size before reading Parquet | `pq.read_metadata(...).row_group(i).total_byte_size` gives the uncompressed size from the footer | Parquet format spec, `RowGroup.total_byte_size` | The isolated read-back cap checks this sum before any table is read. |

### 4.1 G6: one scratch root

The facts on main:

- Eight engine call sites still make a plain `protected_scratch_dir` root with no marker and no lock, so no sweep can prove them:
  - `execution/pipeline/_post_scan.py:249`, :360, :411
  - `verification/postmask/fk_preservation.py:71`

  - `execution/_isolated_run.py:368` (4c slice S3a)
  - `execution/out_of_core/_scratch.py:18-22`, `engine_scratch_root`, used by the subset stage at `execution/pipeline/_subset_stage.py:149`
- The Parquet transactional sink spills its hold-back into an A-4 `hold` stage beside the target (`execution/_chunked_output_sink.py:477-496`, `execution/_transactional_sink.py:439-444`, prefix `_decoy_hold_` in `fileaccess/_output.py:45-56`). No sweep and no reclaim covers it: `fileaccess/_reclaim.py:38` covers `publication` stages only.
- `_decoy_stage_` (`fileaccess/_output.py:45-56`) has one user, the fixed-width writer (`profile/_fixed_width_writer.py:319`). It holds the final output while it is written. It is a publication stage, not scratch (owner question Q5).
- The postgres snapshot spill (`connectors/postgres_snapshot.py:400`, :423-430) is 4c slice S3b.
- Outside `fileaccess/`, the only raw `tempfile` call in engine source is `_spill_estimate.py:521`.

Behavior after G6:

- B1. `fileaccess.scratch_root()` returns the one base directory. `_parent_base(None)` and `default_ooc_temp_root()` both return it. Nothing else in engine source calls `tempfile`.
- B2. `resolve_temp_disk_budget(root)` takes the root the run spills under. The route passes the arena's parent. The cap stays 0.9 of the free bytes at that root (`execution/_pipeline_route_exec.py:64`), or `None` when `disk_usage` fails.
- B3. The six non-4c call sites in the list above open `ScratchArena.fresh()` and use `create_dir(...).local_path()`, the same transitional arm (a) the out-of-core runner uses (`execution/out_of_core/_runner.py:275`). `engine_scratch_root` is deleted. 4c slice S4b later ends arm (a) everywhere.
- B4. The Parquet transactional sink gets `open_spill_scratch`, the hook the callable adapter already has (`execution/_transactional_sink.py:114-130`). Its hold-back spills into an arena child, not beside the target (owner question Q1). The `output_dir(... "_hold")` arm in `_make_stage` goes. The `hold` label leaves `STAGE_PREFIX` if no user is left.
- B5. Disk cap: the hold-back spill is checked against the same `resolve_temp_disk_budget` as the out-of-core spill. Over the cap, the run refuses with the existing `HOLD_BACK_SPILL_UNAVAILABLE`.

### 4.2 G7: bounded cloud reads and the isolated cap

Behavior after G7:

- B6. Parquet `to_frame` (S3 and GCS) opens `pq.ParquetFile` over `_RangeFileReader` with `pre_buffer=False` and reads it with `iter_batches`, one row group at a time, then concatenates. Raw bytes held at once: at most one row group's column chunks plus the tail and footer.
- B7. CSV `to_frame` (S3 and GCS) passes a buffered stream to `pd.read_csv`. S3: a `RawIOBase` over `iter_chunks(1 MiB)`. GCS: `gcs_open(blob, "rb", chunk_size=8 MiB)`. Raw bytes held at once: at most 8 MiB plus the pandas parser block.
- B8. The CSV sample window stops at 64 MiB (windows 1, 2, 4, ... 64 MiB, at most 7 fetches). If `n + 1` rows are not in 64 MiB and the object is larger, the sample refuses with a new value-free reason, `profile.cloud_sample_window_exceeded`. Today it reads the whole object.
- B9. `_s3_full` and the range-less `gcs_download` call go. `gcs_download` keeps its name, and a range becomes required.
- B10. The isolated route reads the staged outputs back only when their decoded size is at most the cap. Decoded size is the sum of `total_byte_size` over every row group in every staged file's footer. The cap is `readback_max_bytes` if given, else `mem_cap_bytes` if given, else `ISOLATED_READBACK_MAX_BYTES = 2 GiB` (owner question Q4). The check runs in `collect` (`execution/_isolated_commit.py:188-211`), before `_read_staged` (:214-218), through the same file-access handle.
- B11. Over the cap with an `output_dir`: the publication commits as today, and the result is `completed` with `outputs={}` and `outputs_withheld=True`. Over the cap with no `output_dir`: the stage is discarded and the result is `crashed` with the new reason `runtime.isolated_readback_over_cap`. Both messages name the cap and the decoded size in bytes only, never a table value.
- B12. The SFTP connector keeps its 1 MiB read. A test pins it, and `build_profile_source` keeps refusing `sftp`.

## 6. Design notes

- One root, one function. The bug class here is two places deriving one fact. `scratch_root()` sits in `fileaccess/_protected_dir.py` beside `_parent_base`, the function that already owns root creation, so the dependency points from `execution` into `fileaccess`, as the import layers require.
- Producers move to `ScratchArena`, not to a new wrapper. The arena already carries the marker, the lock, the registry and the release rule.
- The cloud fix reuses `_RangeFileReader` and the connectors' read sizes. The only new class is one `RawIOBase` adapter over an S3 body, about 30 lines, in `profile/_cloud_readers.py`.
- The isolated cap uses footer metadata, so the check costs one footer read per staged file and no table read.
- No new storage, cache or setting. `TMPDIR` stays the only override for where scratch goes.

### 7.5 Pre-mortem

- The hold-back moves to `/tmp`, which is a small tmpfs on some hosts, and a run that worked beside the target now fails for disk. Mitigation: the B5 refusal names the scratch root and `TMPDIR`; owner question Q1.
- The 64 MiB sample cap refuses a real file with a huge quoted field. Mitigation: the refusal says to profile from a local copy; the cap is a named constant.
- `iter_batches` with `pre_buffer=False` makes many small range requests on a wide file. Mitigation: `_RangeFileReader` reads whole column chunks, so requests are per column chunk, not per page. The G7-1 test counts requests on a 50-column fixture and records the number.
- The read-back cap trips on a job that worked before. Mitigation: with an `output_dir` the data is still published (B11); the default follows `mem_cap_bytes`.
- A 4c slice and a G6 slice edit the same file. Mitigation: section 9 orders them and names the shared files.

## 12. Owner questions

Each has a recommended answer. Builders use the recommendation unless the owner says otherwise.

- Q1. Where does the Parquet sink's hold-back spill go?
  - (a) An arena under the one scratch root (`TMPDIR`), like every other spill. **Recommended.** One root, one budget, one sweep.
  - (b) An arena beside the target, `ScratchArena.fresh(under=target.parent)`. Same disk as the output, but it needs the ambient policy and a second budget root.
  - (c) No change; row 74b adds `_decoy_hold_` to the stage reclaim.
- Q2. Spill at rest (criterion d).
  - (a) Record per path that scratch is owner-only (0700 directories, 0600 files) and not encrypted, in `docs/security/file-access-policy.md`, and name full-disk encryption as the user's control. **Recommended.** It matches the V1 threat model (accidental leaks only).
  - (b) Encrypt spill with a per-run key in 1.0. Large: every spill writer and reader changes.
- Q3. SFTP table reads.
  - (a) Correct the register: SFTP has no table reader in 1.0, and its connector already streams. **Recommended.**
  - (b) Add a bounded SFTP profile reader to 1.0, built on paramiko `SFTPFile` with `prefetch`. One more R2 slice.
- Q4. The isolated read-back cap.
  - (a) Cap = `readback_max_bytes`, else `mem_cap_bytes`, else 2 GiB of decoded size. Over the cap: publish when there is an `output_dir` and withhold the in-memory outputs; refuse when there is not (B10, B11). **Recommended.**
  - (b) Refuse over the cap in every case, before publication.
  - (c) Return lazy outputs (file handles) instead of tables. Changes the result contract; better as a 1.x item.
- Q5. `_decoy_stage_`.
  - (a) It is a publication stage of the fixed-width output, not scratch; its reclaim stays with row 74b. **Recommended.**
  - (b) Treat it as one of the "three temp roots" and move it into an arena. This puts the output's own bytes in `/tmp` before the rename and loses the same-filesystem rename.
