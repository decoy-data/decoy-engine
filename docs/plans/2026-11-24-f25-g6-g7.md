## 2. Guarantee and non-goals

Guarantee, after this plan and the open 4c slices:

1. Every engine scratch directory is made under one root, which one function in `fileaccess` names. The disk preflight and the runtime disk cap measure that same root. The first configured temp variable controls the root. An unusable selected root stops the run.
2. On POSIX, every engine scratch directory that holds table data is a child of a `ScratchArena`: owner-only, flock-held, marker-proven. A killed run leaves only arenas, which the row 74 sweep can prove and reclaim. On Windows, the same producers keep working through a named fallback until 4c slice S1w (H1).
3. Transport bound (H5): no profile reader asks a cloud store for more than 8 MiB in one response, except one Parquet column chunk or footer, and no reader makes an unsized read. GCS rejects an ignored range before buffering the body. The caller owns the parsed frame.
4. On the subprocess route, the parent counts decoded Arrow bytes across all staged outputs. It stops at the first batch over the cap. The excess is at most that batch’s `nbytes`. Batch size limits rows. Wide values can still make one batch large. The child controls the published Parquet layout and bytes.
5. The at-rest state of each scratch path is written down: protected by mode and ownership, not encrypted.

Non-goals:

- Byte quotas (row 58b, release 1.3).
- The orphan sweep (row 74, F26 E3) and publication-stage reclaim (row 74b).
- Encryption of spill (owner question Q2).
- An SFTP table reader (owner question Q3).
- `to_frame` still returns a whole frame. That is its contract.
- A native arena on Windows (4c slice S1w). This plan does not break Windows either: see B3a.
- The DuckDB spill directory. `untrusted_session` (`fileaccess/adapters/duckdb.py:45-50`) sets no `temp_directory`, so DuckDB defaults to `.tmp` in the working directory. 4c slice S3b (T17) closes that; this plan depends on it for guarantee 1 and does not duplicate it (M4).

Size: about 16 source files change. New public names in `decoy_engine.__all__`: none. New engine-internal names: `READBACK_BATCH_ROWS`, the shared lazy spill opener, `fileaccess.scratch_root()`, `fileaccess.stage_scratch()`, `ISOLATED_READBACK_MAX_BYTES`, the kwarg `readback_max_bytes` on `run_pipeline_isolated`, the field `IsolatedRunResult.outputs_withheld`, and three reason codes. `run_pipeline_isolated` is exported from `decoy_engine.execution` (`execution/__init__.py:90`, :179); its signature only grows a keyword with a default. `protected_scratch_dir` stays exported (`__init__.py:128`, `__init__.py:559`), but engine code outside `fileaccess` stops calling it.

## 3. Established solutions

Surveyed before design. The plan adopts each one rather than writing a new mechanism.

| Need | Established method | Source | What we take |
|---|---|---|---|
| One temp root, user-overridable | `tempfile.gettempdir()` honors `TMPDIR`, `TEMP`, `TMP`, but silently tries the next candidate when one is unusable, and caches the result in `tempfile.tempdir` | Python stdlib `tempfile._get_default_tempdir` | Keep it as the base, call it in one place. Select and probe the first configured root before using the cached default (B1a). |
| Scratch dirs a crash can leave | marker plus lock, then sweep (systemd-tmpfiles with flock; Postgres removes `pgsql_tmp` at start) | systemd-tmpfiles(5); Postgres `RemovePgTempFiles` | Already built as `ScratchArena` (`fileaccess/_scratch.py:212-238`). |
| Ranged Parquet reads | `pyarrow.parquet.ParquetFile` over a seekable file reads the footer, then column chunks by range; `iter_batches` goes one row group at a time; `pre_buffer=False` stops coalesced read-ahead | Apache Arrow Python docs | Reuse `_RangeFileReader` (`profile/_cloud_readers.py:52-96`) for `to_frame`. |
| Streamed CSV over a network body | `pandas.read_csv` on a file object reads in buffered blocks; gcsfs, s3fs and smart_open pass a stream, never whole bytes | pandas IO docs; fsspec (default 5 MiB block) | Pass a `RawIOBase` over the stream to `read_csv`. |
| Version pinning across range requests | S3 `GetObject` with `IfMatch=<ETag>` returns 412 when the object changed; GCS reads with `if_generation_match=<generation>` | AWS S3 API reference; google-cloud-storage `Blob.download_as_bytes`, `Blob.open` | Pin every range in one read to the version the size came from (M2). The S3 connector already pins resumed reads (`connectors/s3.py:239`). |
| GCS ranges | GCS can ignore a range during decompressive transcoding. The response can omit its length. | [Google Cloud range behavior](https://docs.cloud.google.com/storage/docs/transcoding#range) | Inspect streamed response headers before the SDK reads the body. Close a refused response immediately. |
| S3 stream | botocore `StreamingBody.iter_chunks(chunk_size)` | botocore `response.py` | Reuse the 1 MiB size for each pinned range. A sized body read and context exit release each response before the next GET. |
| SFTP stream | paramiko `SFTPFile.read(n)`, optional `prefetch()` | paramiko `sftp_file.py` | Already used (`connectors/sftp.py:321-334`). No change. |
| Bounded Parquet read-back | Arrow `ParquetFile.iter_batches` accepts a row count and a row group selection. Each record batch exposes `nbytes`. | Apache Arrow Python API | Count actual decoded bytes per batch. Only the decoded total decides the cap. |

Behavior after G6:

- B1. `fileaccess.scratch_root()` returns the one base directory. `_parent_base(None)` and `default_ooc_temp_root()` both return it. Only the root selector consults the temp variables. Preserve the explicit-parent policy and vetting in `_parent_base(parent)` without probing the default first.
- B1a. Select the first nonempty variable in stdlib order: `TMPDIR`, `TEMP`, then `TMP`. Ignore lower-priority variables. Probe the selected directory by creating and removing a private file there. On failure, raise `FileAccessUnavailable` with `runtime.scratch_root_unusable`. Name only the variable. On success, return that directory even if stdlib cached another path. Use `gettempdir()` only when none is configured.
- B2. `resolve_temp_disk_budget(root)` takes the root the run spills under. The route passes the arena's parent, and `run_fk_out_of_core` measures its given `temp_dir` the same way. The cap stays 0.9 of the free bytes at that root (`execution/_pipeline_route_exec.py:64`), or `None` when `disk_usage` fails.
- B3. `fileaccess.stage_scratch()` is a context manager. On POSIX it opens one `ScratchArena.fresh()` and yields it. Each pipeline stage opens it once at stage entry and hands `create_dir(name)` children down to its producers (4c rule I2), using `create_dir(...).local_path()`, the transitional arm (a) the out-of-core runner uses (`execution/out_of_core/_runner.py:275`). There is one arena per stage entry, not one per producer (M5). The stage entries are: the post-scan stage (covering `execution/pipeline/_post_scan.py:249`, :360 and :411, `verification/postmask/runner.py:119` and `verification/postmask/fk_preservation.py:71`, which take the child they are given) and the subset stage (`_subset_stage.py:149`). `engine_scratch_root` is deleted. The collector at `execution/_pipeline_auto_chunk.py:430` enters `stage_scratch()` on first spill. The runner at `execution/out_of_core/_runner.py:243` enters `stage_scratch(under=temp_dir)` only when it owns the arena. Its caller still closes a supplied arena. 4c slice S4b later ends arm (a).
- B3a. Extract `_arena_supported()` from the platform check at `fileaccess/_scratch.py:214`. Both `fresh` and `stage_scratch` use it. On Windows, the latter uses an owner-only protected directory under the selected parent. Its children support nested directories, local paths and the StageDir file operations used by hold-back replay. Put the fallback in `fileaccess/_scratch_win32.py` until S1w.
- B4. Under Q1(a), both `ParquetTransactionalSink` and the isolated child’s `StagingSink` supply `open_spill_scratch`. The child currently supplies only `spill_parent` (`execution/_isolated_common.py:477-499`). Reuse one lazy, memoized `stage_scratch()` opener patterned on `execution/_pipeline_auto_chunk.py:418-434`. Each sink owns its scope and closes it on commit or abort, including failure. The arena finalizer is the backstop. Remove the beside-target arm only after both sinks supply the hook. ### 4.2 G7: bounded cloud reads and the isolated cap

Behavior after G7:

- B6. Parquet `to_frame` (S3 and GCS) opens `pq.ParquetFile` over `_RangeFileReader` with `pre_buffer=False`, reads it with `iter_batches`, and builds the frame with `pa.Table.from_batches(batches, schema=pf.schema_arrow).to_pandas()`. Passing the schema keeps an empty file valid (`iter_batches` yields no batch) and keeps the pandas index metadata, categoricals and timezones, so the frame matches `pd.read_parquet` (M10). Each range request covers one column chunk or the tail and footer.
- B6a. Capture size and version together. S3 requires a nonempty string ETag from HEAD. GCS reloads metadata if size or generation is missing, even when size is cached (`profile/_cloud_readers.py:346-350`). If the version is still missing, refuse with `source_changed` before fetching data. Pin every S3 GET with `IfMatch` and every GCS read with `if_generation_match`. Translate a failed precondition (412) or a short in-bounds range to `source_changed`. Keep SDK details out of the message and exception chain.
- B7. CSV `to_frame` passes a buffered stream to pandas. Use successive pinned ranges of at most 1 MiB for both providers. In `_s3_range` (`profile/_cloud_readers.py:230`), call `s3_call(stream.read, end_inclusive - start + 1)` inside the body context. Use B9 for GCS.
- B8. The CSV sample keeps its doubling windows, but the total bytes fetched for one sample are capped at 64 MiB (M1). Windows are 1, 2, 4, 8, 16 and 32 MiB (63 MiB), then one last window up to the 64 MiB total. If `n + 1` rows are not in those bytes and the object is larger, the sample refuses with the new value-free reason `connector.sample_window_exceeded` in the existing `connector` namespace (M8). Split each logical window into pinned requests of at most 8 MiB.
- B9. Remove `_s3_full`. Route every GCS profile read through `gcs_download` in `connectors/_clients.py:203-206`. Require start, inclusive end, object size and generation. For an empty object, return EOF without a GET. Use an authenticated streaming media GET with `Range` and `ifGenerationMatch`. Preserve timeout, bounded retries and error translation. Disable eager body reads and automatic decompression. Reject a transcoded or unsupported encoded representation before passing bytes to the parser. Inspect status and headers before any SDK buffering. Require 206 and a Content-Range matching the requested interval and object size. Close an ignored range (200) or malformed range immediately with a value-free connector error. Read only the requested byte count and check for a short read. Close on every exit. Use the same range transport for reads in `connectors/gcs.py:165-176`. Keep the existing write path.
- B10. After admission, process one staged file at a time. Open it once through file access. Construct one `arrow_adapter.parquet_file(handle)` and use it for metadata and all batches. A local handle exposes a path (`fileaccess/_local.py:80-81`). Keep the constructed reader bound through decode.
  1. Use a per-file context. Close the reader before its handle, including on error or overflow. Finish closing both before opening the next file. Use footer metadata for schema and group selection only.
  2. For group `i`, call `arrow_adapter.iter_batches(handle, pf, batch_size=READBACK_BATCH_ROWS, row_groups=[i])`. Add each `batch.nbytes` to one total across groups and files. Check before retaining the batch. Only a total strictly above the cap triggers B11. On overflow, release all retained tables and batches and stop before requesting another. Otherwise assemble the tables with their original schemas, including empty tables.
  3. Keep the child’s `StagedParquetWriter` and Arrow output writers intact (`execution/_transactional_sink.py:182`, `fileaccess/adapters/arrow.py:114-123`). Publication uses the admitted component names even when read-back yields no tables. `collect` hands those staged files to `publish_unit` (`execution/_isolated_commit.py:208-211`). Preserve their bytes and descriptor SHA. Publication failure keeps its existing outcome.
- B10a. The cap is `readback_max_bytes` if given, else `mem_cap_bytes` if given, else `ISOLATED_READBACK_MAX_BYTES = 2 GiB` (owner question Q4). `readback_max_bytes=0` means "do not read back": the result is `completed`, `outputs={}`, `outputs_withheld=True`, with or without an `output_dir` (H3). The in-process fallback, including `isolate=False` and re-entry, returns resident outputs. It skips staged read-back for every cap, including zero. Its `outputs_withheld` stays false.
- B11. Over a cap above 0, with an `output_dir`: the publication commits as today, and the result is `completed` with `outputs={}` and `outputs_withheld=True`. Over a cap above 0 with no `output_dir`: the stage is discarded and the result is `crashed` with the new reason `decoy.isolated_readback_over_cap`, next to the other isolated reasons (`reasons/decoy/_core.py:138-150`, M8). Both messages name the cap and the byte count only, never a table value. The error has `__cause__` and `__context__` set to `None`.
- B11a. The probe (`execution/_probe.py:283-292`) measures the child's peak and never uses `outputs`. It treats any outcome other than `completed` as inconclusive. It passes `readback_max_bytes=0`, so a large probe stays `completed` and auto-routing does not lose its measurement (H3).
- B12. The SFTP connector keeps its 1 MiB read. A connector test pins it. `build_profile_source` keeps refusing `sftp`, already pinned by `tests/unit/profile/test_bounded_profiling.py:271` (L3).

## 6. Design notes

- One root, one function. The bug class here is two places deriving one fact. `scratch_root()` sits in `fileaccess/_protected_dir.py` beside `_parent_base`, which already owns root creation, so the dependency points from `execution` into `fileaccess`, as the import layers require.
- One stage scratch entry point. `stage_scratch()` is the only way engine code outside `fileaccess` gets scratch. The collector and out-of-core runner also enter here (B3). It hides the win32 fallback, so the producers do not branch on the platform, and S1w deletes the fallback in one place.
- Producers take a child, not an arena. One arena per stage entry, children handed down (4c rule I2), so a killed stage leaves one arena to sweep.
- Cloud reads reuse `_RangeFileReader`, the S3 connector’s chunk size and its `IfMatch` pattern. Buffer sequential CSV reads over the same pinned range fetcher.
- The isolated cap counts what it actually holds (Arrow bytes), not what the child claims.
- No new storage, cache or setting. B1a gives the standard temp variables their existing precedence.

## 7. Choke point and sentries

The choke points are `fileaccess.scratch_root()` (one root) and `fileaccess.stage_scratch()` (one producer). GCS enforces the response bound inside `gcs_download`. The ignored-range transport test fails if this helper buffers before checking headers.

- Sentry S-G6a. Keep the creator names in `tests/sentry/fa/sinks.py` and resolve aliases with `tests/sentry/fa/resolve.py`. ### A1.3 Behavior

B-A1. One boundary, `profile/_cloud_boundary.py` (new, about 120 lines). It exports a class decorator `cloud_reader(provider, fmt)`, `provider` in {"S3", "GCS"}, `fmt` in {"csv", "parquet"}. At decoration it wraps every public function in the class body (no leading underscore, `__init__` excluded), marks each wrapper `__cloud_boundary__ = True`, and records the class in `CLOUD_READERS`. At decoration it raises `TypeError` for: a base class other than `object`; a public attribute that is not a plain function (staticmethod, classmethod, property or other descriptor); a dunder method other than `__init__`; a generator or async function. No reader method yields today, so refusing is simpler than wrapping generator results the way `fileaccess/_entry.py:298` does. A method added later is wrapped by construction or refused.

B-A2. Exit table. Inside the wrapper the original is only classified. Each exit is built after the `except` block closes, raised `from None`, with no notes. Rows match in order:

| # | Caught | Leaves as |
|---|---|---|
| 0 | `CloudObjectReadError` or `CloudObjectParseError` (a nested boundary call) | the same object, unchanged |
| 1 | `FileAccessDenied` in the chain | `scrub(exc)` |
| 2 | exact `TransientError` or `PermanentError` | fresh `_clients.classified(provider, exc.kind)` (new public 1-line wrapper of `_classified`) |
| 3 | a `PermanentError` subclass with a class-level `code` and a no-argument constructor (`SampleWindowExceeded`) | fresh `type(exc)()` |
| 4 | `MemoryError` or a typed memory error in the chain | `fresh_classified_failure(exc)` (B-A4) |
| 5 | `pd.errors.ParserError`, `EmptyDataError`, `UnicodeDecodeError`, `csv.Error` | `CloudObjectParseError` |
| 6 | resource `OSError`, or `is_memory_failure(exc)` by text | `fresh_classified_failure(exc)` |
| 7 | any other `Exception` (other `ConnectorError` included) | `CloudObjectReadError` |
| 8 | `BaseException` that is not an `Exception` | unchanged, unless the chain holds a memory error (row 4) |

So `_readers.py` gets them without pulling `connectors._clients` into every local read. `CloudObjectReadError(FileAccessReadError)` keeps existing `except FileAccessReadError` callers working.
