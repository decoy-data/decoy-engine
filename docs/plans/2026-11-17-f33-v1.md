## 0. What V1 gets, and what it does not

Row 72 is "F33 CLI verifier and engine signature envelope". In CLI V1 nothing produces a signed
bundle: the producer (platform P3 to P6a) is parked with the platform. V1 ships the verifier, the
signer primitive and the CLI command that runs the verifier offline. A V1 user can verify a bundle
a later platform produces, and the CLI tests prove it on bundles a test helper signs with the
engine's own `sign_evidence`. The owner confirmed this V1 scope on 2026-11-17 (OQ-1).

### 1.2 Pinned guarantee (V1 bar rules only)

After C1 merges, `decoy report verify-signed DIR --trust-policy FILE --trust-policy-sha256 HEX
--expect FILE --expect-sha256 HEX` exits 0 only when: the signature over the JCS statement is
valid under a key that the digest-pinned trust policy lists as ACTIVE or RETIRED for the
statement's tenant, signer and key version; every expected artifact exists under `DIR/artifacts`
as a regular file (no symlink, no directory redirect, `artifacts` itself not a symlink) and is
byte-equal to its expected digest; the catalog checks are OK; and the pinned expectations say no
output is unbound. It exits 4 for a flipped output byte, an edited statement, a swapped `kid`, a
revoked key, a symlinked artifact or an unbound output. It exits 1 for a digest mismatch on the
policy or the expectations, a missing field, or a malformed file. Every non-success prints one
fixed message per result class, with no path, no file bytes, no exception text and no data value.
The command opens no network connection. `decoy report verify MANIFEST` is unchanged except one
epilog sentence that now points to `verify-signed` (AT-C9 pins the diff).

Rules: rule 1 (function): a valid bundle verifies; rule 2 (data integrity): a changed byte is
reported, never accepted; rule 3 (non-admin surfaces): no value reaches CLI output.

### 1.3 Non-goals

- Producing a signed bundle in the CLI. That is a new feature; it is not in the row text.
- Platform P-OWN, P0 to P6b, E1c, KMS-held keys, rotation and revocation administration.
- The strict release gate (`_release.py`), `evidence_release/` and `hash_file_under`.
- Any change to the `cli-local-1` manifest, `manifest_hash`, or `records/` codecs.
- Windows: the no-follow walk and `ctime` race check are POSIX; on Windows the verifier refuses
  before any open (V2-LOG item 1).

## 2. Established solutions

Search run for this revision: the #335 design record (`docs/security/signed-evidence.md` at
`06877527b`), RFC 7515 (JWS), RFC 7797 (unencoded detached payload), RFC 8785 (JCS), RFC 7493
(I-JSON), the TUF specification (pinned root of trust), Sigstore bundle verification (offline
verification against a pinned trust root), and the engine `_canonical`, `_strict_spec`,
`fileaccess` and `reasons` packages.

- Detached JWS with ES256 over JCS canonical bytes, through `joserfc` and `rfc8785`. No custom
  crypto.
- Digest-pinned trust root and pinned expectations, as TUF and Sigstore do: each loader takes the
  pinned digest and checks it before any parse (`TrustPolicy.from_bytes(raw, pinned_sha256=)`,
  `_trust.py:88`, is the pattern; expectations copy it).
- Strict JSON intake per RFC 8259 with the I-JSON limits, through the one owner.
- Declarative schema checks through `_strict_spec`, as `publication/_descriptor.py` does.
- Rooted no-follow reads under a held directory descriptor through `fileaccess`.

Custom code left: the statement schema and the decision table (reviewed on #335), the identity to
wire-token table, and the bundle opener.

## 3. Design notes

1. **One rebase branch, not a merge of #335.** E1a starts from engine main and brings over, by
   path, `src/decoy_engine/signed_evidence/` (minus `_release.py` and `_canonical.py`, and with
   `hash_file_under` deleted from `_artifacts.py`), its tests (`ET:unit/signed_evidence/`,
   `ET:sentry/test_evidence_signing_boundary.py`), the conformance corpus,
   `docs/security/signed-evidence.md` and the `docs/methodology-registry.yaml` lines.
   `evidence_release/` and its tests are not brought over. #335 is closed with a pointer to the
   E1a PR. Unit tests of `hash_file_under` are removed and each removal is named in the PR body.
2. **JCS joins `_canonical` as a third named form.** New `E:_canonical/_jcs.py` with
   `jcs_bytes(value) -> bytes` (the `rfc8785.dumps` call and its exception mapping), exported from
   `E:_canonical/__init__.py`. Its refusal is a `CanonicalJsonError` subclass. The choke-point
   sentry `ET:sentry/defects/test_canonical_json_choke_point.py` gains one rule: `rfc8785` is
   imported only in `_canonical/_jcs.py`.
3. **The owner's strict reader gains two parse options; the profile maps its tokens.**
   `strict_json_loads` gains keyword-only `forbid_float: bool = False` and
   `forbid_negative_zero: bool = False`. With `forbid_float`, a `parse_float` hook records
   `float`; with `forbid_negative_zero`, the integer hook records `negative_zero` for the text
   `-0`. Defaults keep the three existing callers byte-identical (AT-E13). Recording keeps the
   owner's rule (hooks never raise; the first recorded defect is raised after the parse, with no
   context). `signed_evidence/_strict_json.py` keeps its pre-parse limits (UTF-8 without BOM,
   `MAX_BYTES` 4 MiB, `MAX_DEPTH` 32) and post-parse walk (`MAX_NODES` 200,000, integers within
   `2**53 - 1`, no unpaired surrogate), calls `strict_json_loads(data, max_int_digits=None,
   forbid_float=True, forbid_negative_zero=True)`, and maps owner tokens to #335's wire tokens in
   one dict: `duplicate_key` to `DUPLICATE_MEMBER`, `non_finite` to `NON_FINITE_NUMBER`,
   `negative_zero` to `INTEGER_OUT_OF_DOMAIN`, `float` to `FLOAT_NOT_ALLOWED`, `out_of_range` to
   `INTEGER_OUT_OF_DOMAIN`, `not_json` to `NOT_JSON`. A token missing from the dict is a
   `KeyError` at import time (the dict is checked against the owner's token set by AT-E2).
4. **Artifact reads: the owner's no-follow open reports a kind.** `open_checked` keeps one
   denial and one message (`file access denied: <field key>`), and the `FileAccessDenied` it
   raises gains a closed, value-free attribute `kind` in {`absent`, `link`, `not_regular`,
   `unreadable`}, set from the `errno` of the failed `_confined_open` (`ENOENT` absent; `ELOOP`,
   `ENOTDIR` on an intermediate component, `EXDEV` from `openat2` resolve flags: link) or from
   the `fstat` of the opened descriptor (`not_regular`); anything else is `unreadable`. The kind is
   computed inside `open_checked` from data it already holds: no post-denial `lstat` probe.
   `str()` and the field key are unchanged, so every existing denial test stays green.
   `_artifacts.py` maps kind to #335's status and token: `absent` to MISSING `ARTIFACT_MISSING`;
   `link` to UNAVAILABLE `ARTIFACT_PATH_UNSAFE`; `not_regular` to UNAVAILABLE
   `ARTIFACT_NOT_REGULAR_FILE`; `unreadable` to UNAVAILABLE `ARTIFACT_UNREADABLE`. A symlinked
   artifact is therefore UNAVAILABLE (exit 4, "artifacts: unavailable"), as #335 pins.
5. **Root semantics and one held bundle handle.** New `fileaccess/_ambient_tree.py` (about 70
   lines) with `open_ambient_tree(path) -> DirHandle`: calls `require_ambient`, opens the
   caller-named directory with `O_RDONLY | O_DIRECTORY | O_CLOEXEC` (the final component follows
   a symlink, as #335's root open did, because the caller named it), `fstat`s it, and returns an
   `FdDirHandle`. It sits outside `_rooted.py` so `_rooted.py` stays a pure capability module, and
   outside `_local.py` (595 lines). The module is added to `ambient_only_modules` and
   `ambient_guards` in `ET:sentry/file_access_modules.toml`, its one `os.open` gets a registry
   entry with `ambient_only = true`, and `open_ambient_tree` joins `engine_dir_handle` as a named
   sink in the scanner (`ET:sentry/fa/scan.py:453`), so each caller needs its own registry entry.
   Callers: `signed_evidence/_bundle.py` (one) and `signed_evidence/_artifacts.py` (one, the
   path form below). Registry count: 185 + 3 (AT-E10 pins 188).
   `verify_signed_evidence` keeps its signature; `artifact_root` accepts a path (as #335: opened
   with `open_ambient_tree`, root followed, so #335's suites are unchanged) or a `DirHandle` (the
   CLI route). New `signed_evidence/_bundle.py`: `open_signed_bundle(path) -> SignedBundle` opens
   the bundle directory once with `open_ambient_tree`, reads `evidence.json` and
   `evidence.sig.json` through that held handle with the one bounded reader (design note 12), and
   opens `artifacts` with `open_dir` (confined, no-follow), so a symlinked `artifacts/` is a
   `link` denial and every expected artifact is UNAVAILABLE. The CLI passes
   `artifact_root=bundle.artifacts`.
6. **Enumeration fails closed, on the owner's errors.** `_artifacts.py` loses #335's private walk
   and its `os.walk`. It enumerates by `entries()` recursion over `open_dir` handles, bounded by
   #335's `MAX_TREE_ENTRIES` (200,000) and a depth bound of `MAX_DEPTH` 32. Any
   `FileAccessDenied` or `OSError` during enumeration (a mode-000 subdirectory, a vanished entry)
   is `ARTIFACT_ENUMERATION_FAILED` and the artifact status is never MATCH. #335 used
   `os.walk(..., onerror=None)` (`_artifacts.py:152-171`), which skipped an unreadable subtree.
7. **Race check.** Replaces #335's byte-count check: `fstat` the open descriptor; hash in bounded
   chunks; `fstat` again and require equal size, `st_mtime_ns` and `st_ctime_ns`; then re-open the
   same relative path through `open_file` and require its `(st_dev, st_ino)` to equal the hashed
   descriptor's. Any difference is `ARTIFACT_CHANGED_DURING_READ`. The test seam for the rename
   case fires after the second `fstat` and before the re-open: a rename-over before the second
   `fstat` moves `ctime` and would be caught by the first check, which would let M3b survive.
   Pattern: git's racy-index check. Limit: a coarse-`ctime` filesystem can miss a same-size write
   inside one tick (Not verified).
8. **Codes: identities in the registry, one table to the frozen wire tokens.** E1b adds profile
   `evidence(owner)` in `E:reasons/_catalog.py`: kind FAILURE, phase VERIFY, severity ERROR,
   outcome VERIFICATION, retry NEVER, namespace `evidence`. `E:reasons/evidence/_signed.py`
   declares one lowercase identity per raised code (for example
   `evidence.statement.duplicate_member`) and holds `WIRE_TOKEN: Mapping[Identity, str]`, the
   one table from identity to the frozen uppercase token (`STATEMENT_DUPLICATE_MEMBER`).
   Composite tokens (`STATEMENT_`, `TRUST_POLICY_`, `CATALOG_` prefixes over an inner code) are
   rows of their own: the wrappers that built `f"{PREFIX}_{code}"` take a `Prefix` enum and an
   identity and look the composite up with `wire_for(prefix, identity)`, which raises on a missing
   row at import (the table is generated from the closed product of the prefixes and the inner
   codes each wrapper can receive, not from strings). `SignedEvidenceError(DecoyError)` takes an
   identity; its `.code` property returns the wire token, so `reasons.add(exc.code)` and every
   corpus vector stay unchanged. Wrapper parameters (`_err`, `_bad`, `_schema`, `_refusal`) are
   typed `Identity` (a `NewType`), and mypy plus AT-E7 reject a string. The raised set is counted
   by AT-E7's walk at build time, not by grep. Input refusals are not findings, so the
   `verification` profile is not used. The verification result's own status tokens (for example
   `ARTIFACT_NOT_EXPECTED`) stay fields of the frozen result contract and are not registered.

    no import cycle appears. The only `report.py` edit replaces one epilog sentence in place
    ("Keyed signing is platform R4 territory." becomes "Keyed check: decoy report
    verify-signed."), same line count. The new command takes `DIR` as a required argument, so
    `--signed`, an optional `EVIDENCE_FILE` and a "both given" case do not exist.
12. **One bounded reader for the four inputs.** `signed_evidence/_bundle.py` also holds
    `read_input(path, *, max_bytes) -> bytes` for the policy and expectations files: it opens the
    file's parent with `open_ambient_tree` (no new sink: the same named sink, one registry entry
    for this caller, already in the +3) and the leaf with `open_file`, reads at most `max_bytes +
    1` bytes and refuses `INPUT_TOO_LARGE` above the bound. Bounds: the statement and expectations
    4 MiB (the strict profile's `MAX_BYTES`), the signature 64 KiB, the policy 1 MiB
    (`MAX_POLICY_BYTES`, `_trust.py:33`). The statement and signature are read from the held
    bundle handle, never from a second open of `DIR`.
13. **Expectations through `_strict_spec`, with the pin first.** New
    `E:signed_evidence/_expectations.py`: `parse_expectations(raw: bytes, *, pinned_sha256: str)
    -> Expectations` checks the pin exactly as `TrustPolicy.from_bytes` does (pin form, then
    `hmac.compare_digest` on `"sha256:" + hexdigest`, refusal `EXPECTATIONS_DIGEST_MISMATCH`)
    before any parse, then parses with the strict profile and loads with one declared spec:
    `ObjectSpec` with fields `v` (new `VersionSpec(1)` in `_strict_spec.py`: `type(raw) is int and
    raw == 1`, else `schema_unknown`; the one owner addition), `tenant`, `job_id`, `attempt_id`,
    `bundle_id` (`ShapedSpec` with `_context.py`'s id rule), `snapshot_id`
    (`NullableSpec(ShapedSpec)`), `artifacts` (`ListSpec(ObjectSpec(id: ShapedSpec, sha256:

    (`CountSpec`), and `catalog` (a local `Spec` whose `load` calls
    `RequiredCatalog.from_bytes(jcs_bytes(raw))`). Hand-written checks are only: `artifacts`
    non-empty and ids unique. Each `SpecCheck` maps to one `evidence` identity
    (`expectations.<check>`). Normalization happens here only: each wire `sha256` becomes

    design note 14. The shape is the platform P6a writer contract (revision 9), frozen here as
    `expectations` version 1. The CLI never builds a context itself and never compares a digest
    itself: it passes `pinned_sha256="sha256:" + flag` to both loaders, and a malformed flag is
    refused by the loader's pin-form check.
14. **Unbound outputs are an engine decision.** `VerificationContext` gains
    `expected_unbound_outputs: int = 0`, and `_verifier._decide` returns `ExitClass.PARTIAL` when
    it is above 0, after every other check. This changes `_verifier.py` and `_context.py`; the
    review re-reads both.

    baseline does not grow. No new exit integer.

## 4. Behavior

- `decoy report verify-signed DIR` requires `--trust-policy`, `--trust-policy-sha256`, `--expect`,
  `--expect-sha256`; a missing one is Click's own missing-option error (exit 2), as for every
  other required option in the CLI.
- The policy and expectations bytes go to their loaders with the pinned digest; the loader checks
  the digest before parsing. A mismatch is exit 1, "trust policy digest does not match" or
  "expectations digest does not match".
- The engine verifier runs with `Purpose.CONSUMER_ACCEPTANCE` and the context from
  `parse_expectations` only. No context value comes from a flag.
- `--json` prints `{"command": "report verify-signed", "status": ..., "exit_class": ...,
  "signature": ..., "trust": ..., "artifacts": ..., "checks": ..., "unbound_outputs": ...}`, each a
  closed enum token; `unbound_outputs` is `none` or `present`. The shape is added to
  `CT:fixtures/release_freeze/json-shapes.json`.
- Human output: one line per dimension with a fixed word (valid, invalid, mismatch, missing,
  unavailable, revoked, retired, untrusted), then the verdict line.
