## 0. What row 81 adds, and what it does not

Nothing of row 81 is merged. Today:

- A disguise is a YAML bundle (`src/decoy_engine/disguises/schema.py:45`, `FieldRule`: `detectors`,
  `mask`, `params`, `why`, first match wins). Nothing in the engine applies one to a config. The only
  consumers are `load_disguises` readers: CLI `list disguises`, tab completion, the platform router,
  and the platform web `MaskInspector`, which applies rules in the browser.
- The bundle vocabulary is not the pipeline vocabulary. A rule says `mask: faker` with
  `params.faker_type: email`, or `date_shift` with `jitter_days: 30`. A pipeline column says
  `strategy: faker`, `provider: person_email`, or `provider_config: {min_days: -30, max_days: 30}`.
  The CLI keeps a hand-written map between the two in `tests/unit/test_template_disguise_drift.py`.
- Four shipped rules cannot run at all: `faker_type: ipv4` in `hipaa`, `gdpr` and `ccpa` (no ipv4
  provider; the CLI templates already substitute `redact`) and `faker_type: zipcode` in `default`
  (the provider is `address_zip`).
- CONFIG-EXPLICIT (row 22, done) makes every source column a declared `columns:` entry with a
  `strategy`. So the set of fields is known from the config alone, with no source read.

Row 81 adds four things:

1. **Disguises applied in the engine.** Bundle rules are rewritten in the pipeline column
   vocabulary (new dated versions), and a pipeline names a disguise and a version. A column that
   the user classifies (`classification: email`, the PII type the user picks, per the presets
   decision) gets that disguise's rule. The engine does it inside the one validation choke point,
   so every caller sees an explicit config.
2. **Selector grammar.** One closed, bounded selector over table and column names (globs),
   classification, tag, declared logical type and relationship role.
3. **Prohibition predicates.** `forbid` or `require` a strategy set on selected fields. They are
   checked after expansion against every field, explicit ones included. A violation refuses the
   config and names the prohibition id.
4. **5-level precedence** with a per-field explanation and fingerprint: exact field, exact
   object or classification, scoped pattern, classification default (the disguise), global
   default.

Non-goals (a review finding here becomes a follow-up item, not a blocker):

- Auto-classification. Detection never assigns a `classification`; the user writes it. A scan may
  suggest one in its starter text later (row 32b and STORM work), never here.
- Organization policy libraries, shared selector files, `include:` composition (F18), approval
  workflows for new matches, advisory checks, orphan-policy and release-gate predicates. V1
  prohibitions constrain the strategy only.
- Nested-path selectors (F07, row 82) and source-scope selectors. In the V1 config one source
  feeds one table, so `table` is the object.
- Org-authored or directory-loaded disguises in the CLI. V1 policy names built-in disguises only.
- Older disguise versions kept loadable side by side. A pin to a version the engine no longer
  ships is refused; keeping history is V2.
- The disguise `triggers` and `expected_fields` blocks. They stay as they are and nothing in this
  plan reads them.
- Generate-kind tables (`generate_columns`). Policy decides mask columns only.
- A policy fingerprint member in `RunResult` (frozen). The plan hash covers the expanded config,
  so the run's plan hash already identifies the decisions (Q12).
- The platform: its `MaskInspector` reads `mask` and `params` and breaks at its next repin (Q13).

## 1. Guarantee

- A config with no `policy` block, no `classification` and no `tags` validates, dumps, hashes and
  masks exactly as on today's main (same `model_dump()`, same plan hash, same output bytes).
- With a `policy` block, `PipelineConfig.model_validate(raw).model_dump()` is an explicit config:
  every mask column carries the `strategy` (and `provider`, `provider_config`, `namespace`) the
  precedence decided. Nothing downstream of the choke point knows a policy existed.
- `classification` and `tags` are labels. Adding them to an explicit column never changes output
  bytes (they are in no seed or strategy fingerprint).
- The decision for each mask field is the highest-precedence level that matches it (section 3.3).
  Two different decisions at the same level refuse the config with `config.policy_rule_conflict`
  naming both sources. A rule that selects no field refuses with `config.policy_selector_unmatched`.
  A mask field with no decision at any level refuses with `config.policy_field_undecided`. Nothing
  falls back to passthrough.
- A prohibition violated by any decided field, explicit or expanded, refuses the config with
  `config.policy_prohibited`, naming the prohibition id, the `table.column` and the strategy.
- The disguise pin is exact: `policy.disguise.version` must equal the shipped bundle's `version`,
  or the config is refused with `config.policy_disguise_version_mismatch`.
- Every shipped disguise rule, applied to a column, compiles and masks a small frame.
- Validation is idempotent: validating the dump of a validated config gives the same dump.
- `PipelineConfig.policy_expansion` gives, per mask field, the decision, its level, its source
  (column, rule id, `disguise id@version`, or default), the rule ids it overrode, and a decision
  digest, plus one fingerprint over all fields. No cell value is read. Errors and the explanation
  carry config names, ids and strategy names only.

## 2. Established solutions

Search run (2026-11-17): web search for Delphix masking domain default algorithms and column
override, and for AWS Lake Formation LF-tag expressions; codebase search
`git grep -n -i "disguise|field_rules|selector|precedence|prohibit"` over engine `src/`, CLI
`src/` and platform `api/` and `web/src`; the vault (`qmd search "F16 selector precedence"`,
`qmd vsearch "selector grammar prohibition predicates precedence disguises"`).

Found:

- **Classification default with column override.** Delphix assigns each inventory column a domain.
  The domain's default algorithm fills the column and follows later default changes; an algorithm
  picked on the column is an override that does not follow them
  ([Delphix ruleset docs](https://dcs.delphix.com/docs/latest/customize-a-ruleset)). This is level
  4 (disguise rule for the classification) under level 1 (the column's own strategy).
- **Bounded tag expressions.** AWS Lake Formation LF-tag expressions AND across keys and OR within
  one key's values, with fixed limits on keys and values
  ([LF-tag expressions](https://docs.aws.amazon.com/en_us/lake-formation/latest/dg/TBAC-creating-tag-expressions.html)).
  Kubernetes `matchLabels` has the same form. The selector follows it: keys AND, list values OR,
  no negation, no nesting.
- **Specificity precedence.** CSS specificity and dbt's config hierarchy (in-model config over
  path-scoped project config over project defaults) pick the more specific source. Both break a
  tie at equal specificity by order. The F16 spec says conflicts fail compilation, so a tie here
  is refused instead.
- **Deny after resolution.** OPA Gatekeeper and Kyverno `validate` rules run on the resolved
  object and name the policy that denied it. Prohibitions run after expansion and name their id.
- **Globs.** Python `fnmatch.fnmatchcase`: case-sensitive and anchored (it compiles to a regex
  ending in `\Z`), so it meets recurring defect 1 with no hand-written matcher.
- **Digests.** `decoy_engine._canonical.canonical_json_bytes` is the one canonical JSON form, and
  SHA-256 over it is how records and F22 descriptors are identified.
- **In the code.** `registered_detector_ids()` (`src/decoy_engine/detection/domains.py:87`) is the
  closed classification vocabulary; every detector id the ten bundles use is in it (checked
  2026-11-17). `contracts/distribution_behavior.py` keys every mask strategy, and an existing test
  pins it against `SCALAR_HANDLERS`. `problem_details` (`config/_generate_options.py`) reports many
  config problems at once at their locations.

Choice: the precedence and selector semantics above; one engine expansion run inside
`PipelineConfig` validation; bundle rules rewritten in the column vocabulary so a rule is a
column decision and no translation table exists. The custom code is the expansion itself (about
250 lines); no library offers it for this config format.

## 3. Behaviour

### 3.1 Config surface

```yaml
version: 2
policy:
  disguise: {id: hipaa, version: "2026-11-20"}   # optional; pin required when present
  rules:                                          # optional
    - id: visit-dates
      select: {table: visits, column: "*_date"}
      strategy: date_shift
      namespace: visit_dates
      provider_config: {min_days: -30, max_days: 30}
  prohibit:                                       # optional
    - id: no-clear-ssn
      select: {classification: ssn}
      forbid: [passthrough]
    - id: keys-keyed
      select: {role: child_key}
      require: [hash, fpe, tokenize]
  default: {strategy: redact}                     # optional, level 5
tables:
  - name: patients
    columns:
      - {name: email, classification: email}      # decided by the disguise (level 4)
      - {name: ssn, classification: ssn, tags: [direct_id]}
      - {name: notes, strategy: passthrough}      # level 1
```

- `PolicyConfig` (strict, `extra="forbid"`): `disguise` (`id` slug, `version` `YYYY-MM-DD`
  fullmatch), `rules` (each: `id` slug unique across rules and prohibitions, `select`, `strategy`,
  optional `provider`, `provider_config`, `namespace`, `why`), `prohibit` (each: `id`, `select`,
  exactly one of `forbid` or `require`, a non-empty list of strategy names, optional `why`),
  `default` (a decision without `id` or `select`). Strict strings throughout (recurring defect 2).
  At most 200 rules and 200 prohibitions, lists of at most 50 values.
- `ColumnConfig` gains `classification` (one id from the classification vocabulary) and `tags` (up
  to 20 slugs). Both are omitted from dumps when unset, as `when` is today.
- A column with no `strategy` is allowed only when `policy` is present. It may carry only `name`,
  `classification`, `tags` and the F06 declared-casting keys. Any strategy-shaping key (`provider`,
  `provider_config`, `namespace`, `cardinality_mode`, `deterministic`, `scale`, `coherent_with`,
  `backend_type`, `backend_version`, `pool_size`, `vault`, `allow_collisions`, `when`) refuses with
  `config.policy_column_partial`. To tune a field, write its strategy (level 1).
- Without `policy`, a column without `strategy` fails exactly as today (pydantic `missing`).

### 3.2 Selector grammar (engine, slice E2a)

`Selector` keys, all optional, at least one present; keys AND, list values OR:

| Key | Value | Matches |
|---|---|---|
| `table` | glob or literal | `fnmatchcase(table_name, value)` |
| `column` | glob or literal | `fnmatchcase(column_name, value)` |
| `classification` | id or list of ids | the column's `classification` |
| `tag` | slug or list | any of the column's `tags` |
| `logical_type` | one of the F06 `LOGICAL_TYPES` | the column's declared `logical_type` |
| `role` | `parent_key` or `child_key`, or a list | the column is in a `relationships` parent or child column list |

A glob is a value holding `*`, `?` or `[`. Values are strict strings of 1 to 128 printable
characters. An empty selector, an unknown key or a bad value refuses with
`config.policy_selector_invalid` at the selector's location. A classification outside the
vocabulary refuses with `config.policy_unknown_classification`.

### 3.3 Precedence (the one registry, `disguises/_precedence.py`)

| Level | Name | Source |
|---|---|---|
| 1 | `exact_field` | the column's own `strategy`; a rule whose selector has a literal `table` and a literal `column` |
| 2 | `exact_object_or_classification` | a rule with no glob anywhere and either a literal `table` (no `column`) or a `classification` |
| 3 | `scoped_pattern` | any other rule (a glob, or `tag`, `role` or `logical_type` without a literal table and column) |
| 4 | `classification_default` | the pinned disguise's first rule whose `detectors` holds the column's `classification` |
| 5 | `global_default` | `policy.default` |

`selector_level(selector)` is the only function that assigns a level; `PrecedenceLevel` is the only
enum. For each mask field, the expansion takes the lowest-numbered level with at least one
matching source. If two sources at that level give different decisions (compared as the
canonical JSON of `strategy`, `provider`, `provider_config`, `namespace`), the config is refused
with `config.policy_rule_conflict` naming both. Equal decisions merge, and the explanation lists
both. A disguise is one source, so its internal first-match order is not a conflict.

### 3.4 Expansion and prohibitions (E2a, E2b)

`expand_policy(raw, inputs: ExpansionInputs) -> tuple[dict, PolicyExpansion]` is pure.
`ExpansionInputs` carries the validated `PolicyConfig`, the classification vocabulary, the strategy
vocabulary and the pinned `Disguise` (or `None`). The function reads only the config. For each mask
table it walks `columns` in order, computes the decision, and writes the decided keys into a copy
of the column dict. It collects every problem and raises them together through `problem_details` at
their config locations. A malformed structure (tables not a list, a column without a string `name`)
is skipped, so the model's own error reports it.

Prohibitions run on the explicit result over every mask field. `forbid` refuses a field whose
strategy is in the list; `require` refuses a field whose strategy is not. A prohibition that
selects no field is not an error; the explanation shows `matched: 0`.

### 3.5 Disguises (slice E1)

`FieldRule` becomes `detectors`, `strategy`, `provider`, `provider_config`, `namespace`, `why`,
with `extra="forbid"`. All ten bundles are rewritten and each gets a new dated `version`:

- `faker` with `faker_type: X` becomes `provider: <the provider whose Faker method is X>`, from
  `providers_v2/_faker_adapter.py`; `locale` moves into `provider_config`.
- `date_shift` with `jitter_days: N` becomes `provider_config: {min_days: -N, max_days: N}` and a
  bundle namespace `<id>_dates`, so all date columns of one pipeline shift together, as the CLI
  hipaa template does.
- The three `ipv4` rules become `redact` (the CLI templates' documented exception); `zipcode`
  becomes `address_zip`.
- Other strategies keep their parameters, moved to `provider_config` (`fpe` `charset`,
  `validate_luhn`, `checksum`; `truncate`; `redact` `redact_with`; `code_set`;
  `geo_generalize`).

`decision_for(disguise, classification) -> ColumnDecision | None` is the level 4 source.

Closing RGF1-KL-3: `disguises/_versions.json` pins the SHA-256 of each bundle file per
`(id, version)`. A test fails when a bundle's bytes change and its version does not, or when a
known `(id, version)` changes digest. A new version adds a row; rows are never edited.

### 3.6 The choke point (slice E3)

`PipelineConfig` gets `policy: PolicyConfig | None = None` (omitted from dumps when `None`) and a
`model_validator(mode="before")` that, when `policy` is present:

1. checks column `classification` values against `registered_detector_ids()`, and all strategy
   names in `forbid`, `require`, rules and `default` against `mask_strategy_names()` (a new public
   function in `contracts/distribution_behavior.py` returning the keys of its existing table);
2. loads built-in disguises once and finds the pinned `id` and `version`;
3. calls `expand_policy` with those vocabularies injected. The layer contract puts `disguises`
   below `config`, `detection` and `contracts`, so the vocabularies are passed in, not imported;
4. replaces `raw["tables"]` with the explicit copy and `raw["policy"]` with the validated
   `PolicyConfig`, which carries the expansion as a private attribute.

Field validation then runs on the explicit columns, so every existing column check sees the
decided strategy as if a person wrote it. `PipelineConfig.policy_expansion` returns the
expansion (or `None`). Re-validating the dump re-expands: filled columns are now level 1 with the
same decisions, so the dump is unchanged.

Label keys and fingerprints: `generators/derivation.py` `strategy_config_fingerprint` hashes every
column key outside `_EXCLUDED_FROM_FINGERPRINT`. It is called for generate columns, which policy
does not decide, but E3 adds `classification` and `tags` to that exclusion set so a label can never
move a seed. F16-T10 proves it on a mask column and a generate column.

JSON schema: `ColumnConfig.__get_pydantic_json_schema__` drops `strategy` from `required` (the
description says "required unless the pipeline has a policy block"); runtime keeps it required.

### 3.7 Explanation document

`expansion_to_dict` writes `policy-expansion/v1`:

- `schema`, `disguise` (`{id, version}` or null), `fingerprint` (SHA-256 hex of the canonical JSON
  of the sorted `[table, column, decision_digest]` list plus the disguise pin);
- `fields`: `table`, `column`, `strategy`, `provider`, `level`, `level_name`, `source`
  (`{kind: column|rule|disguise|default, id}`), `overridden` (rule ids), `classification`,
  `decision_digest` (SHA-256 of the decision's canonical JSON; `provider_config` itself is not
  copied);
- `rules` (`id`, `level`, `matched`), `prohibitions` (`id`, `matched`).

It is write-only in V1 (no reader), so it has one strict writer model and a tag. A reader is added
with its first consumer that reads it back (recurring defect 4).

## 4. Failure modes

| Case | Result |
|---|---|
| Unknown disguise id | `config.policy_unknown_disguise` at `policy.disguise.id` |
| Pin differs from shipped version | `config.policy_disguise_version_mismatch`; the message names both dates |
| Classification not in the vocabulary | `config.policy_unknown_classification` at the column or selector |
| Strategy name not known (rule, default, forbid, require) | `config.policy_unknown_strategy` |
| Bad selector | `config.policy_selector_invalid` |
| Rule selects no field | `config.policy_selector_unmatched` naming the rule id |
| Two decisions at one level | `config.policy_rule_conflict` naming both sources and the `table.column` |
| No decision for a field | `config.policy_field_undecided` naming the `table.column` |
| Policy-decided column with a strategy-shaping key | `config.policy_column_partial` |
| Prohibition violated | `config.policy_prohibited` naming id, `table.column`, strategy |
| Decided strategy needs a setting the decision lacks | the existing column or compile check, unchanged |
| Several problems | all reported in one `ValidationError` |
| CLI | exit 1 (`EXIT_USAGE`) through the existing config-error path; no new exit code |

## 5. Design notes and choke points

- New structure: five pure modules in `disguises/`. One place per fact: levels and the level
  function in `_precedence.py`; the selector model and matching in `_selectors.py`; the YAML
  model in `_policy.py`; expansion, conflicts and the explanation in `_expand.py`; prohibitions in
  `_prohibit.py`; the level 4 table in the bundles. Principle applied: single responsibility for
  the precedence rule, which changes for policy reasons and must not be copied into the CLI or the
  platform. House style: a typed context (`ExpansionInputs`) instead of long parameter lists; no
  flag arguments.
- Choke point: `expand_policy` is called only from `config/_pipeline.py`. Guard: new sentry
  `tests/sentry/test_policy_expansion_choke_point.py`, an AST scan of `src/decoy_engine/` that
  fails on an import or call of `expand_policy` or `selector_level` outside `disguises/` and
  `config/_pipeline.py`. Covered shapes (recurring defect 5): `from decoy_engine.disguises import
  x`, `from decoy_engine.disguises._expand import x`, `as` aliases, `import
  decoy_engine.disguises._expand as m` with attribute access, each also inside a function body.
  Mutation MS-1: a second call in `execution/_pipeline_context.py`.
- The CLI never expands. It reads `policy_expansion` from the validated model. C1 adds a CLI sentry
  that fails on an import of `expand_policy` or `selector_level` anywhere in `src/decoy/` (same
  shapes; mutation MC-1).
- Placement in `disguises/` is forced: `config/` is at the 25-module fan-out cap and the engine
  root takes no new package. This is a map change (section 7).

## 8. Enumerations

### Routes

- Config load: every route starts from `PipelineConfig.model_validate`
  (`src/decoy_engine/config/_pipeline.py:87`). The before-validator is the one expansion site.
- Run: `build_run_context` (`src/decoy_engine/execution/_pipeline_context.py:171`) consumes the
  dump, so resident, sequential, out-of-core, chunked, stream and isolated routes see explicit
  columns. No route file changes.
- Compile: `compile_plan` (`src/decoy_engine/plan/_compile.py:122`) and `run_config_only_checks`
  (`src/decoy_engine/plan/_compile.py:477`) see explicit columns. `_hash_config`
  (`src/decoy_engine/plan/_compile.py:625`) hashes the dump, which now holds `policy`. No edit to
  `_compile.py` (656 lines against its 666 ceiling).
- CLI: `decoy run`, `decoy validate`, `decoy validate compile`, `decoy.mask()` and the other readers
  validate through the engine model (CONFIG-EXPLICIT C1 made them share one declared-column
  choke point).

### Fields

- New config keys: `policy` (and its members, section 3.1), `columns[].classification`,
  `columns[].tags`. Existing: the `ColumnConfig` keys the decision writes
  (`src/decoy_engine/config/_tables.py:65`); `logical_type`; `relationships[].parent.columns` and
  `children[].columns`.
- Bundle `FieldRule` (`src/decoy_engine/disguises/schema.py:45`): `detectors`, `strategy`,
  `provider`, `provider_config`, `namespace`, `why`.
- CLI raw strategy readers to check in C1: `src/decoy/_native_gate.py:265` and `:277`,
  `src/decoy/cli/_token_vault.py:409` (documented as reading the dump), `src/decoy/cli/tokenize.py:577`,
  `src/decoy/cli/compile_explain.py:398` (replaced in C2).

### Exit paths

- Each refusal in section 4: a pydantic `ValidationError` with the code at its location; CLI exit 1.
- Success: explicit dump; `policy_expansion` set.
- `decoy validate compile --explain`: exit 0 with the explanation; exit 1 on a refusal.
- `decoy.mask()`: raises the same `ValidationError` before any source read.

### FK shapes

- Single-column FK: `role: parent_key` or `child_key` selects the key columns. The decided
  strategy then meets the existing namespace and FK checks unchanged.
- Composite FK: every member column carries the role. A rule that selects one member and not the
  others is allowed, and the existing composite checks judge the result.
- Self-referencing and multi-parent relationships: roles are per column, so a column can have
  both; `role` lists OR.
- No new join behavior; the expansion only writes column keys.

### Output surfaces

- The explicit config dump (and the plan hash over it).
- `policy-expansion/v1` via `PipelineConfig.policy_expansion` and `expansion_to_dict`.
- Refusal messages and locations.
- CLI `validate compile --explain` text and `--json` `policy`; `decoy explain disguises`.
- Logs: none added. Expansion runs at config load, before the job log opens; refusals reach the
  user as the config error.
