## 1. Frame

The unified slice is the default route for a single table under 100,000 rows. It declines to the full-frame pandas oracle for two reasons that have nothing to do with the masking:

1. **A passthrough or unconfigured column of a common type.** `cheap_admission` (`execution/_unified_slice_admission.py:196`) converts the whole source table to pandas (line 352), converts it back (line 387), and declines if any column is not type- and value-identical (lines 391-401). `decimal128` (precision re-inferred), `int64` with nulls that is not declared (becomes `float64`), `large_string` (becomes `string`), `date32` and `timestamp` with some units all fail. Then `resident_contract_admission` (line 410) checks a passthrough node against `{string, int64, bool}` (`execution/_operator_registry.py:139`), so float, date, timestamp, decimal and the other int widths decline too. A table with one `amount decimal(12,2)` column that nobody masks runs full frame.
2. **A `large_string` target column.** Polars and some Parquet writers emit `large_string`. The registry domains are exact `pa.string()` (`execution/_operator_registry.py:93` `_STRING_ONLY`), the chunked native admission uses `string_source_type_rejection` (`execution/native/_real_type_admission.py:93`, called at line 171), and both decline. Every string strategy on such a file runs on pandas.

The unified slice builds its output from the pandas frame (`reconstruct_source_shaped_output`, `execution/_unified_slice_evidence.py:191`): passthrough columns come from the frame and masked columns are overlaid. That is why every column must survive the round trip today.

## 2. Established solutions

Search run: how Arrow-native engines carry columns a transform does not touch (DuckDB projection pushdown, Polars `with_columns`, Spark `withColumn`); how Arrow tools treat `large_string` against `string` kernels (Arrow C++ compute kernel dispatch, `pyarrow.compute.cast` docs, Polars string type normalization).

- DuckDB, Polars and Spark never convert a column the query does not reference. Untouched columns are carried by reference into the output. Converting them to another representation and back is the thing the unified slice does today, and it is the source of both the cost and the loss.
- Arrow C++ kernels register separate `string` and `large_string` implementations, or cast at the dispatch boundary. A safe cast from `large_string` to `string` copies offsets and keeps the value bytes, and fails when the data passes 2 GiB of offsets. Polars normalizes text to one type at its boundary for the same reason.
- The engine already has the parts: `narrow_text` (`_arrow_types.py:26`), "the one owner of offset-width normalization for kernels that have a `string` fast path", and `split_narrow_text` (line 67). The kernel scalar path already narrows (`kernel/_scalar.py:103`). The chunked lane already writes passthrough columns from the resident Arrow chunk, so the unified slice change makes the two lanes agree.

### Reuse inventory

- `narrow_text` (`_arrow_types.py:26`) and `is_text` (`_arrow_types.py:21`): the boundary cast and the predicate. No second cast is written.
- `lossless_int_columns_from_config` (`execution/_fk_keys.py:406`): still decides the dtype of columns that stay in the frame.
- `coded(...)` and `RouteDeclineCode` (`execution/native/_route_decline_codes.py:25`): one new member for the offset overflow, registered in the reasons catalog as the others are.
- The operator registry (`execution/_operator_registry.py`): passthrough's domain changes in its one row.

## 3. Guarantee and non-goals

After S1 (UF-DOMAIN):

1. A column of a unified-slice table is **unread** when no non-passthrough node targets it, it is not a `group_by` sibling of a `group_key` node, and no `when:` predicate reads it. Unread columns are not converted to pandas. The output carries the resident Arrow column, unchanged, at its source position.
2. Unread columns of any Arrow type do not decline the unified slice. The round-trip guard and the resident-domain check apply only to read columns.
3. The masked columns are byte-identical to today's unified slice output for the same config.

After S2 (LARGE-STRING-CAST):

4. A `large_string` column targeted by `redact`, `truncate`, `text_redact`, `text_mask`, `faker`, `categorical`, `bucket_perturb`, `date_shift`, `fpe` or `hash` is narrowed to `string` with `narrow_text` at the route boundary, on the unified slice and on the chunked native route. The masked output column is `string`, the type the pandas route writes today.
5. A column whose text does not fit 32-bit offsets declines with the new coded reason `large_string_offsets_overflow`, before any masking. On the chunked route each chunk is narrowed on its own, so this only fires for one chunk over 2 GiB.

Non-goals: `string_view` sources (they keep `source_type_not_string`); the sequential FK route and out-of-core (`string_source_type_rejection` keeps its exact-string meaning there, `execution/_sequential_native_text_mask.py:62`); widening a masking strategy's own domain to new types (hash on int widths, date_shift on typed dates is DATE-SHIFT-TYPED); the legacy full-frame route's output, which keeps its bytes (owner question Q1); tables with FK relationships (the unified slice declines them today).

## 4. Enumerations

### Exit paths

- Unread column of any type: spliced from resident Arrow (S1).
- Read column that fails the round-trip guard: unchanged decline, full frame (`execution/_unified_slice_admission.py:401`).
- Read column outside its strategy's domain: unchanged decline (`execution/_unified_slice_admission.py:521`).
- `large_string` target that fits 32-bit offsets: narrowed and admitted (S2).
- `large_string` target that does not fit: `large_string_offsets_overflow`, full frame.
- `string_view` target: `source_type_not_string`, unchanged.

### Routes

| Route | S1 | S2 |
|---|---|---|
| Unified slice (single table, under 100k rows) | unread columns spliced; domain gate only on read columns | target `large_string` narrowed at `cheap_admission` before the frame is built |
| Chunked native (100k rows or more) | none (already writes resident columns) | `_real_type_admission.py:171` uses `is_text`; `run_kernel_step` (`execution/native/_operator_step.py:303`) and `run_kernel_step_masked` (line 507) narrow at entry |
| Sequential FK, out-of-core | none | none (non-goal) |
| Full-frame pandas | none | none |

### FK shapes

- Table with FK edges: the unified slice declines it today; unchanged. S2 does not touch the sequential route.
- FK key column in a single-table job with no declared relationship: an ordinary column, covered by the read and unread rules.

### Fields

- Read column: a non-passthrough node's target; a `group_key` `group_by` sibling; a column named in a `when:` predicate.
- Unread column: everything else, including passthrough targets and columns the config does not name.
- Types admitted as unread: every Arrow type, including `int8` to `uint64`, `float32` and `float64` with `NaN`, `decimal128` and `decimal256`, `date32`, `date64`, `timestamp` of any unit and zone, `large_string`, `binary`, `list` and `struct`.

### Output surfaces

- Column values and types of unread columns: resident Arrow (byte change where pandas was lossy, section 10).
- Column order: the source order, unchanged.
- Schema `pandas` metadata: describes only the frame columns (byte change, section 10).
- Masked columns: unchanged (S1); `string` from a `large_string` source (S2), the same as the pandas route.
- Route evidence: `unified_slice` in place of `pandas_oracle` for newly admitted tables; new decline code in run records.

## 7. Design notes

One fact, one place: "which columns does the unified slice read" is `read_columns(...)` in `_unified_slice_resident_types.py`. Admission (which columns go to pandas and through the guard) and assembly (which columns are spliced back) both call it; neither computes it. If they disagreed, a column could be dropped or written twice.

The choke point for the assembly is `reconstruct_source_shaped_output`: it receives the read set and asserts that the frame columns plus the spliced columns equal the source columns in order. A missing or extra column fails the run with an internal error, not a silent bad output.

The choke point for text width is `narrow_text`. The sentry `test_unified_read_columns_one_rule.py` parses `execution/_unified_slice_*.py` and `execution/physical/` (AST walk) and fails on any `.cast(pa.string())` or `.cast("string")` outside `_arrow_types.py`, and on any call that computes a read set other than `read_columns`. Seeded cases in the sentry's own test: a local `col.cast(pa.string())`, and a second helper that collects `node.columns`. The mutation that must turn it red: inline the large_string cast in `cheap_admission`.

Smallest alternative considered: widen the passthrough domain with type-family predicates and keep the round trip. Rejected. It keeps the pandas cost for every passthrough column, and it still declines `decimal`, nullable `int64` and `large_string`, which fail the round trip, not the domain.

## 9. Acceptance tests (each fails before the change unless marked)

- **U1 any unread type.** One table under 100k rows with unread columns of every type in section 4 "Fields" plus one `hash` target column. The route is `unified_slice`. Each unread output column `equals` the source column (type, values, nulls, chunk-insensitive), at its source position. Fail-before: declines to `pandas_oracle`.
- **U2 lane agreement.** The U1 table at 120,000 rows on the chunked lane and the same data cut to 2,000 rows on the unified slice: unread columns are typed and valued the same on both lanes. Fail-before: the unified slice declines.
- **U3 no change for lossless tables (control).** Tables whose columns are `string`, `int64` without nulls and `bool`, with `redact`, `hash`, `faker`: the output Arrow data and schema equal today's unified slice output, compared without the `pandas` metadata blob. Passes before and after.
- **U4 read columns stay in the frame.** A `group_key` node whose `group_by` sibling is a nullable `int64`, and a `when:` predicate reading a `decimal` column: those two are read, go through the round-trip guard, and decline as today. A third unread `decimal` column alone does not decline. Fail-before: the third column also declined.
- **U5 lossy cases named.** `decimal(12,2)` keeps `decimal128(12, 2)` (pandas gave a different precision); nullable undeclared `int64` keeps `int64` (pandas gave `float64`); `large_string` keeps `large_string`; `timestamp[s, UTC]` keeps its unit. Each is a marked byte change. Fail-before: declined, and the forced pandas route gives the old types.
- **L1 large_string targets.** For each strategy in guarantee 4, a `large_string` target column on the unified slice (2k rows) and the chunked native route (120k rows): admitted, and the masked output equals the same job over the `string` cast of the source. Fail-before: `source_type_not_string` or a unified decline.
- **L2 chunk narrowing.** A 120k-row `large_string` column read in chunks: each chunk narrows on its own and the job completes on the native route.
- **L3 overflow.** `_OFFSET_LIMIT` patched low (`_arrow_types.py:43`, a documented patch target): the column declines with `large_string_offsets_overflow` before any output is written; the message carries no value.
- **L4 sequential unchanged (control).** A two-table FK job with a `large_string` child column under `text_mask`: the sequential route still reports `source_type_not_string`. Passes before and after.
- **S sentry.** `test_unified_read_columns_one_rule.py` passes, and fails on each seeded case.

Mutations (record the head they ran on): splice without the position (U1 red); drop `group_by` siblings from `read_columns` (U4 red); remove the narrow in `run_kernel_step` (L1 chunked half red).

Performance evidence (performance.md): a 90,000-row table with 20 unread `string` columns and one `hash` target, before and after S1, three runs each on the Dell node through `vm-run`, wall time and peak RSS. Expected: the pandas conversion of the 20 columns is gone. A Polars-written `large_string` file at 120k rows, before and after S2. Numbers go in the PR bodies.

## 10. Frozen contracts and compatibility

- **Byte change, marked (S1):** on the unified slice, an unread column's output equals the resident source column. Where pandas was lossy this differs from earlier unified-slice and pandas-route output: `decimal` precision, nullable undeclared ints (no longer `float64`), `large_string` (no longer `string`), `timestamp` units and `date32`. It matches what the chunked lane already writes. Recorded as a ROUTE-OUTPUT-CONTRACT entry in `docs/compatibility-contract.md`.
- **Byte change, marked (S1):** the output schema's `pandas` metadata lists only the read columns. Readers that use the metadata (pandas `to_pandas`) read spliced columns with Arrow's default conversion.
- S1 fragment first line: `Breaking: on the unified slice, columns no rule reads are written as stored in the source (decimal, nullable int, large_string and timestamp keep their exact type), and the pandas schema metadata lists only the masked and read columns.`
- S2 changes no output bytes: a `large_string` source already gave a `string` masked column on the pandas route. New decline code `large_string_offsets_overflow` is added to the reasons catalog (additive).
- D9 flag-on/flag-off parity: becomes "masked and read columns equal the legacy route; unread columns equal the source". The test names each lossy type it exempts.
- `SEED_PROTOCOL_VERSION` and plan digests: unchanged.

## 11. Pre-mortem

- The pandas metadata blob is read by a consumer that expects every column in it (the CLI's sample-output preview, the platform viewer). The builder greps the CLI repo for `b"pandas"` and `pandas_metadata` and lists consumers in the PR. If one relies on it, the owner decides (Q2).
- `when:` reads a column through a helper the read-set walk does not see. U4 covers the closed grammar; the builder confirms the predicate column list comes from the compiled plan, not from string matching.
- A chunked-lane schema rule pins masked output to the source type for some strategy, so a `large_string` source yields `large_string` on chunked and `string` on unified. L1 compares both lanes; a difference stops the build.
- `split_narrow_text` exists and could avoid the overflow decline by splitting. Not used: the overflow case is a single unified table over 2 GiB of text, which the auto-chunk lane takes first.
