## 1. Frame

The unified slice is the default route for a single table under 100,000 rows. It declines to the full-frame pandas oracle for two reasons that have nothing to do with masking:

1. **A passthrough column of a common type.** `cheap_admission` (`execution/_unified_slice_admission.py:196`) converts the whole source table to pandas (line 352), converts it back (line 387), and declines if any column is not type- and value-identical (lines 390-401). Probed at pyarrow 24: `decimal128(12,2)` comes back `decimal128(3,2)`, nullable `int64` not declared lossless comes back `double`, and `large_string` comes back `string`, so these decline. `date32`, `timestamp[us, UTC]` and `float64` with nulls round-trip cleanly. They decline later, in `resident_contract_admission` (line 410), because the passthrough domain is `{string, int64, bool}` (`execution/_operator_registry.py:139`). A table with one `amount decimal(12,2)` column that nobody masks runs full frame.
2. **A `large_string` target column.** Polars and some Parquet writers emit `large_string`. The registry domains are exact `pa.string()` (`execution/_operator_registry.py:93` `_STRING_ONLY`), and the chunked native admission uses `string_source_type_rejection` (`execution/native/_real_type_admission.py:93`, called at line 171). Every string strategy on such a file runs on pandas.

The same pandas loss reaches output on the full-frame and sequential routes. They build output with `table_from_pandas_keeping_source_types` (`execution/_fk_keys.py:521`, called at `execution/_pandas_adapter.py:319` and `execution/_sequential.py:526`). That helper restores only nested types and the date columns named in `keep_types`, so an untouched `decimal`, nullable `int64` or `large_string` column changes type. The chunked lane carries untouched columns from the Arrow chunk and keeps them. So the same config gives different output types by route, and the route depends on table size and on options such as `post_validation` and `fidelity_report` that force the full frame.

## 2. Established solutions

Search run: how Arrow-native engines carry columns a transform does not touch (DuckDB projection pushdown, Polars `with_columns`, Spark `withColumn`); how Arrow tools treat `large_string` against `string` kernels (Arrow C++ kernel dispatch, `pyarrow.compute.cast` docs, Polars string type normalization).

- DuckDB, Polars and Spark never convert a column the query does not reference. Untouched columns are carried by reference into the output.
- Arrow C++ kernels register separate `string` and `large_string` implementations, or cast at the dispatch boundary. A safe cast from `large_string` to `string` copies offsets, keeps the value bytes, and fails past 2 GiB of offsets.
- The engine already has the parts. `untouched_columns` (`execution/_chunked_carry.py:191`) says which columns no node changes, for the full-frame and sequential adapters. `table_from_pandas_keeping_source_types` already takes source types back for some untouched columns and handles a frame with no remaining columns (`execution/_fk_keys.py:547`). `narrow_text` (`_arrow_types.py:26`) is "the one owner of offset-width normalization".

### Reuse inventory

- `untouched_columns` (`execution/_chunked_carry.py:191`): the one definition of "no rule changes this column", reused by the unified slice.
- `table_from_pandas_keeping_source_types` (`execution/_fk_keys.py:521`): the one output assembler for every pandas-built route. It is widened, not copied.
- `narrow_text` and `is_text` (`_arrow_types.py:26`, `:21`): the boundary cast and the predicate.
- `lossless_int_columns_from_config` (`execution/_fk_keys.py:406`): still decides the dtype of columns that stay in the frame.
- `coded(...)` and `RouteDeclineCode` (`execution/native/_route_decline_codes.py:25`): one new member for the offset overflow.

## 3. Guarantee and non-goals

After S1 (one output assembler):

1. `table_from_pandas_keeping_source_types` takes the source Arrow table (not only its schema) and an optional `arrow_columns: Mapping[str, pa.Array]`. It builds the output from the source table's row count and column order: each untouched column is the source column as stored; each column in `arrow_columns` is that array as given; every other column comes from the frame through `from_pandas`. It asserts that the frame row count equals `source.num_rows`, that the frame index is still `RangeIndex(0, n)` (no row was dropped or reordered between the source and the frame), and that the output names equal the source names in order, and raises an internal error otherwise.
2. The full-frame adapter, the sequential route and the unified slice all build output through it. The same config gives the same output types on every route, with any option on or off.

After S2 (UF-DOMAIN):

3. On the unified slice, a **frame column** is a non-passthrough node's target or any column that node reads. `frame_columns(nodes, config, table)` returns, in source order, the target columns of `nodes` plus every column in `column_access(entry).reads` for each node's config entry (`execution/_column_access.py:142-200`; `column_access` at `:362`). This covers `group_key` `group_by` siblings, `when:` reads (phase `source`, WHEN-READS-SOURCE guarantee 9), `joint_mask` `key_by`, `date_shift` `group_by` and `derived` expression references. If any node's access is `reads_unknown`, it returns every column of the batch. PER-COLUMN-ROUTING reuses this one definition for its Python sub-table. S2 builds the frame from the candidate's execution table selected to `frame_columns`; before S3 that table is the original source, and after S3 it is `candidate.execution_source`. The round-trip guard and the domain check apply to frame columns only. A passthrough target outside the frame set may be of any Arrow type.
4. The output is built through the S1 assembler from `candidate.source`, the resident table admission already holds. It is never reloaded.

After S3 (LARGE-STRING-CAST):

5. A `large_string` column targeted by `redact`, `truncate`, `text_redact`, `text_mask`, `faker`, `categorical`, `bucket_perturb`, `date_shift`, `fpe` or `hash` is narrowed to `string` with `narrow_text` at one route boundary. On the unified slice, `CheapCandidate` carries both the immutable original `source` used only for source-shaped output and an `execution_source` in which every targeted `large_string` column is narrowed. `_execute_admitted` substitutes that one `execution_source` into `caller_sources` before `build_live_physical_plan_inputs`; compilation, resident-contract admission, snapshot capture, `when:` predicates and operator execution therefore all see the same narrowed table (`execution/_unified_slice.py:190-252` is the existing sequence that must be rewired). Assembly alone uses the original `source`, so untouched columns retain their stored type. On the resident auto-chunk lane, all resident slices are narrowed and retained by preflight before `_core.mask_chunked` is called (`execution/_pipeline_auto_chunk.py:309-340`). The masked output column is `string`, the type the pandas route writes today.
6. If any unified target or any resident auto-chunk slice cannot narrow to 32-bit offsets, route preflight declines with the registered reason `large_string_offsets_overflow` before compilation or masking. The unified slice falls through to the full-frame oracle. The auto-chunk dispatcher selects its existing oracle lane for the whole table; it does not enter native `_core.mask_chunked`, so no earlier chunk has been masked. The public arbitrary-iterable/streamed chunk entry remains exact-`string` admission because it cannot pre-read and replay a one-shot stream without breaking bounded memory; admitting `large_string` there is a non-goal.

Non-goals: `string_view` sources (they keep `source_type_not_string`); the sequential FK route and out-of-core for `large_string` targets (`string_source_type_rejection` keeps its exact-string meaning there, `execution/_sequential_native_text_mask.py:62`); widening a masking strategy's own domain to new types (DATE-SHIFT-TYPED does `date_shift`); relaxing the unified slice rule that every source column is named in the config (section 4 "Fields"); tables with FK relationships on the unified slice (declined today).

## 4. Enumerations

### Exit paths

- Untouched column of any type: written from the source Arrow column (S1, every pandas-built route).
- Unified slice, passthrough target outside the frame set: no round trip, no domain check (S2).
- Frame column that fails the round-trip guard: unchanged decline, full frame (`execution/_unified_slice_admission.py:401`).
- Frame column outside its strategy's domain: unchanged decline (`execution/_unified_slice_admission.py:521`).
- Assembler row-count or column-order mismatch: internal error, no output written.
- `large_string` target that fits 32-bit offsets: narrowed and admitted (S3).
- `large_string` target that does not fit: `large_string_offsets_overflow`, full frame.
- `string_view` target: `source_type_not_string`, unchanged.

### Routes

| Route | S1 | S2 | S3 |
|---|---|---|---|
| Full-frame pandas (`_pandas_adapter.py:319`) | untouched columns from the source table | none | none |
| Sequential FK (`_sequential.py:526`) | untouched columns from the source table | none | none |
| Unified slice | output through the assembler (`_unified_slice_evidence.py:244`) | frame built from frame columns only; guard and domain on frame columns only | `cheap_admission` builds one narrowed `execution_source`; `_unified_slice.py:190-252` uses it for compile, admission, snapshot, predicates and operators; assembly uses the original source |
| Resident auto-chunk native | none (already carries Arrow chunks) | none | `_pipeline_auto_chunk.py` narrows and retains every resident slice before calling `_core.mask_chunked`; overflow selects the whole-table oracle lane before masking |
| Public iterable / streamed chunked | none | none | unchanged exact-`string` admission; a one-shot stream is not pre-read or silently buffered |
| Out-of-core | none | none | none |

### FK shapes

- Table with FK edges on the sequential route: untouched columns, FK keys that no rule masks included, are written from the source table (S1). A masked key column is unchanged: it is not untouched.
- Composite FK group: every column is masked (`untouched_columns` at `execution/_chunked_carry.py:205`), so nothing is spliced.
- The unified slice declines tables with relationships; unchanged.

### Fields

- Frame column (unified slice): a non-passthrough node's target; a `group_key` `group_by` sibling; a column named in a `when:` predicate.
- Passthrough target outside the frame set: any Arrow type, including `int8` to `uint64`, `float32` and `float64` with `NaN`, `decimal128` and `decimal256`, `date32`, `date64`, `timestamp` of any unit and zone, `large_string`, `binary`, `list` and `struct`.
- Columns the config does not name: unchanged. The unified slice still requires every source column to be named (`execution/_unified_slice_admission.py:315` and the 1:1 check at line 544). Relaxing that is not in this plan.
- A source column literally named `__index_level_0__`: it is named in the config like any other column; as a passthrough target it is untouched and written from the source.

### Output surfaces

- Values and types of untouched columns: the source Arrow column on every route (byte change where pandas was lossy, section 10).
- Column order and row count: the source's, asserted.
- Schema `pandas` metadata: produced by `from_pandas` over the frame-built columns only (byte change, section 10).
- Masked columns: unchanged (S1, S2); `string` from a `large_string` source (S3), the same as the pandas route.
- Route evidence: `unified_slice` in place of `pandas_oracle` for newly admitted tables; new decline code in run records.

## 7. Design notes

One assembler: `table_from_pandas_keeping_source_types` is the only place that turns a masked pandas frame into an output table. It starts from the source's row count and column order, so a frame with no columns (every column untouched) or a source with no rows gives the right shape. `pa.Table.from_pandas` of a zero-column frame has zero rows; the assembler never uses that result for the row count.

One definition of untouched: `untouched_columns` (`execution/_chunked_carry.py:191`). The unified slice uses it for output. `frame_columns` decides only which columns go to pandas for masking, and it is carried on `CheapCandidate` from admission to assembly, so the two steps cannot disagree.

One execution source: `cheap_admission` constructs `execution_source` once. The physical-input builder, compiler, resident-contract gate, snapshot, predicate evaluation and coordinator all consume that exact object; the original `source` is reserved for untouched-column assembly. This preserves the existing identity invariant at `_unified_slice.py:218-230` instead of asking compilation and admission to reason about different schemas. L1's unified cells assert the compiled input schema and resident schema are `string`, not merely that the final output happens to match.

One normalization mechanism: every cast goes through `_arrow_types.narrow_text` (`_arrow_types.py:26-38`). Unified admission owns resident-table normalization; resident auto-chunk preflight owns slice normalization before native route selection. `_real_type_admission.py` and `_operator_step.py` gain no parallel cast or overflow handler. The sentry's Rule B guards that choke point.

Source metadata on `select`: `Table.select` keeps the schema metadata, and that `b"pandas"` blob can name columns and an index that the selection dropped. `pandas_metadata_for(schema, names)` rewrites the blob before `to_pandas`: `columns` keeps the entries whose `name` is in `names`; `index_columns` keeps RangeIndex descriptors (dicts) and drops string entries (a physical index column such as `__index_level_0__`), whose column is then untouched and written from the source. Other schema metadata keys are kept. U6 covers it.

Sentry `test_output_assembly_one_path.py`, a concrete AST rule over `execution/**/*.py`:

- Rule A: a call to `pa.Table.from_pandas` or `pyarrow.Table.from_pandas` is allowed only inside `table_from_pandas_keeping_source_types` and in a named allowlist of non-output uses: `_unified_slice_admission.py` `cheap_admission` (the consistency round trip), `_mixed_fk_bridge.py:274` (a one-column key resolution), `physical/_shadow_assembly.py:95` (dtype normalization), `pipeline/_lifecycle_inputs.py:65` and `:83` (sample frames). Each entry carries its reason in the sentry file.
- Rule B: `.cast(` whose first argument is `pa.string()`, `pa.large_string()`, `"string"` or `"large_string"` is allowed only in `_arrow_types.py`, plus a named allowlist seeded from the first walk with reasons.
- Seeded cases in the sentry's own test: a `from_pandas` in a new output function, and a local `col.cast(pa.string())`; both must fail.
- The mutation that must turn it red: restore the `pa.Table.from_pandas(frame, ...)` call in `reconstruct_source_shaped_output`.

Iterating `node.columns` is not restricted; it is legitimate in admission and assembly.

Smallest alternative considered: widen the passthrough domain with type-family predicates and keep the round trip. Rejected. It keeps the pandas cost for every passthrough column, still declines `decimal`, nullable `int64` and `large_string`, and leaves the per-route type differences in place.

## 9. Acceptance tests (each fails before the change unless marked)

- **U1 untouched types, full frame and sequential (S1).** A table with passthrough columns of every type in section 4 "Fields" plus one `hash` target, run on the full-frame route and as the child of a two-table FK job on the sequential route. - **U3 unified any passthrough type (S2).** The U1 table under 100k rows: route is `unified_slice`; untouched columns equal the source. Fail-before: declines to `pandas_oracle`.
- **U4 control (S2).** Tables whose columns are `string`, `int64` without nulls and `bool`, with `redact`, `hash`, `faker`: output data and schema equal today's unified output, compared without the `pandas` metadata blob. Passes before and after.
- **U5 frame columns keep the guard (S2).** A `group_key` whose `group_by` sibling is a nullable undeclared `int64`, and a `when:` predicate that reads a `decimal` column: both are frame columns and decline as today. - **U5b frame columns follow declared reads (S2).** A `derived` node whose expression reads a passthrough `decimal` column, a `joint_mask` `key_by` column, and a node with `reads_unknown`: the first two read columns are frame columns; with the `reads_unknown` node present every batch column is a frame column. - **U6 source metadata (S2).** A source written by pandas with `b"pandas"` metadata naming a `StringDtype` frame column and a physical `__index_level_0__` column (configured as passthrough): admitted; the frame column reads with the dtype the full metadata gives; `__index_level_0__` is written from the source unchanged.
- **U7 one type per config (S1).** One config with passthrough `decimal(12,2)`, nullable `int64`, `large_string` and `timestamp[ms, UTC]`, plus a masked column.
