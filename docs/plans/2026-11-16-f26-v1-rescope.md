## 1. V1 guarantee

**G1 (rule 2, never delete what is not proven dead litter).** `decoy cleanup --yes` recursively removes an entry only if all of these held on the same inode, in this order: (a) its name is an exact Decoy litter name (`re.fullmatch` on `\._decoy_publication_pending_[0-9a-f]{12}` or `\._decoy_publication_reclaim_[0-9a-f]{12}` in a scope directory, or `decoy-arena-v1-[0-9a-f]{16}` or `\._decoy_arena_reclaim_[0-9a-f]{12}` in the temp root); (b) before any `open`, `fstatat(parent, name, AT_SYMLINK_NOFOLLOW)` shows a directory owned by `geteuid()` with mode exactly 0700 (another uid is `foreign` here, so another user's 0700 entry in a shared `/tmp` is never opened and never costs an `EACCES`); (c) it opens `O_RDONLY|O_DIRECTORY|O_NOFOLLOW` and `fstat` of the descriptor is the inode of (b) with the same type, owner and mode; (d) the interior proof is present and valid: a stage has an owned, no-follow, 0600 regular `.decoy-publication-stage` marker whose magic and original pending-name token are valid, and an arena has an owned, no-follow, 0600 regular `.decoy-arena` whose magic and original arena token are valid; the proof rule is identical under the writer-owned and reclaim names; (e) for a `pending` stage, its age is at least the grace (one hour), where age is now minus the newest `max(st_mtime, st_ctime)` over the stage directory and every entry below it, walked by descriptor with `AT_SYMLINK_NOFOLLOW` and no link followed; a subdirectory the walk cannot open (`EACCES`) counts with its own times and its contents are not walked, since no writer without write and search permission can change them (either reclaim name and either arena name have no grace, 3.1); (f) `flock(LOCK_EX|LOCK_NB)` on that descriptor succeeded; (g) after the lock, (b) to (e), including the full interior proof, hold again and `fstatat(parent, name, AT_SYMLINK_NOFOLLOW)` still names the locked inode; (h) a `pending` stage is renamed to a fresh `._decoy_publication_reclaim_<12 hex>`, and a final-name arena is renamed to a fresh `._decoy_arena_reclaim_<12 hex>`, in the same parent, with the new name checked as the locked inode before removal. The proof is never renamed, replaced or removed by that transition. For either a newly renamed entry or an entry already under a reclaim name, `_rmtree_fd(last=proof_name)` removes every other entry, then unlinks the proof, then removes the reclaim directory with plain `rmdir`. The reclaim name alone never authorizes recursion. If a reclaim-named directory has no valid proof, the shared fallback takes the lock, repeats the outer type, uid, mode, no-follow and inode checks, and permits only a plain `rmdir`: apply removes an empty directory as `removed`, maps `ENOTEMPTY` to `kept`, and maps another removal error to `failed`; preview checks emptiness without mutation and reports the empty case `eligible` and the non-empty case `kept`. In every non-empty case the count carries no path and no child is opened or changed. Anything else is reported retained, with a closed reason, and is not changed. Tests: AT-E2 to AT-E8, AT-E11, AT-E12, AT-E14 to AT-E17, AT-C2, AT-C3.

**G2 (rule 1, a live run is never broken).** (a) Locked stage: a publication stage holds `flock(LOCK_SH)` on its own directory descriptor from creation until after its publish rename or its abort's last `rmdir`, on every route that binds output (they all open the stage through `OutputDir.begin(..., label="publication")`: `publication/_publish.py:359`, `execution/_transactional_sink.py:462`, `execution/_isolated_commit.py:123`). A cleanup run concurrently with a run whose stage is locked changes nothing that run reads or writes, and that run publishes the same bytes it would have without the cleanup. (b) Unlocked stage (an engine before E1, the unlocked fallback of 3.1, NFS mounted `local_lock=flock` or `local_lock=all` where another host's lock is invisible, CIFS before Linux 5.5 where `flock` is local to the client): if the cleaner proves it dead by age while its writer is in fact alive, the cleaner's rename to a `reclaim` name happens before any removal, so the writer's publish rename of the `pending` name fails `ENOENT` and the run fails with an error; either the writer's rename wins and the cleaner removes nothing, or the cleaner's wins and nothing is bound. No unit is ever bound with fewer tables than its descriptor names. Tests: AT-E1, AT-E3, AT-E4, AT-C4.

**G3 (rule 1, preview first).** Without `--yes`, `decoy cleanup` changes nothing on disk (no file, directory, mode, mtime or lock file is created or removed) and lists what `--yes` would remove now. With `--yes`, each entry is proven again at removal (G1); a preview is never trusted. Tests: AT-E6, AT-C1.

**G4 (rule 2, crash safe).** A cleanup killed at any point leaves every entry either untouched under its writer-owned name or under its exact reclaim name with the interior proof still present, except for the final proof-unlink window. The cleaner creates `._decoy_publication_reclaim_<12 hex>` or `._decoy_arena_reclaim_<12 hex>` only after the full interior proof, exclusive lock, and name-to-inode recheck. The next cleanup does not trust that name: it re-proves the stage marker or arena marker exactly as for the writer-owned form, takes the exclusive lock, repeats the proof and inode check, and only then recurses. Both protocols remove every other entry through `_rmtree_fd(last=proof_name)`, unlink the proof last, and call plain `rmdir` last. A kill after the proof unlink therefore leaves an empty reclaim-named directory. The next run cannot re-prove it, so it reaches only the empty-directory fallback and finishes it with plain `rmdir`. A non-empty reclaim-named directory without valid proof is always `kept` and never traversed, including on every later run. Tests: AT-E7, AT-E12, AT-E15 to AT-E17, E3's T-A08-SWEEP.

**G5 (rule 3, value-free).** The engine report and its `str()`/`repr()` hold closed outcome codes and counts only: no path, name, token, size per entry, row value or OS message text. The CLI prints the scope it was given (the project's pipeline names it already shows elsewhere) and counts. Tests: AT-E9, AT-C7.

## 3. Behaviour

### 3.1 Engine

- `fileaccess._fdtree.hold_stage_lock(fd) -> bool` (E1). Contract: `fcntl.flock(fd, LOCK_SH)`, blocking, exactly as the arena takes its lock (`fileaccess/_scratch.py:174`). `EINTR` is retried (PEP 475 already retries `fcntl.flock`; the code never treats `InterruptedError` as unlocked). Any other `OSError`, whatever its errno, returns `False` and the run continues unlocked with the publish unchanged; there is no errno list, because the values differ between platforms (on macOS `ENOTSUP` is 45 and `EOPNOTSUPP` is 102; on Linux both are 95) and a list would turn an unlisted errno into a failed run. Blocking is deliberate: only `min_age_s=0` in tests, or a wall-clock step forward beyond the grace, lets a cleaner reach the lock on a just-made stage. Called in `RootedOutputTxn.__init__` right after `make_stage_dir_at` for the `publication` label (`fileaccess/_output.py:375`), and in the ambient POSIX arm where `_make_stage_dir` now returns the open descriptor instead of closing it (`fileaccess/_local_chain.py:65`). The same two stage-creation choke points create `.decoy-publication-stage` as a 0600 regular file, write fixed magic plus the original pending token, read back its exact proof, and leave it as reserved metadata when the stage binds. The strict arm already keeps `state.stage_fd` open until after the rename (`fileaccess/_output.py:430-436`); in `_discard` (`:259-283`) E1 moves `_close(state.stage_fd)` to after the `rmdir` of the stage name, so the lock is held until the name is gone. The ambient arm stores the descriptor on the txn. E1 moves `_publish_durable_dir` from `fileaccess/_local.py:465-477` to `_local_chain.py`, and closes the descriptor there after `os.replace`, after the `rmtree` in `abort` (`fileaccess/_local.py:479-484`), and in a `weakref.finalize` like the strict arm's. The descriptor is `O_CLOEXEC`, so an isolated child does not inherit it; the parent holds the stage's lock until the parent publishes or aborts (`execution/_isolated_commit.py:123`).
- Module layout (E1 and E3, no import cycle). `fileaccess/_fdtree.py` is a new leaf module that imports only the standard library. It imports `fcntl` only under `if sys.platform != "win32":`, exactly as `fileaccess/_scratch.py:53-54` does. On win32, `hold_stage_lock` returns `False` without referencing or calling `fcntl`. The module owns `_DIR_FLAGS` (moved from `fileaccess/_output.py:75`), `_close` (moved from `fileaccess/_output.py:221-223`), `_rmtree_fd` (moved from `fileaccess/_output.py:226-237`), `_exact_stat(found, kind, mode)`, one `_write_marker` moved from `_scratch.py`, and one exact `_prove_marker(dir_fd, name, expected_magic, token_pattern)` primitive that opens no-follow, checks regular type, uid and 0600 mode, bounds the read, and checks the complete content. `_output.py`, `_local_chain.py` and `_scratch.py` use the one writer; `_scratch._prove_arena` and `_reclaim` use the one reader. `_output.py` imports `_DIR_FLAGS` and `_close` from the leaf instead of defining copies. `_output.py`, `_local_chain.py`, `_scratch.py` and `_reclaim.py` import from it. `_scratch.py` owns the arena constants and private `_apply_arena_reclaim` arm because it already owns arena lifecycle and mutation wrappers. `_reclaim.py` imports those arena names from `_scratch.py` and `STAGE_PREFIX` from `_output.py`; `_scratch.py` never imports `_reclaim.py`. Nothing outside `fileaccess` imports either private module. Neither `_fdtree.py` nor `_reclaim.py` is added to `capability_modules` in `tests/sentry/file_access_modules.toml`: each syscall site in them gets its own row in `tests/sentry/file_access_registry.toml`.
- `fileaccess.reclaim_stages(directory, *, apply, min_age_s=3600) -> ReclaimReport` is introduced preview-only in E2a and gains its apply arm in E2b, in `fileaccess/_reclaim.py`, ambient policy only (`require_ambient`, as `ScratchArena._adopt` does at `fileaccess/_scratch.py:255`). It opens `directory` once (`O_RDONLY|O_DIRECTORY|O_NOFOLLOW` on the last component, so the scope folder itself is never a link; its parents may be the user's own links, as main's ambient outputs are) and lists it with `os.scandir(fd)`. If opening or listing `directory` raises any `OSError`, including `ELOOP`, the function raises no `OSError`: after the `except` block closes it returns a `ReclaimReport` with `scope_unavailable == 1` and every entry count zero. The exception object is discarded before return, so it cannot survive as `__context__`, and the report stores no path, name, errno or OS text. For each listed entry whose name fullmatches the `pending` or the `reclaim` pattern (both built from `STAGE_PREFIX["publication"]` and the token length, 5.2) it runs the G1 proof by descriptor, in G1's order: classify by `fstatat(AT_SYMLINK_NOFOLLOW)` before any `open` (another uid is `foreign`, never opened, so a shared `/tmp`-style folder costs no `EACCES`); open no-follow and compare inodes; prove `.decoy-publication-stage` through `_fdtree._prove_marker`; age over the tree for `pending` (none for `reclaim`); `flock(LOCK_EX|LOCK_NB)`, where `BlockingIOError` is `live` and any other `OSError`, whatever its errno, is `lock_unavailable`; then repeat type, owner, mode, marker, age and the name-to-inode check. With `apply=False` a fully proved entry stops there and releases the lock (outcome `eligible`). With `apply=True`, for a `pending` entry it first uses the arena `_rename` wrapper to move the name to a fresh `._decoy_publication_reclaim_<token_hex(6)>` in the same directory (the new name is checked absent first and redrawn up to 8 times, as `_mark_and_publish` does at `fileaccess/_scratch.py:175-184`; `ENOENT` from the rename means the writer's own rename won, outcome `unproven`, nothing removed) and checks that the new name is the locked inode. For either name, recursive removal is allowed only while the valid marker remains open and unchanged: `_rmtree_fd(last=".decoy-publication-stage")` removes every other entry, then unlinks the marker, calls plain `rmdir` on the reclaim name, and closes the descriptor last. If a reclaim-name entry lacks a valid marker, `_fdtree` performs only the locked, rechecked empty-directory fallback: empty is `removed`, `ENOTEMPTY` is `kept`, and no child is opened. A live unlocked writer (G2(b)) whose files land after the content walk makes the `rmdir` fail `ENOTEMPTY`: `failed`, the `reclaim` name stays for the next run with its marker, and that writer's publish has already lost the `pending` name. It does not recurse into other entries and never looks below the scope directory. Outcomes per entry, closed: `removed`, `eligible` (preview), `live`, `young`, `foreign` (another uid), `unproven` (wrong outer type, mode, link, or a recheck or rename found the name gone or changed), `kept` (reclaim name, invalid or absent marker, non-empty), `lock_unavailable`, `failed` (an `OSError` during an authorized removal; the name stays for the next run). The report holds one count per outcome plus `scope_unavailable`, and nothing else.
- `fileaccess.sweep_scratch(*, apply) -> ReclaimReport` (E3, F25 S5 on the shared core, in `_reclaim.py`): scans `tempfile.gettempdir()` only (F25 4.4 and its `test_sweep_takes_no_root`) for both `decoy-arena-v1-<16 hex>` and `._decoy_arena_reclaim_<12 hex>`. A final-name arena gets F25 4.4 steps 1 to 4 in G1's order: classify by `fstatat` uid before `open`, no-follow open and exact stat, exact `.decoy-arena` marker proof, exclusive lock, then the complete proof and name-to-inode check again. Another user's 0700 arena in a shared `/tmp` is `foreign` and never opened, so `--yes` does not exit 4 on every shared Linux host. A reclaim-name arena gets exactly the same marker, type, uid, exact 0700 mode, no-follow, exclusive-lock and post-lock proof, with no grace. If its marker is absent or invalid, only the shared locked and rechecked empty-directory fallback may call plain `rmdir`; a non-empty entry is `kept` and never traversed. G1(b) and G1(c) call `_fdtree._exact_stat`; `_scratch._exact` at `fileaccess/_scratch.py:99-103` becomes `_exact_stat(os.fstat(fd), kind, mode)` rather than retaining a second predicate. `_scratch._prove_arena` is the one exact name, inode, type, uid, mode and marker predicate used before and after the lock by the owner and sweep, and delegates the marker read to `_fdtree._prove_marker`. It retains `_scratch`'s own magic and token pattern and does not copy `_protected_dir._owned_private` at `fileaccess/_protected_dir.py:106-108`.
- One arena apply protocol, for the owner and sweep (E3). `ARENA_RECLAIM_PREFIX = "._decoy_arena_reclaim_"` lives beside `ARENA_PREFIX` and `_MARKER` in `_scratch.py`; `_reclaim.py` builds its one fullmatch from that fact. `_scratch._apply_arena_reclaim` takes an already proven, exclusively locked arena descriptor, its parent descriptor and its exact current name. For a final-name arena it draws `ARENA_RECLAIM_PREFIX + token_hex(6)`, checks the name absent, atomically renames within the temp root, and checks the reclaim name is the locked inode. For an entry already under a reclaim name it re-proves the marker before removal. It then calls `_rmtree_fd(dir_fd, last=_MARKER)`, unlinks the marker last, and removes the reclaim name. This is state-based dispatch on the exact current name, not a flag argument and not two removal implementations. The owner's `_reclaim` converts its lifetime lock to `LOCK_EX`, rechecks the final name, inode, type, owner, mode and marker, and calls this arm. The sweep proves either name, takes `LOCK_EX|LOCK_NB`, rechecks the same full proof and calls the same arm. A sweep cannot rename a live arena because its nonblocking exclusive lock fails. AT-E12 covers kills immediately before and after the rename, immediately before and after marker unlink, and before final `rmdir`, for both owner and sweep; AT-E15 to AT-E17 cover the no-proof branch. After marker unlink only the empty `rmdir` fallback may finish the directory.
- Win32: importing `decoy_engine.fileaccess` succeeds because `_fdtree.py` never imports `fcntl` there. Both functions return an empty report and change nothing (F25 4.5 for the sweep; F22 5.8 and WIN-FEAS for stages). Named limit L5.

### 3.2 CLI

`decoy cleanup [--yes]` (C1a preview and C1b apply), in `C:src/decoy/cli/cleanup/`:

1. Find the project with the one project root finder (`find_project`, `C:src/decoy/cli/io/_project.py:168`, through the `decoy.cli.io` facade). With a project: list `out/` (`project_out_folder`), and for each child name that passes `is_valid_name` (`C:src/decoy/cli/io/_layout.py:70`), build `pipeline_folder(root, name)` (`:379-381`, path only); `lstat` it, and if it is a symlink, skip it (one policy: a linked pipeline folder is never scanned, and the line for it says "not scanned: link"; not a failure, no exit 4); otherwise read its claim with `read_claim` (`:319-323`). A scope is exactly `out/<name>/` when the folder is not a link, `is_valid_name(name)` is true, and `read_claim(out, name)` returns a non-empty string. `read_claim` already requires `PIPELINE` to be a regular file, not a link, readable, and at most `_CLAIM_MAX_BYTES` (4096 at `C:src/decoy/cli/io/_layout.py:63`); the YAML path stored in the claim need not still exist. No claim, or an unreadable, linked, or oversize claim, puts the folder out of scope. `name_dir` (`:384-391`) is not used: it `mkdir`s and raises `OUTPUT_PATH_ESCAPES` on a linked folder, and cleanup must create nothing (G3). `pipeline_folder` and `project_out_folder` are not exported from the facade today; C1a adds them to `C:src/decoy/cli/io/__init__.py` (264 lines), and `_layout.py` (800, at its cap) is not touched. A folder swapped for a link between the `lstat` and the engine call is refused by the engine's `O_NOFOLLOW` open (3.1): its report has `scope_unavailable == 1`, its scope line says "failed", and C1b exits 4 under `--yes`. Without a project, only the scratch sweep runs, and the output says so.
2. For each scope directory, call `reclaim_stages(dir, apply=yes)`; then `sweep_scratch(apply=yes)` once.
3. Print one line per scope (pipeline name, counts by outcome) and one for scratch. Preview ends with "rerun with --yes to remove", as `decoy library clean` does (CLI PR #219 `_destructive.py:122-165`).
4. Exit: 0 when nothing was left that `--yes` was asked to remove; `EXIT_FINDINGS` (4) when any entry ended `failed` or `lock_unavailable`, or any report has `scope_unavailable`, under `--yes` (the `library clean` rule for "left behind"); a project file that cannot be read keeps today's layout error and exit through `exit_code_for`. No new exit code (the CLI exit codes are public UX: CODEMAP "Gotchas").

The CLI never deletes, renames, creates or opens an entry for writing itself (AT-C9). It does not take the library lock and never reads `.decoy/`.

## 5. Design notes

### 5.1 Scope

The scope manifest is the project layout, not the `cli-local-1` evidence manifest #68 used. The evidence manifest lists published outputs and inputs, which V1 never deletes, and no stage. Stages sit beside the run folder in `out/<name>/` (DELIV 4.3 kind R), and P4 writes the `PIPELINE` claim there when it makes the folder (`C:src/decoy/cli/io/_layout.py:394`, `write_claim`). In scope is exactly a non-link `out/<name>/` whose name passes `is_valid_name` and whose `read_claim(out, name)` result is a non-empty string. The `PIPELINE` claim itself must be a regular, non-link, readable file no larger than `_CLAIM_MAX_BYTES`; its named YAML need not still exist. No claim, or an unreadable, linked, or oversize claim, means not in scope. The temp root scope belongs to the engine (F25 4.4), not to the caller. Owner Q3.

### 5.3 Principles from `architecture.md`

- One place per fact. The stage prefix and stage-marker facts stay beside `STAGE_PREFIX` (`fileaccess/_output.py:45-55`); both stage patterns are built from `STAGE_PREFIX["publication"]` (the `pending` name as is, the `reclaim` name with `pending_` swapped for `reclaim_`) and the token length (`secrets.token_hex(6)`, `:369`), so a renamed prefix cannot leave the reclaimer looking for the old one. The arena prefix, `ARENA_RECLAIM_PREFIX`, marker facts, `_prove_arena` and one arena apply arm stay together in `fileaccess/_scratch.py:56-58`; the sweep imports them rather than copying literals, predicates or mutation steps. `_reclaim.py` owns enumeration, outcome mapping and stage proof orchestration; `_scratch.py` owns arena proof orchestration and the lifecycle transition from proven name to removed name. The primitives every path needs, `hold_stage_lock`, `_prove_marker`, `_rmtree_fd(last=)` and the empty-only fallback, live in the leaf `fileaccess/_fdtree.py` (standard library imports only), so stage and arena paths cannot assign authority to a reclaim name differently.
- Library code does not know its callers. The engine takes a directory and a flag; it knows nothing of projects, pipelines, claims or exit codes. The CLI owns scope, wording and exit.
- Proportionality: no policy file, no digest confirmation, no new reason codes (F25 Q4), no `--json` in V1 (no consumer named), no parameter on `sweep_scratch` beyond `apply`.
