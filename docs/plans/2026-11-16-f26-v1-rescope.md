## 1. V1 guarantee

**G1 (rule 2, never delete what is not proven dead litter).** `decoy cleanup --yes` removes an entry only if all of these held on the same inode, in this order: (a) its name is an exact Decoy litter name (`re.fullmatch` on `\._decoy_publication_pending_[0-9a-f]{12}` or `\._decoy_publication_reclaim_[0-9a-f]{12}` in a scope directory, or `decoy-arena-v1-[0-9a-f]{16}` in the temp root); (b) before any `open`, `fstatat(parent, name, AT_SYMLINK_NOFOLLOW)` shows a directory owned by `geteuid()` with mode exactly 0700 (another uid is `foreign` here, so another user's 0700 entry in a shared `/tmp` is never opened and never costs an `EACCES`); (c) it opens `O_RDONLY|O_DIRECTORY|O_NOFOLLOW` and `fstat` of the descriptor is the inode of (b) with the same type, owner and mode; (d) for an arena, the `.decoy-arena` marker is a 0600 regular file owned by `geteuid()` holding the magic and the name's token; (e) for a `pending` stage, its age is at least the grace (one hour), where age is now minus the newest `max(st_mtime, st_ctime)` over the stage directory and every entry below it, walked by descriptor with `AT_SYMLINK_NOFOLLOW` and no link followed; a subdirectory the walk cannot open (`EACCES`) counts with its own times and its contents are not walked, since no writer without write and search permission can change them (a `reclaim` name and an arena have no grace, 3.1); (f) `flock(LOCK_EX|LOCK_NB)` on that descriptor succeeded; (g) after the lock, (b) to (e) hold again and `fstatat(parent, name, AT_SYMLINK_NOFOLLOW)` still names the locked inode; (h) for a `pending` stage, `renameat` to a fresh `._decoy_publication_reclaim_<12 hex>` in the same directory succeeded and that name is the locked inode; only then are contents removed, by descriptor. Anything else is reported retained, with a closed reason, and is not changed. Tests: AT-E2 to AT-E8, AT-E11, AT-E14, AT-C2, AT-C3.

**G2 (rule 1, a live run is never broken).** (a) Locked stage: a publication stage holds `flock(LOCK_SH)` on its own directory descriptor from creation until after its publish rename or its abort's last `rmdir`, on every route that binds output (they all open the stage through `OutputDir.begin(..., label="publication")`: `publication/_publish.py:359`, `execution/_transactional_sink.py:462`, `execution/_isolated_commit.py:123`). A cleanup run concurrently with a run whose stage is locked changes nothing that run reads or writes, and that run publishes the same bytes it would have without the cleanup. (b) Unlocked stage (an engine before E1, the unlocked fallback of 3.1, NFS mounted `local_lock=flock` or `local_lock=all` where another host's lock is invisible, CIFS before Linux 5.5 where `flock` is local to the client): if the cleaner proves it dead by age while its writer is in fact alive, the cleaner's rename to a `reclaim` name happens before any removal, so the writer's publish rename of the `pending` name fails `ENOENT` and the run fails with an error; either the writer's rename wins and the cleaner removes nothing, or the cleaner's wins and nothing is bound. No unit is ever bound with fewer tables than its descriptor names. Tests: AT-E1, AT-E3, AT-E4, AT-C4.

**G3 (rule 1, preview first).** Without `--yes`, `decoy cleanup` changes nothing on disk (no file, directory, mode, mtime or lock file is created or removed) and lists what `--yes` would remove now. With `--yes`, each entry is proven again at removal (G1); a preview is never trusted. Tests: AT-E6, AT-C1.

**G4 (rule 2, crash safe).** A cleanup killed at any point leaves every entry either untouched, still under its `pending` name, or under a `reclaim` name that only a cleaner makes and that the next cleanup proves (no grace: the cleaner held `LOCK_EX` before the rename, so a `reclaim` entry is never a live writer's) and finishes. Contents go first and the name last; in an arena, the marker goes after every other entry and just before the name, both when the sweep removes it and when its owner reclaims it (3.1). Tests: AT-E7, AT-E12, E3's T-A08-SWEEP.

**G5 (rule 3, value-free).** The engine report and its `str()`/`repr()` hold closed outcome codes and counts only: no path, name, token, size per entry, row value or OS message text. The CLI prints the scope it was given (the project's pipeline names it already shows elsewhere) and counts. Tests: AT-E9, AT-C7.

**Never cleaned in V1** (each is outside the name pattern of G1(a), so the engine cannot reach it, and C1a and C1b add no deletion path of their own, AT-C9). Protection is by name only: no content of a directory protects it. A killed stage may already hold `_decoy_publication.json` (the descriptor is written into the stage before the rename), and it is still litter; a bound unit is safe because its name is not a litter name, not because of its descriptor.

### 3.1 Engine

- `fileaccess._fdtree.hold_stage_lock(fd) -> bool` (E1). Contract: `fcntl.flock(fd, LOCK_SH)`, blocking, exactly as the arena takes its lock (`fileaccess/_scratch.py:174`). `EINTR` is retried (PEP 475 already retries `fcntl.flock`; the code never treats `InterruptedError` as unlocked). Any other `OSError`, whatever its errno, returns `False` and the run continues unlocked with the publish unchanged; there is no errno list, because the values differ between platforms (on macOS `ENOTSUP` is 45 and `EOPNOTSUPP` is 102; on Linux both are 95) and a list would turn an unlisted errno into a failed run. Blocking is deliberate: only `min_age_s=0` in tests, or a wall-clock step forward beyond the grace, lets a cleaner reach the lock on a just-made stage. Called in `RootedOutputTxn.__init__` right after `make_stage_dir_at` for the `publication` label (`fileaccess/_output.py:375`), and in the ambient POSIX arm where `_make_stage_dir` now returns the open descriptor instead of closing it (`fileaccess/_local_chain.py:65`). The strict arm already keeps `state.stage_fd` open until after the rename (`fileaccess/_output.py:430-436`); in `_discard` (`:259-283`) E1 moves `_close(state.stage_fd)` to after the `rmdir` of the stage name, so the lock is held until the name is gone. The ambient arm stores the descriptor on the txn. E1 moves `_publish_durable_dir` from `fileaccess/_local.py:465-477` to `_local_chain.py`, and closes the descriptor there after `os.replace`, after the `rmtree` in `abort` (`fileaccess/_local.py:479-484`), and in a `weakref.finalize` like the strict arm's. The descriptor is `O_CLOEXEC`, so an isolated child does not inherit it; the parent holds the stage's lock until the parent publishes or aborts (`execution/_isolated_commit.py:123`).
- Module layout (E1, no import cycle). `fileaccess/_fdtree.py` is a new leaf module that imports only the standard library. It imports `fcntl` only under `if sys.platform != "win32":`, exactly as `fileaccess/_scratch.py:53-54` does. On win32, `hold_stage_lock` returns `False` without referencing or calling `fcntl`. The module owns `_DIR_FLAGS` (moved from `fileaccess/_output.py:75`), `_close` (moved from `fileaccess/_output.py:221-223`), `_rmtree_fd` (moved from `fileaccess/_output.py:226-237`), and `_exact_stat(found, kind, mode)`. `_output.py` imports `_DIR_FLAGS` and `_close` from it instead of defining copies. `_output.py`, `_local_chain.py`, `_scratch.py` and `_reclaim.py` import from it; `_reclaim.py` also imports `STAGE_PREFIX` from `_output.py`; nothing imports `_reclaim.py` except `fileaccess/__init__.py`. Neither `_fdtree.py` nor `_reclaim.py` is added to `capability_modules` in `tests/sentry/file_access_modules.toml`: each syscall site in them gets its own row in `tests/sentry/file_access_registry.toml`.
- `fileaccess.reclaim_stages(directory, *, apply, min_age_s=3600) -> ReclaimReport` is introduced preview-only in E2a and gains its apply arm in E2b, in `fileaccess/_reclaim.py`, ambient policy only (`require_ambient`, as `ScratchArena._adopt` does at `fileaccess/_scratch.py:255`). It opens `directory` once (`O_RDONLY|O_DIRECTORY|O_NOFOLLOW` on the last component, so the scope folder itself is never a link; its parents may be the user's own links, as main's ambient outputs are) and lists it with `os.scandir(fd)`. If opening or listing `directory` raises any `OSError`, including `ELOOP`, the function raises no `OSError`: after the `except` block closes it returns a `ReclaimReport` with `scope_unavailable == 1` and every entry count zero. The exception object is discarded before return, so it cannot survive as `__context__`, and the report stores no path, name, errno or OS text. For each listed entry whose name fullmatches the `pending` or the `reclaim` pattern (both built from `STAGE_PREFIX["publication"]` and the token length, 5.2) it runs the G1 proof by descriptor, in G1's order: classify by `fstatat(AT_SYMLINK_NOFOLLOW)` before any `open` (another uid is `foreign`, never opened, so a shared `/tmp`-style folder costs no `EACCES`); open no-follow and compare inodes; age over the tree for `pending` (none for `reclaim`); `flock(LOCK_EX|LOCK_NB)`, where `BlockingIOError` is `live` and any other `OSError`, whatever its errno, is `lock_unavailable`; then type, owner, mode, age and the name-to-inode recheck again. With `apply=False` it stops there and releases the lock (outcome `eligible`). With `apply=True`, for a `pending` entry it first uses the arena `_rename` wrapper to move the name to a fresh `._decoy_publication_reclaim_<token_hex(6)>` in the same directory (the new name is checked absent first and redrawn up to 8 times, as `_mark_and_publish` does at `fileaccess/_scratch.py:175-184`; `ENOENT` from the rename means the writer's own rename won, outcome `unproven`, nothing removed) and checks that the new name is the locked inode; then, for both patterns, it removes the contents with `_rmtree_fd`, uses the arena `_rmdir` wrapper on the `reclaim` name, and closes the descriptor last (which drops the lock). A live unlocked writer (G2(b)) whose files land after the content walk makes the `rmdir` fail `ENOTEMPTY`: `failed`, the `reclaim` name stays for the next run, and that writer's publish has already lost the `pending` name. It does not recurse into other entries and never looks below the scope directory. Outcomes per entry, closed: `removed`, `eligible` (preview), `live`, `young`, `foreign` (another uid), `unproven` (wrong type, mode, link, marker, or a recheck or the rename found the name gone or changed), `lock_unavailable`, `failed` (an `OSError` during removal; the name stays for the next run). The report holds one count per outcome plus `scope_unavailable`, and nothing else.
- `fileaccess.sweep_scratch(*, apply) -> ReclaimReport` (E3, F25 S5 on the shared core, in `_reclaim.py`): scans `tempfile.gettempdir()` only (F25 4.4 and its `test_sweep_takes_no_root`), proof as F25 4.4 steps 1 to 4 in G1's order (classify by `fstatat` uid before `open`, so another user's 0700 arena in a shared `/tmp` is `foreign` and never opened; `--yes` does not exit 4 on every shared Linux host), plus the post-lock recheck. G1(b) and G1(c) call `_fdtree._exact_stat`; `_scratch._exact` at `fileaccess/_scratch.py:99-103` becomes `_exact_stat(os.fstat(fd), kind, mode)` rather than retaining a second predicate. The arena marker proof remains `_scratch`'s own magic, exact length and token check, exposed as one function for the sweep. It does not copy `_protected_dir._owned_private` at `fileaccess/_protected_dir.py:106-108`. No rename: every arena on main holds its lock from before its final name exists, so there is no unlocked live arena to race. Removal is `_rmtree_fd(fd, last=".decoy-arena")`, followed by the existing arena `_rmdir` wrapper. F25 4.4's `retained_*` names map onto the same closed outcomes. No grace: an arena is renamed to its final name only after its lock is taken (`fileaccess/_scratch.py:174-177`), so F25's pending-then-rename already closes the creation window.
- Marker last, for the owner too (E3). `_rmtree_fd(dir_fd, *, last: str | None = None)` gains one option: it removes every entry except `last` in `scandir` order, then `last`. The arena owner's own reclaim (`fileaccess/_scratch.py:130-147`, `_rmtree_fd(root.fd.fd)` at `:136`) passes `last=_MARKER`, as the sweep does. Today the owner removes the marker in `scandir` order, so an owner killed midway can leave rows with no marker, which the sweep can never prove (forever `unproven`); with the option, an owner killed at any point leaves the marker until every row is gone. AT-E12 gains the cell.
- Win32: importing `decoy_engine.fileaccess` succeeds because `_fdtree.py` never imports `fcntl` there. Both functions return an empty report and change nothing (F25 4.5 for the sweep; F22 5.8 and WIN-FEAS for stages). Named limit L5.

2. For each scope directory, call `reclaim_stages(dir, apply=yes)`; then `sweep_scratch(apply=yes)` once.
3. Print one line per scope (pipeline name, counts by outcome) and one for scratch. Preview ends with "rerun with --yes to remove", as `decoy library clean` does (CLI PR #219 `_destructive.py:122-165`).
4. No new exit code (the CLI exit codes are public UX: CODEMAP "Gotchas").

The CLI never deletes, renames, creates or opens an entry for writing itself (AT-C9). It does not take the library lock and never reads `.decoy/`.

## 5. Design notes

### 5.1 Scope

The scope manifest is the project layout, not the `cli-local-1` evidence manifest #68 used. The evidence manifest lists published outputs and inputs, which V1 never deletes, and no stage. Stages sit beside the run folder in `out/<name>/` (DELIV 4.3 kind R), and P4 writes the `PIPELINE` claim there when it makes the folder (`C:src/decoy/cli/io/_layout.py:394`, `write_claim`). In scope is exactly a non-link `out/<name>/` whose name passes `is_valid_name` and whose `read_claim(out, name)` result is a non-empty string. The `PIPELINE` claim itself must be a regular, non-link, readable file no larger than `_CLAIM_MAX_BYTES`; its named YAML need not still exist. No claim, or an unreadable, linked, or oversize claim, means not in scope. The temp root scope belongs to the engine (F25 4.4), not to the caller. Owner Q3.

### 5.3 Principles from `architecture.md`

- One place per fact. The stage prefix stays in `STAGE_PREFIX` (`fileaccess/_output.py:45-55`); both reclaim patterns are built from `STAGE_PREFIX["publication"]` (the `pending` name as is, the `reclaim` name with `pending_` swapped for `reclaim_`) and the token length (`secrets.token_hex(6)`, `:369`), so a renamed prefix cannot leave the reclaimer looking for the old one. The arena prefix and marker stay in `fileaccess/_scratch.py:56-58`. The proof and removal protocol (prove, lock, recheck, rename, remove) lives in one module, `fileaccess/_reclaim.py`. The two primitives that the writers also need, `hold_stage_lock` and `_rmtree_fd`, live in the leaf `fileaccess/_fdtree.py` (standard library imports only), so `_output.py` and `_scratch.py` import them without importing `_reclaim.py`, and `_reclaim.py` can import `STAGE_PREFIX` from `_output.py` without a cycle.
- Library code does not know its callers. The engine takes a directory and a flag; it knows nothing of projects, pipelines, claims or exit codes. The CLI owns scope, wording and exit.
- Proportionality: no policy file, no digest confirmation, no new reason codes (F25 Q4), no `--json` in V1 (no consumer named), no parameter on `sweep_scratch` beyond `apply`.
