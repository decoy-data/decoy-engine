## 1. V1 guarantee

**G1 (rule 2, never delete what is not proven dead litter).** `decoy cleanup --yes` removes an entry only if, at the moment of removal, all of these held on the same inode: (a) its name is an exact Decoy litter name (`re.fullmatch` on `\._decoy_publication_pending_[0-9a-f]{12}` in a scope directory, or `decoy-arena-v1-[0-9a-f]{16}` in the temp root); (b) it is a real directory (opened `O_RDONLY|O_DIRECTORY|O_NOFOLLOW`), owned by `geteuid()`, mode exactly 0700; (c) for an arena, the `.decoy-arena` marker is a 0600 regular file owned by `geteuid()` holding the magic and the name's token; (d) `flock(LOCK_EX|LOCK_NB)` on that descriptor succeeded; (e) after the lock, `fstatat(parent, name, AT_SYMLINK_NOFOLLOW)` still names the locked inode; (f) for a stage, `max(st_mtime, st_ctime)` is at least the grace (one hour) in the past. Anything else is reported retained, with a closed reason, and is not changed. Tests: AT-E2 to AT-E8, AT-E11, AT-E14, AT-C2, AT-C3.

**G2 (rule 1, a live run is never broken).** A publication stage holds `flock(LOCK_SH)` on its own directory descriptor from creation until after its publish rename or its abort, on every route that binds output (they all open the stage through `OutputDir.begin(..., label="publication")`: `publication/_publish.py:359`, `execution/_transactional_sink.py:462`, `execution/_isolated_commit.py:123`). A cleanup run concurrently with any `decoy run` changes nothing that run reads or writes, and that run publishes the same bytes it would have without the cleanup. Tests: AT-E1, AT-E3, AT-E4, AT-C4.

**G3 (rule 1, preview first).** Without `--yes`, `decoy cleanup` changes nothing on disk (no file, directory, mode, mtime or lock file is created or removed) and lists what `--yes` would remove now. With `--yes`, each entry is proven again at removal (G1); a preview is never trusted. Tests: AT-E6, AT-C1.

**G4 (rule 2, crash safe).** A cleanup killed at any point leaves every entry either untouched, or still provably litter under its own name (contents first, the name last, the arena marker just before the name), so the next cleanup finishes it. Tests: AT-E7, E3's T-A08-SWEEP.

**G5 (rule 3, value-free).** The engine report and its `str()`/`repr()` hold closed outcome codes and counts only: no path, name, token, size per entry, row value or OS message text. The CLI prints the scope it was given (the project's pipeline names it already shows elsewhere) and counts. Tests: AT-E9, AT-C7.

## 2. Established solutions

Search run (2026-11-16): how tools reclaim crash-left temporary directories without touching live ones, and how they delete a directory tree without following links planted by someone else.

| Source | Pattern | Taken |
|---|---|---|
| `systemd-tmpfiles(8)`, "age" rules | Age-based cleanup of `/tmp` skips a directory, and everything below it, while any `flock(2)` lock (shared or exclusive) is held on it | The liveness lock: the owner holds `LOCK_SH` for the object's life; the reclaimer needs `LOCK_EX|LOCK_NB`. F25 already cites it (`fileaccess/_scratch.py:4`), so a live stage or arena also survives the distribution's own `/tmp` aging |
| Maildir (`maildir(5)`, D. J. Bernstein): `tmp/` files untouched for 36 hours may be deleted; git `gc.pruneExpire` (two weeks for unreachable loose objects) | Delete crash-left temporaries only past an age, so an in-progress write is never raced | The one-hour grace (G1(f)) covers the microseconds between `mkdir` and `flock` at stage creation and stages made by engines before E1 (no lock) |
| systemd `make_lock_file()` (`src/basic/lockfile-util.c`): after `flock`, `fstat` the descriptor and retry if the file was unlinked meanwhile | A lock taken on a descriptor proves nothing about the name unless the name is checked again after the lock | G1(e): after `LOCK_EX`, the name must still be the locked inode; this is what stops a reclaimer from removing a stage that was just renamed into a published unit (AT-E4) |
| CPython `shutil.rmtree` `_rmtree_safe_fd` (bpo-4489) and Rust `std::fs::remove_dir_all` (CVE-2022-21658 fix): `openat(O_NOFOLLOW|O_DIRECTORY)`, `fstatat(AT_SYMLINK_NOFOLLOW)`, `unlinkat` relative to a held descriptor | Symlink-race-safe tree removal | Removal goes through A-4's existing `_rmtree_fd` (`fileaccess/_output.py:231-242`), moved to the reclaim module (E1). No path-based `shutil.rmtree` |
| git `*.lock` convention; F22's own rule (`fileaccess/_durable.py:161-165`) | A lock file is never removed by anyone but its protocol | Lock files are never cleaned |
| `git clean -n` / `-f`; dev-rules `destructive-operations.md` | Read-only preview, then an explicit flag; resolve the exact target, bound the run, reconcile the outcome | Preview by default, `--yes` to remove, each target re-proven at removal, a per-entry outcome |

Custom code that remains: the proof order (no library ships one for this layout) and the stage name pattern, about 150 lines in one module. The stage cannot carry an ownership marker as an arena does, because the stage becomes the published unit by rename and a marker would ship inside the user's output; the name, owner, mode, lock and age stand in for it, which is why E2 is R3 (section 9).

## 3. Behaviour

### 3.1 Engine

- `fileaccess._reclaim.hold_stage_lock(fd)` (E1): `flock(fd, LOCK_SH)` on the new stage descriptor. Called in `RootedOutputTxn.__init__` right after `make_stage_dir_at` for the `publication` label (`fileaccess/_output.py:386`), and in the ambient POSIX arm where `_make_stage_dir` now returns the open descriptor instead of closing it (`fileaccess/_local_chain.py:65`). The strict arm already keeps `state.stage_fd` open until after the rename (`fileaccess/_output.py:441-447`) and closes it in `_discard` (`:275`), so the lock's life is the stage's life with no new state. The ambient arm stores the descriptor on the txn and closes it after `os.replace` in `_publish_durable_dir` (`fileaccess/_local.py:483`), after the `rmtree` in `abort` (`:494`), and in a `weakref.finalize` like the strict arm's. `ENOLCK`, `EOPNOTSUPP` and `EINVAL` from `flock` leave the stage unlocked and the publish unchanged: such a filesystem also refuses the reclaimer's `LOCK_EX`, so an unlocked stage there is never reclaimed (L3). The descriptor is `O_CLOEXEC`, so an isolated child does not inherit it; the parent holds the stage's lock until the parent publishes or aborts (`execution/_isolated_commit.py:123`).
- `fileaccess.reclaim_stages(directory, *, apply, min_age_s=3600) -> ReclaimReport` (E2), ambient policy only (`require_ambient`, as `ScratchArena._adopt` does at `fileaccess/_scratch.py:255`). It opens `directory` once (`O_RDONLY|O_DIRECTORY`; the directory itself may be reached through the user's own links, as main's ambient outputs are), lists it with `os.scandir(fd)`, and for each entry whose name fullmatches the publication stage pattern runs the G1 proof by descriptor. With `apply=False` it stops after the proof and releases the lock (outcome `eligible`). With `apply=True` it removes the contents with `_rmtree_fd`, then `rmdir`s the name, then closes the descriptor (which drops the lock). It does not recurse into other entries and never looks below the scope directory. Outcomes per entry, closed: `removed`, `eligible` (preview), `live`, `young`, `foreign` (another uid), `unproven` (wrong type, mode, link, marker, or the recheck failed), `lock_unavailable`, `failed` (an `OSError` during removal; the name stays for the next run). The report holds a count per outcome and nothing else.
- `fileaccess.sweep_scratch(*, apply) -> ReclaimReport` (E3, F25 S5 on the shared core): scans `tempfile.gettempdir()` only (F25 4.4 and its `test_sweep_takes_no_root`), proof as F25 4.4 steps 1 to 4 plus G1(e), removal contents first, the marker, then the name. F25 4.4's `retained_*` names map onto the same closed outcomes. No grace: an arena is renamed to its final name only after its lock is taken (`fileaccess/_scratch.py:174-177`), so F25's pending-then-rename already closes the creation window.
- Win32: both functions return an empty report and change nothing (F25 4.5 for the sweep; F22 5.8 and WIN-FEAS for stages). Named limit L5.

### 3.2 CLI

`decoy cleanup [--yes]` (C1), in `C:src/decoy/cli/cleanup/`:

1. Find the project with the one project root finder (`C:src/decoy/cli/io/__init__.py` `find_project`). With a project: scope directories are `out/<name>/` for each child of `out/` whose name is a valid pipeline name (`is_valid_name`) and whose `PIPELINE` claim reads (`read_claim`, `C:src/decoy/cli/io/_layout.py:319-324`). The claim is the scope manifest: a directory Decoy did not claim is never scanned. Without a project, only the scratch sweep runs, and the output says so.
2. For each scope directory, call `reclaim_stages(dir, apply=yes)`; then `sweep_scratch(apply=yes)` once.
3. Print one line per scope (pipeline name, counts by outcome) and one for scratch. Preview ends with "rerun with --yes to remove", as `decoy library clean` does (CLI PR #219 `_destructive.py:122-165`).
4. Exit: 0 when nothing was left that `--yes` was asked to remove; `EXIT_FINDINGS` (4) when any entry ended `failed` or `lock_unavailable` under `--yes` (the `library clean` rule for "left behind"); a project file that cannot be read keeps today's layout error and exit through `exit_code_for`. No new exit code (the CLI exit codes are public UX: CODEMAP "Gotchas").

The CLI never deletes, renames or opens an entry for writing itself (AT-C9). It does not take the library lock and never reads `.decoy/`.

## 4. Failure modes

| Case | What happens | Test |
|---|---|---|
| A `decoy run` is writing its stage (concurrent run) | Its `LOCK_SH` makes `LOCK_EX|LOCK_NB` fail: `live`, untouched | AT-E3, AT-C4 |
| The run publishes while the reclaimer is between `open` and `flock` | The run renames the stage onto the run folder while still holding `LOCK_SH`, then closes. The reclaimer then gets `LOCK_EX` on what is now the bound unit, but the recheck finds no entry at the stage name: `unproven`, nothing removed | AT-E4 |
| The run aborts while the reclaimer is between `open` and `flock` | Both remove the same dead tree; each `ENOENT` is absorbed; outcome `removed` or `unproven` | AT-E4 (abort cell) |
| Stage just created, lock not yet taken (between `mkdir` and `flock`) | Age under the grace: `young` | AT-E8 |
| Stage from an engine before E1 (no lock), run still live | Kept while its directory mtime is within the grace. A run that writes only below the top level for over an hour can lose its stage: named limit L1, pre-GA (one CLI pin, one engine) | AT-E8 |
| Partial publish: crash before bind | Stage is dead litter: `removed` after the grace; the empty run folder P4 made stays (V2) | AT-E2, AT-C2 |
| Crash after bind, before `LATEST` | No stage left; the bound run folder and the orphan vault are outside the pattern: untouched | AT-C2 |
| Crash during the descriptor fsync walk before rename | The stage is still the stage: dead litter, `removed` | AT-E2 |
| Symlink named like a stage (to a directory full of data) | `O_NOFOLLOW` open fails `ELOOP`: `unproven`, the link and its target untouched | AT-E5 |
| Symlink or hard link planted inside a dead stage | `_rmtree_fd` unlinks the link, never follows it; a hard link removes one name only, the other name's data stays | AT-E5 |
| Name off by one (11 or 13 hex, upper case, trailing newline, other prefix) | Not a `re.fullmatch`: never opened | AT-E5 |
| Wrong mode (0755), regular file with a stage name, another uid's stage | `unproven` or `foreign`: untouched | AT-E5 (foreign cell needs root, marked) |
| A subdirectory in a dead stage the user made unreadable (`chmod 000`) | `_rmtree_fd` raises `EACCES`: `failed`, the name stays (removed last), exit 4; the next run after the user fixes it finishes | AT-E11, AT-C6 |
| Scope directory unreadable or vanished | That scope reports `failed` (directory not listable), others continue, exit 4 | AT-C6 |
| Cleanup killed mid-removal | Lock dies with the process; the name and, for an arena, the marker are still there: the next cleanup proves it again and finishes | AT-E7 |
| Two cleanups at once | One wins `LOCK_EX`; the other sees `live` for that entry, or `ENOENT` after removal (`unproven`) | AT-E7 (two-sweeper cell) |
| Filesystem without `flock` (some FUSE) or NFS (`LOCK_EX` on a read-only directory descriptor fails `EBADF`) | `lock_unavailable`: untouched, exit 4 under `--yes`. Such a stage is litter forever until the user removes it: named limit L3 | AT-E10 |
| Project file missing | Scratch sweep only, stated in the output | AT-C5 |
| `decoy.yaml` corrupt, or a `PIPELINE` claim unreadable, a link, or naming another YAML | Corrupt project: today's layout error, nothing removed. A bad claim: that directory is not in scope (never guessed) | AT-C3 |
| A pipeline folder `out/<name>` that is a symlink to elsewhere | `reclaim_stages` opens the scope directory the same way run outputs reach it (the user's own link is their choice, as `C:src/decoy/cli/io/_layout.py:114-135` resolves run folders); every entry below is opened `O_NOFOLLOW` | AT-C3 |
| Isolated route: parent killed, orphan child still writing the stage | The parent's lock is gone, so after the grace the stage can be removed under the orphan; the orphan's writes fail. Nothing was going to publish it: no output lost (named limit L4) | none (documented) |
| Clock skew: stage mtime in the future | Age is negative: `young` | AT-E8 |
| Case-insensitive volume | The pattern is matched on the name as listed, case-sensitively, and Decoy writes lower case: an entry the user renamed is never matched | AT-E5 |
| Windows | Empty report, message "not available on this platform", exit 0 (L5) | AT-C8 (Windows lane, by hand) |

Named limits: L1 pre-E1 stages are protected only by the grace; L2 same-uid interference (a process of the same user can forge a name, swap entries between the recheck and `rmdir`; F22 L6 and F25 L6 already exclude it); L3 no `flock`, no reclaim; L4 an orphaned isolated child; L5 Windows.

## 5. Design notes

### 5.1 Scope

The scope manifest is the project layout, not the `cli-local-1` evidence manifest #68 used. The evidence manifest lists published outputs and inputs, which V1 never deletes, and no stage. Stages sit beside the run folder in `out/<name>/` (DELIV 4.3 kind R), and P4 writes the `PIPELINE` claim there when it makes the folder (`C:src/decoy/cli/io/_layout.py:394`, `write_claim`), so the claim marks exactly the directories a Decoy run may leave a stage in. The temp root scope belongs to the engine (F25 4.4), not to the caller. Owner Q3.

### 5.2 Principles from `architecture.md`

- One place per fact. The stage prefix stays in `STAGE_PREFIX` (`fileaccess/_output.py:44-54`); the reclaim pattern is built from it and the token length (`secrets.token_hex(6)`, `:380`), so a renamed prefix cannot leave the reclaimer looking for the old one. The arena prefix and marker stay in `fileaccess/_scratch.py:56-58`. The liveness protocol (hold, prove, recheck, remove) lives in one module, `fileaccess/_reclaim.py`, which is also the new home of `_rmtree_fd` (its third consumer; `_output.py` and `_scratch.py` import it from there).
- Library code does not know its callers. The engine takes a directory and a flag; it knows nothing of projects, pipelines, claims or exit codes. The CLI owns scope, wording and exit.
- Proportionality: no policy file, no digest confirmation, no new reason codes (F25 Q4), no `--json` in V1 (no consumer named), no parameter on `sweep_scratch` beyond `apply`.

### 5.3 Choke points (roadmap 4.1, 4.4)
