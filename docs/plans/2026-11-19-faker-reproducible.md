## 0. The defect, measured

Measured 2026-11-18 on E#695 with `itmask.py` (scratchpad probe: `run_pipeline`, `execution_mode="full_frame"`, 400 rows, one `faker` column), and again on 2026-11-19 with a prototype probe on the Dell (CPython 3.10.20, Faker 40.23.0, `PYTHONHASHSEED` 0, 1, 2 and 12345):

- Hash order. Faker's it_IT address provider builds its city list with `list({c[0] for _cap, cities in fulldict.items() for c in cities})` (`faker/providers/address/it_IT/__init__.py:7`). A set of strings iterates in an order that follows `PYTHONHASHSEED`, so `city()` (`random_element(self.cities)`) picks a different city for the same seeded index in each process. Every engine route that calls it_IT `city` moves: the masking `faker` strategy with `address_city` (deterministic and positional), the composite address providers, and generation `faker_type: city`. Faker 40.54.0 has the same line (wheel checked 2026-11-19).
- Unseeded module random. These Faker modules call the standard library's module-level `random` (one hidden `random.Random` per process, seeded from OS entropy at start-up), never the instance generator that `seed_instance` seeds: `ssn/es_ES` (`cif`, `nie`, `nif`, `nuss`), `ssn/es_MX` (`curp`, `rfc`, `elector_code`), `automotive/uk_UA` and `ssn/uk_UA`, `ssn/sv_SE` (`org_id`, `org_and_vat_id`, `vat_id` through `random.shuffle`), `ssn/th_TH` (`from random import randint`), `ssn/el_GR` (`tin`, `vat_id`) and `passport/en_US` (`passport_gender` through `random.choices`, so `passport_full` in all 104 locales). They ignore every seed. `passport_gender(seed=N)` also calls `random.seed(N)`, which reseeds the process-global generator as a side effect. The same nine modules use module `random` in Faker 40.54.0.
- The FAKER-MIGRATE S1 lock already records all of these as `unstable` (`tests/sentry/dependencies/_faker_lock_lists.py::EXPECTED_UNSTABLE` on `feat/faker-migrate-s1`: 20 entries).
- en_US `first_name`, `email` and it_IT `first_name` are stable across the four hash seeds (controls).

The prototype (section 2, "Chosen design") made all 20 probed pairs stable across the four hash seeds, left the three controls byte-identical to raw Faker, and left the process-global `random` state untouched.

Where the pool builder is: the brief places it in `decoy_engine.determinism`, but that package holds only the seed and derivation code (`_derive.py`, `_hkdf.py`, `_seeds.py`). The V2 masking pool builder is `generation/pool/_builder.py::PoolBuilder`, which calls `FakerAdapter.generate_batch`; the generation pool bridge is `generation/_faker_pool.py::build_pool_values`. Both are fixed by this plan through the Faker factory, not by editing the builders.

## 1. Guarantee and non-goals

### 1.1 What this change promises

1. Same seed and same key give byte-identical masked and generated output across processes, `PYTHONHASHSEED` values and the supported Python minors (3.10, 3.11, 3.12), on every route that turns Faker into output (5.2), for every Faker provider and locale the engine admits on the default install.
2. Every Faker instance the engine builds comes from one factory, `decoy_engine.internal.faker_repro.new_faker`. The factory returns an instance whose providers never read the process-global random generator and whose data lists have a canonical order. A raw `Faker(...)` construction anywhere else in `src/decoy_engine/` fails a sentry.
3. An engine Faker draw never changes the process-global `random` state, so one job cannot move another job's or the host program's random stream.
4. Output of every provider and locale pair that is reproducible today does not change. The FAKER-MIGRATE output lock diff of the build slice contains only "newly reproducible" pairs and no "changed" pair (AT-R8).
5. After the build slice the lock's unstable set is empty. A pair can become unstable again only by adding it to a packaged refusal set, which the engine refuses with a coded reason in every seeded mode (slice R2, owner question Q3).

### 1.2 Non-goals (findings here become follow-ups, not blockers)

- Calendar-dependent providers (FAKER-MIGRATE F-4). Their output depends on the date, not on the process.
- User-registered custom providers that call `random` themselves. `register_faker_provider` documents that `fn` must draw from the seeded instance (`internal/faker_setup.py:66`).
- The `mimesis` extra. It is outside the 1.x freeze (FAKER-MIGRATE owner question B).
- Vendoring or snapshotting Faker's providers (FAKER-MIGRATE Q4, Later).
- CPython changing a `random.Random` method's algorithm between minors. The engine already depends on this for every Faker draw; the FAKER-MIGRATE lock matrix job (3.10, 3.11, 3.12) detects it. Fixing it would mean vendoring a generator, a separate decision.
- Order of the engine's own set iteration outside Faker. The route matrix (AT-R5) would catch it on the tested routes, but no new rule is added for engine code here.
- Platforms outside FAKER-MIGRATE owner question A's blocking set.

## 2. Established solutions

Search run (2026-11-19): web search for Faker issues and changelog entries on providers that bypass the instance generator and on hash-order dependence; Faker's documentation on seeding; pytest-randomly and factory_boy (how test tools reseed Faker and `random`); Mimesis seeding; the CPython `random` and hash-randomization documentation; reproducible-builds guidance on unordered collections. In the codebase: the faker-determinism harness (`scripts/faker-determinism/`, including the hash-order fail-control worker), the FAKER-MIGRATE S1 output lock, `tests/sentry/defects/test_rng_construction.py` (an existing generator-construction sentry), `tests/sentry/_call_resolution.py`, and the 2026-06-26 F16a fix in `expressions/_safe_eval.py:95-113` that moved formula RNG bindings from module `random` to a per-formula `random.Random`.

| Need | Established solution | What we take | What we do not take, and why |
|---|---|---|---|
| A provider must draw from the seeded generator | Faker's own convention and fixes: providers draw from `self.generator.random`; Faker 2.0.3 changed `invalid_ssn` to "use the provider's RNG instead of the random module". Faker docs: `seed_instance` gives an instance its own `random.Random` | The same substitution: inside an engine draw, the name `random` in an affected module resolves to the drawing instance's generator, so `random.choice(x)` becomes `generator.random.choice(x)` with the same call sequence | Rewriting each provider with `self.random_element(...)`: different algorithm, so different bytes from any upstream fix that keeps the call shape, and it is per-provider vendoring |
| Reseed library randomness for reproducibility | pytest-randomly and factory_boy call `random.seed(...)` and set Faker's shared generator state at the start of each test | Nothing at run time | Seeding the process-global `random` (even under a lock): the engine runs pool builds on threads, the host program shares that generator, any other draw between seed and use breaks the stream, and a lock serialises every Faker call. These tools work because a test is single-threaded and owns the process |
| Per-instance generators | Mimesis (`Generic(locale, seed=...)` with its own `Random`), NumPy NEP 19 (`Generator` objects, no global state), the engine's F16a formula fix | One instance generator per Faker instance, already present through `seed_instance`; the fix routes the stray module calls to it | A second RNG design |
| Output independent of hash order | Python docs: set iteration order of `str` depends on hash randomization; reproducible-builds.org: sort unordered collections before output. Faker itself does `sorted(set(...))` for et_EE person names (`faker/providers/person/et_EE/__init__.py:36`) | Canonical order `sorted(...)` for each data list Faker builds from a set (owner question Q1) | Fixing `PYTHONHASHSEED=0` for the process: the CLI and the platform do not own the interpreter's start-up, and it hides the defect rather than removing it |
| Detect the class | The S1 output lock (three hash seeds, 8 draws); the harness's `hash_order_probe_worker.py` fail-control | The lock as the provider-level hash-seed matrix with `EXPECTED_UNSTABLE` required empty; a non-sampling data-order audit across hash seeds; a source scan of the installed Faker for module `random` use | A runtime allowlist of reproducible providers (thousands of pairs frozen into the engine; refuses valid pairs the lock never sampled with kwargs) |
| Enforce the construction rule | `tests/sentry/defects/test_rng_construction.py` (AST walk with `_call_resolution.local_names`) | The same walk shape for `Faker(...)` constructions | A text grep |

Options the brief named, weighed:

| Option | Fixes hash order | Fixes module random | Every route | Global side effects | Verdict |
|---|---|---|---|---|---|
| Sort or canonicalize provider element lists at load | yes | no | yes, if done in one factory | none (instance attribute) | Take, for the hash-order class |
| Wrap providers that use module-level random (route the name to the instance generator during a draw) | no | yes, same call shape | yes, through the factory | none inside a draw; inert outside one | Take, for the module-random class |
| Seed module-level random under a lock | no | only while every caller holds the lock | no (host code and threads draw too) | reseeds the host's generator; serialises Faker | Reject |
| Allowlist of reproducible providers | no | no (refuses instead) | yes | none | Reject as the primary fix: function break for es_ES, es_MX and others that can be fixed |
| Coded refusal for a non-reproducible provider in seeded mode | no | no | yes | none | Take as the backstop for pairs a future Faker adds and the shim cannot fix (slice R2, Q3) |

Chosen design (prototype on the Dell, 2026-11-19, all 20 pairs stable, controls unchanged): the factory (a) canonicalizes the data lists named in one table, (b) once per affected Faker module replaces the module's names that point at the standard `random` module or its bound functions with a proxy, and (c) wraps each public generator method so that the call runs with a context variable set to that generator's `random`. The proxy forwards to the context generator when one is set and to the standard module otherwise. So inside an engine draw the module calls use the seeded instance generator; outside one (host code using its own `Faker`) nothing changes.

Generation path, weighed: generation draws through the same reflected surface (`get_faker_providers`) on instances built by `make_faker` or raw `Faker()` (5.2), reseeding per row or once per pool. Neither shape helps a provider that ignores the instance generator, and the per-row shape picks from the same hash-ordered list. Generation is therefore broken the same way and is fixed by the same factory, with no generation-specific code.

Remaining custom code: one module of about 140 lines (`internal/faker_repro.py`). An upstream Faker fix with the same call shape would make it a no-op with identical bytes (owner question Q2).

## 4. Behaviour

### 4.1 The factory (R1)

`src/decoy_engine/internal/faker_repro.py`:

- `new_faker(locale: str | list[str] | None) -> Faker`: constructs `faker.Faker(locale)` (or `Faker()` for `None`), applies `harden`, and returns it. It raises exactly what `Faker(...)` raises for a bad locale; `make_faker` keeps catching that and falling back to `en_US` with its warning.
- `harden(fake)`, for each factory generator of the instance (`fake._factories`, so locale lists are covered):
  1. Canonical order. For each provider whose `(module, class, attribute)` is in `_CANONICAL_ORDER`, set an instance attribute with the canonical order (`sorted(...)` under the recommended Q1 answer). Today the table has one entry: `("faker.providers.address.it_IT", "Provider", "cities")`. The class attribute is not changed.
  2. Module random. For each module in the MRO of each provider class whose name starts with `faker.`, once per process under a lock: every module global that is the standard `random` module becomes `_SCOPED_RANDOM`; every global that is a bound method of the standard module's hidden instance (`from random import randint`) becomes a scoped function of the same name. The set of patched modules is derived by this walk, not listed by hand.
  3. Scope. Every public attribute of the generator that is a bound method of one of its providers is replaced by a wrapper that sets the context variable `_ACTIVE_RANDOM` to `generator.random` for the call and resets it in `finally`. `generator.random` is read at call time, because Faker's first `seed_instance` replaces the shared generator with a per-instance one.
- `_SCOPED_RANDOM.__getattr__(name)`: when `_ACTIVE_RANDOM` holds a generator and `name` is one of its methods, returns that bound method; otherwise returns `getattr(random, name)`. So `random.seed(N)` inside `passport_gender(seed=N)` reseeds the instance generator, not the process one.

Every construction site in `src/decoy_engine/` (5.2) calls `new_faker` or `make_faker`.

### 4.2 The output lock after R1

The S1 worker builds the reflected shapes with `make_faker` and is hardened without change. Its adapter shape patches `faker.Faker` to return one preconstructed `Faker(locale)`. R1 changes that preconstruction to `_engine_access.new_faker(locale)` and patches the factory name the adapter calls. `output_lock.py --write` then records the 20 former unstable pairs as digests. The rendered diff contains only "newly reproducible" entries (AT-R8). `EXPECTED_UNSTABLE` becomes `{}`.

### 4.3 The coded refusal (R2, Q3)

`decoy_engine/internal/faker_repro.py::NON_REPRODUCIBLE_FAKER_PAIRS: frozenset[tuple[str, str, str]]` (surface, provider, locale), empty after R1. A plan check refuses a column whose provider and resolved locale are in the set, in every seeded mode (deterministic mask, positional mask, seeded generation), with the new reason `provider.faker_not_reproducible` and the existing config-error exit category. An unseeded generation column (`determinism: fresh`) is admitted. A sentry asserts the set equals the lock's unstable set, so a future Faker bump that makes a pair unstable must either extend the shim or refuse the pair; it cannot ship the pair silently.

## 5. Enumerations

### 5.1 Exit paths

- Success: output as today, except the 20 former unstable pairs, which become a fixed function of seed and key.
- Invalid locale on the masking route: `Faker(locale)` raises inside `new_faker`, `FakerAdapter` wraps it as today (`providers_v2/_faker_adapter.py:128`, `providers_v2/_faker_adapter.py:229`); no change.
- Invalid locale on the reflected route: `make_faker` logs the warning and falls back to `en_US` (`internal/faker_setup.py:660`); no change.
- A provider raises during a scoped call: the wrapper resets the context variable in `finally` and re-raises the same exception; the existing provider error handling applies.
- A canonical-order table entry whose attribute is absent in the installed Faker: skipped at run time; the audit sentry fails at the bump PR (AT-R3).
- R2: a pair in `NON_REPRODUCIBLE_FAKER_PAIRS` in a seeded mode: refused at plan compile with `provider.faker_not_reproducible`, config-error exit category; the message names the provider and locale only.

### 5.2 Routes

Every route reaches Faker through one of these construction sites; each moves to the factory:

- Masking `faker` strategy, deterministic and positional: `execution/_strategies/_faker.py:101` builds the pool with `PoolBuilder` (`generation/pool/_builder.py:116`), which calls `FakerAdapter.generate_batch`, which constructs at `providers_v2/_faker_adapter.py:229` (seeded) or `providers_v2/_faker_adapter.py:128` (unseeded cache). Native, chunked and out-of-core masking only index into that Python-built pool.
- Composite providers (person, address, city-state-zip, name-email): `generation/composite/*.py::build_pool`, through the registry and the adapter above.
- Generation per-row `faker_type`: `generation/synthesize.py:499` and `generation/synthesize.py:505` (`make_faker`), `generation/synthesize.py:85` (raw `Faker()` default instance), `generation/_column_streams.py:168` (`make_faker`), `generators/columns.py:84` (raw `Faker()`), `generators/_formula.py:210` (formula `faker` binding).

- Generation pooled `faker_type`: `generation/_faker_pool.py:359` (`make_faker`).
- Text-mask Faker spans: `transforms/_faker_span.py:32` (raw `Faker()` per thread), drawn at `execution/native/_draw_site_providers.py:171`.

## 10. Design notes

- Choke point: `new_faker` is the one place a Faker instance is born in the engine. The rule is enforced by construction: a raw `Faker(...)` fails AT-R1, so a site that skips the factory cannot merge. Mutation: revert one site.
- Second choke point: the patched-module set is derived from the instance's provider MRO at construction, never listed. AT-R2 walks the real loaded modules and the installed source, and proves it sees an aliased import.
- Why a context variable and not seeding: a context variable is per thread and per task, so concurrent pool builds and host code never share state. Seeding the global generator fails all three (section 2).
- Why patch module names, not provider methods: helper functions in the same module (uk_UA `select_gender`) and decorated methods read the module global, so one name swap covers them. Per-method rewrites would be vendoring.
- Why wrap every public generator method, not only those of affected modules: nested calls (`passport_full` calls `passport_gender`; `format` calls `city`) inherit the scope from the outer entry point, and the rule needs no list. The cost is one context-variable set and reset per call (AT-R13).
- Why canonical order is an instance attribute: host code's own it_IT `Faker` keeps Faker's behaviour; only engine instances change.
- Design principles from `architecture.md`: single factory (one place per fact), no flag arguments (`new_faker` has one behaviour; `make_faker` keeps the fallback), typed module constants for the two tables.
- New public names: none. `new_faker`, `harden` and `NON_REPRODUCIBLE_FAKER_PAIRS` live in `internal/`.

## 14. Pre-mortem

- "The factory fixed the masking route, but generation still built raw instances." Guard: AT-R1 over every module; AT-R5 generation cells.
- "A Faker bump added a new module-random provider and nobody saw it." Guard: the walk patches it automatically; AT-R2's source scan and AT-R4's lock fail if it escapes; R2 refuses what cannot be fixed.
- "The patch changed the host program's Faker." Guard: AT-R7.
- "The fix moved output of providers that were fine." Guard: AT-R8 on the lock diff.
- "A rare branch of an es_MX provider still used module `random` after hardening." Guard: AT-R2 checks module globals, not sampled outputs, so a branch is covered whether or not 8 draws reach it.
- "Upstream Faker fixes it_IT with a different order and a 1.x bump becomes a 2.0 change." Answer: owner question Q2, upstream PRs with the same order and call shape.
- "Throughput fell." Guard: AT-R13.

## 15. Residual risks

- RR-1: call-time hash order inside a provider method (iterating a set during a draw) is caught only by the lock and the route matrix samples, not by the attribute audit. None exists in 40.23.0 or 40.54.0 by the lock; a new one would fail the lock at a bump.
- RR-2: an upstream Faker fix that uses a different call shape changes bytes for the module-random pairs at a later bump; under FAKER-MIGRATE question C that is a changed digest, so a 2.0 change unless the shim is kept to preserve bytes.
- RR-3: CPython changing a `Random` method between minors (non-goal); detected by the matrix job.
- RR-4: hardening reads Faker internals (`_factories`, `providers`, generator attributes set by `add_provider`). A Faker refactor of these fails AT-R6, AT-R11 or AT-R1 at the bump PR, not silently.
