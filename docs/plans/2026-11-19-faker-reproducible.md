## 0. The defect, measured

Measured 2026-11-18 on E#695 with `itmask.py` (scratchpad probe: `run_pipeline`, `execution_mode="full_frame"`, 400 rows, one `faker` column), and again on 2026-11-19 with a prototype probe on the Dell (CPython 3.10.20, Faker 40.23.0, `PYTHONHASHSEED` 0, 1, 2 and 12345):

- Hash order. Faker's it_IT address provider builds its city list with `list({c[0] for _cap, cities in fulldict.items() for c in cities})` (`faker/providers/address/it_IT/__init__.py:7`). A set of strings iterates in an order that follows `PYTHONHASHSEED`, so `city()` (`random_element(self.cities)`) picks a different city for the same seeded index in each process. Every engine route that calls it_IT `city` moves: the masking `faker` strategy with `address_city` (deterministic and positional), the composite address providers, and generation `faker_type: city`. Faker 40.54.0 has the same line (wheel checked 2026-11-19).
- Unseeded module random. These Faker modules call the standard library's module-level `random` (one hidden `random.Random` per process, seeded from OS entropy at start-up), never the instance generator that `seed_instance` seeds: `ssn/es_ES` (`cif`, `nie`, `nif`, `nuss`), `ssn/es_MX` (`curp`, `rfc`, `elector_code`), `automotive/uk_UA` and `ssn/uk_UA`, `ssn/sv_SE` (`org_id`, `org_and_vat_id`, `vat_id` through `random.shuffle`), `ssn/th_TH` (`from random import randint`), `ssn/el_GR` (`tin`, `vat_id`) and `passport/en_US` (`passport_gender` through `random.choices`, so `passport_full` in all 104 locales). They ignore every seed. `passport_gender(seed=N)` also calls `random.seed(N)`, which reseeds the process-global generator as a side effect. The same nine modules use module `random` in Faker 40.54.0.
- Two more Faker modules bind module `random` outside any provider class (40.23.0): `faker/generator.py:1` (`import random as random_module`, used for `random_module.Random()` in `seed_instance`, line 73) and `faker/providers/color/color.py:16` (`import random`, drawn at lines 147 and 148 only when `RandomColor` is built without a generator; the color provider always passes one, `providers/color/__init__.py:228`). Neither draws on an engine route today, but a hardening walk over provider MROs would miss both (section 4.1 step 2 covers them). `faker/utils/distribution.py` uses `random` only as a parameter name (lines 10 to 13, 29 to 35, 60 to 73); it binds no module.
- The FAKER-MIGRATE S1 lock already records all of these as `unstable` (`tests/sentry/dependencies/_faker_lock_lists.py::EXPECTED_UNSTABLE` on `feat/faker-migrate-s1`: 20 entries keyed `(surface, provider)`). The lock runs its clock-A workers at eight hash seeds (`A_SEEDS = tuple(range(8))`, `scripts/faker-determinism/output_lock.py:62`) with 8 draws each.
- en_US `first_name`, `email` and it_IT `first_name` are stable across the four hash seeds (controls).

The prototype (section 2, "Chosen design") made all 20 probed pairs stable across the four hash seeds, left the three controls byte-identical to raw Faker, and left the process-global `random` state untouched.

Where the pool builder is: the brief places it in `decoy_engine.determinism`, but that package holds only the seed and derivation code (`_derive.py`, `_hkdf.py`, `_seeds.py`). The V2 masking pool builder is `generation/pool/_builder.py::PoolBuilder`, which calls `FakerAdapter.generate_batch`; the generation pool bridge is `generation/_faker_pool.py::build_pool_values`. Both are fixed by this plan through the Faker factory, not by editing the builders.

## 1. Guarantee and non-goals

### 1.1 What this change promises

1. Same seed and same key give byte-identical masked and generated output across processes, `PYTHONHASHSEED` values and the supported Python minors (3.10, 3.11, 3.12), on every route that turns Faker into output (5.2), for every Faker provider and locale the engine admits on the default install. This includes a second process that re-masks only a child table against a parent kept from an earlier process (5.3).
2. Every Faker instance the engine builds comes from one factory module, `decoy_engine.internal.faker_repro` (`new_faker` and `new_faker_or_default`). The factory returns an instance whose providers never read the process-global random generator and whose data lists have a canonical order. A raw `Faker(...)` construction or an `add_provider` call anywhere else in `src/decoy_engine/` fails a sentry.
3. An engine Faker draw never changes the process-global `random` state, so one job cannot move another job's or the host program's random stream.
4. Output of every provider and locale pair that is reproducible today does not change. The FAKER-MIGRATE output lock diff of the build slice contains only "newly reproducible" pairs and no "changed" pair (AT-FR8). Any "changed" pair stops R1 and requires a plan revision before implementation continues.
5. After the build slice the lock's unstable set is empty (`EXPECTED_UNSTABLE == {}`, AT-FR4 static cell). A Faker bump that makes any pair unstable fails that cell in the bump PR, which must then extend the shim or take the deferred refusal (4.3). Nothing unstable can ship silently.
6. Every test this plan marks `faker_output_lock` runs in a required CI job on 3.10.20, 3.11.9 and 3.12.7, proved by a lane-coverage cell (AT-FR14).

### 1.2 Non-goals (findings here become follow-ups, not blockers)

- Calendar-dependent providers (FAKER-MIGRATE F-4). Their output depends on the date, not on the process. This also covers the clock-based providers in `faker/providers/misc/__init__.py` (lines 198 and 263).
- `os.urandom` in `faker/providers/misc/__init__.py:63`: reached only on an unseeded generator; every seeded engine route seeds first.
- User-registered custom providers that call `random` themselves. `register_faker_provider` documents that `fn` must draw from the seeded instance (`internal/faker_setup.py:66`).
- The `mimesis` extra. It is outside the 1.x freeze (FAKER-MIGRATE owner question B).
- Vendoring or snapshotting Faker's providers (FAKER-MIGRATE Q4, Later).
- CPython changing a `random.Random` method's algorithm between minors. The engine already depends on this for every Faker draw; the FAKER-MIGRATE lock matrix job (3.10, 3.11, 3.12) detects it. Fixing it would mean vendoring a generator, a separate decision.
- Order of the engine's own set iteration outside Faker. The route matrix (AT-FR5) would catch it on the tested routes, but no new rule is added for engine code here.
- A runtime refusal of non-reproducible pairs (deferred to V2-LOG, 4.3).
- Platforms outside FAKER-MIGRATE owner question A's blocking set.

| Option | Fixes hash order | Fixes module random | Every route | Global side effects | Verdict |
|---|---|---|---|---|---|

Chosen design (prototype on the Dell, 2026-11-19, all 20 pairs stable, controls unchanged): the factory (a) canonicalizes the data lists named in one table, (b) once per loaded Faker module replaces the module's names that point at the standard `random` module or its bound functions with a proxy, and (c) wraps each public generator method so that the call runs with a context variable set to that generator's `random`. The proxy forwards to the context generator when one is set and to the standard module otherwise. So inside an engine draw the module calls use the seeded instance generator; outside one (host code using its own `Faker`) nothing changes.

Generation path, weighed: generation draws through the same reflected surface (`get_faker_providers`) on instances built by `make_faker` or raw `Faker()` (5.2), reseeding per row or once per pool. Neither shape helps a provider that ignores the instance generator, and the per-row shape picks from the same hash-ordered list. Generation is therefore broken the same way and is fixed by the same factory, with no generation-specific code.

Remaining custom code: one module of about 160 lines (`internal/faker_repro.py`). An upstream Faker fix with the same call shape would make it a no-op with identical bytes (owner question Q2).

## 4. Behaviour

### 4.1 The factory (R1)

`src/decoy_engine/internal/faker_repro.py`:

- `_construct(locale: str | list[str] | None) -> Faker`: private; `faker.Faker(locale)`, or `Faker()` for `None` or empty. The only raw construction in `src/decoy_engine/`.
- `new_faker(locale) -> Faker`: `harden(_construct(locale))`. It raises exactly what `Faker(...)` raises for a bad locale. Used by the strict adapter route.
- `new_faker_or_default(locale) -> Faker`: the `make_faker` fallback, moved here so that the `except` covers construction only:

  ```python
  try:
      fake = _construct(locale)
  except (AttributeError, ValueError, TypeError) as exc:
      _log.warning(
          "make_faker: locale %r is invalid (%s); falling back to en_US",
          locale,
          type(exc).__name__,
      )
      fake = _construct(None)
  return harden(fake)
  ```

  A hardening error raises to the caller; it never becomes a silent en_US fallback. The warning does not interpolate `exc` or `str(exc)`, so R1 deletes the old exception-interpolation allowlist and baseline entries. The rendered message keeps the existing locale, exception type and fallback intent while dropping exception text. The byte-for-byte claim is about message text only and does not claim logger-name identity. The logger name changes from `decoy_engine.internal.faker_setup` to `decoy_engine.internal.faker_repro`. The caplog tests at `tests/unit/internal/test_faker_setup.py:254-282` select the new logger and continue to assert only the locale and `falling back to en_US`, not exception text.
- `harden(fake)`, idempotent (a method already wrapped carries a marker attribute and is skipped), for each factory generator of the instance (`fake._factories`, so locale lists are covered):
  1. Canonical order. For each provider whose `(module, class, attribute)` is in `_CANONICAL_ORDER`, set an instance attribute with the canonical order (`sorted(...)` under the recommended Q1 answer). Today the table has one entry: `("faker.providers.address.it_IT", "Provider", "cities")`. The class attribute is not changed.
  2. Module random (option i of Dennis H2). Under a module lock, for every module in `sys.modules` whose name is `faker` or starts with `faker.` and that this process has not processed yet: every module global that is the standard `random` module object becomes `_SCOPED_RANDOM`; every module global that is a bound method of the standard module's hidden instance (`getattr(v, "__self__", None) is random._inst`, which is what `from random import randint` binds) becomes a scoped function of the same name. Globals bound to the classes `random.Random` or `random.SystemRandom` (`faker/proxy.py:8`, `faker/utils/distribution.py:4`) and to Faker's shared generator instance (`faker.generator.random`, imported as `mod_random` at `faker/utils/distribution.py:7`) are not module draws and stay. Parameters and locals named `random` (`faker/utils/distribution.py`) are not module globals and are never touched. The walk is over the real loaded modules, so it covers provider modules, `faker.generator` and `faker.providers.color.color` without a list. `Faker(locale)` imports the locale provider modules before `harden` runs, so they are loaded when the walk runs.
     - `faker.generator`: `random_module` becomes the proxy. Its one runtime use, `random_module.Random()` in `Generator.seed_instance` (`faker/generator.py:73`), resolves `Random` through the proxy fallback to the standard class, so `seed_instance` is byte-identical.
     - `faker.providers.color.color`: `random` becomes the proxy. Its draws at lines 147 and 148 run only without a generator; under a scope they would use the instance generator, outside one the standard module.
  3. Scope. Every public attribute of the generator that is a bound method of one of its providers is replaced by a wrapper built with `functools.wraps(bound_method)`, so `inspect.signature(wrapper)` follows `__wrapped__` and equals the bound method's signature. The wrapper sets the context variable `_ACTIVE_RANDOM` to `generator.random` for the call and resets it in `finally`. `generator.random` is read at call time, because Faker's first `seed_instance` replaces the shared generator with a per-instance one.
- `_SCOPED_RANDOM.__getattr__(name)`: when `_ACTIVE_RANDOM` holds a generator and `name` is in `_DRAW_NAMES`, returns that generator's bound method; otherwise returns `getattr(random, name)`. `_DRAW_NAMES` is derived at import: the names in `random.__all__` whose module attribute is a bound method of `random._inst` (so `Random`, `SystemRandom` and constants fall back to the module). So `random.seed(N)` inside `passport_gender(seed=N)` reseeds the instance generator, not the process one.

Providers added after hardening: `harden` does not hook `add_provider`. The engine never calls `add_provider` (none in `src/decoy_engine/` on `origin/main`), and AT-FR1 makes that a rule: an `add_provider` call outside `faker_repro.py` fails. Engine code that ever needs a custom Faker provider registers it inside the factory before `harden` runs.

Every construction site in `src/decoy_engine/` (5.2) calls `new_faker`, `new_faker_or_default` or `make_faker`.

### 4.3 The coded refusal (deferred to V2-LOG)

Revision 1 planned a runtime refusal set `NON_REPRODUCIBLE_FAKER_PAIRS` keyed `(surface, provider, locale)`. It is deferred:

- The static cell `EXPECTED_UNSTABLE == {}` (AT-FR4) already fails any bump PR that makes a pair unstable, so no unstable pair can ship silently.
- The lock is keyed `(surface, provider)` with compressed locales and separate kwargs cells. A runtime `(provider, locale)` check cannot map one to one onto those keys, so the equality sentry would need its own mapping.
- A plan check needs the effective locale of a column, which `plan/checks/_generate_columns.py` already resolves; a second resolver would be a copy of a central mechanism.

Revisit trigger: the first Faker bump that makes a pair unstable that the shim cannot fix. ## 5. Enumerations

### 5.1 Exit paths

- Success: output as today, except the 20 former unstable pairs, which become a fixed function of seed and key.
- Invalid locale on the masking route: `Faker(locale)` raises inside `new_faker`, `FakerAdapter` wraps it as today (`providers_v2/_faker_adapter.py:128`, `providers_v2/_faker_adapter.py:229`); no change.

### 5.3 FK shapes

- Same-process run: a masked or generated parent key from an affected provider (for example deterministic `faker` with `nif` es_ES or `address_city` it_IT on a key column) with children referencing it. Inside one process the masking pool is built once and cached (`execution/_strategies/_faker.py:97-108`, `ctx.pool_cache`), so parent and child index the same pool and integrity holds before and after. That in-process cache hides the defect.
- Cross-process `--resume`: run 1 masks the parent and is interrupted; the parent output is kept; the rerun in a new process (a new `PYTHONHASHSEED`) rebuilds the pool and masks the child. Before R1 the rebuilt pool for an affected provider differs from run 1's, so the child's masked foreign keys no longer match the kept parent keys: a referential-integrity break with no error. After R1 the pool is a function of seed and key, so the rerun child equals run 1's child. AT-FR5 resume cell.

## 10. Design notes

- Choke point: `faker_repro.py` is the one place a Faker instance is born in the engine, and both of its public constructors return hardened instances. The rule is enforced by construction: a raw `Faker(...)`, an `add_provider` call or an import of `_construct` elsewhere fails AT-FR1, so a site that skips the factory cannot merge. Mutation: revert one site.
- Second choke point: the patched-module set is derived from the real loaded `faker.*` modules at construction, never listed. AT-FR2 walks those modules and the installed source scope by scope, and proves it sees an aliased import, a non-provider module and the unpatchable spellings.
- Why every loaded `faker.*` module and not provider MROs: `faker.generator` and `faker.providers.color.color` bind module `random` outside every provider class. A walk over the loaded package covers them and any future helper module with no list.
- Why a context variable and not seeding: a context variable is per thread and per task, so concurrent pool builds and host code never share state. Seeding the global generator fails all three (section 2).
- Why patch module names, not provider methods: helper functions in the same module (uk_UA `select_gender`) and decorated methods read the module global, so one name swap covers them. Per-method rewrites would be vendoring.
- Why wrap every public generator method, not only those of affected modules: nested calls (`passport_full` calls `passport_gender`; `format` calls `city`) inherit the scope from the outer entry point, and the rule needs no list. The cost is one context-variable set and reset per call (AT-FR13). `functools.wraps` keeps the signature that reflection reads.
- Why canonical order is an instance attribute: host code's own it_IT `Faker` keeps Faker's behaviour; only engine instances change.
- Why the fallback moves into the factory: the `except` must cover construction only (L1), and a construct-only hook outside the factory would be a raw construction the sentry must allow.
- Why select the CI job by marker: a hand-kept file list in a workflow drifts as soon as a marked file is added (the S1 split into three modules already shows it); `-m faker_output_lock` over the narrow parents `tests/sentry/dependencies` and `tests/integration/faker_repro`, plus rule M7, makes the lane follow the marker within the owned paths and fail when a marked file lands outside them.
- Design principles from `architecture.md`: single factory (one place per fact), no flag arguments (`new_faker` and `new_faker_or_default` each have one behaviour), typed module constants for the two tables.
- New public names: none. Everything new lives in `internal/`.

## 14. Pre-mortem

- "The factory fixed the masking route, but generation still built raw instances." Guard: AT-FR1 over every module; AT-FR5 generation cells.
- "A Faker bump added a new module-random provider and nobody saw it." Guard: the walk patches every loaded `faker.*` module automatically; AT-FR2's loaded-module check and source scan and AT-FR4's lock fail if it escapes.
- "The marked tests never ran." Guard: the job selects by marker; AT-FR14 proves every marked file is collected; the R1 gate reads the job's junit.
- "Reflection broke because the wrapper hid signatures." Guard: AT-FR6 (e).
- "The patch changed the host program's Faker." Guard: AT-FR7.
- "The fix moved output of providers that were fine." Guard: AT-FR8 on the lock diff.
- "A rare branch of an es_MX provider still used module `random` after hardening." Guard: AT-FR2 checks module globals, not sampled outputs, so a branch is covered whether or not 8 draws reach it.
- "A resumed job broke foreign keys." Guard: AT-FR5 resume cell.
- "Upstream Faker fixes it_IT with a different order and a 1.x bump becomes a 2.0 change." Answer: owner question Q2, upstream PRs with the same order and call shape.
- "Throughput fell." Guard: AT-FR13.

## 15. Residual risks

- RR-1: call-time hash order inside a provider method (iterating a set during a draw) is caught only by the lock and the route matrix samples, not by the attribute audit. None exists in 40.23.0 or 40.54.0 by the lock; a new one would fail the lock at a bump.
- RR-2: an upstream Faker fix that uses a different call shape changes bytes for the module-random pairs at a later bump; under FAKER-MIGRATE question C that is a changed digest, so a 2.0 change unless the shim is kept to preserve bytes.
- RR-3: CPython changing a `Random` method between minors (non-goal); detected by the matrix job.
- RR-4: hardening reads Faker and CPython internals (`_factories`, `providers`, generator attributes set by `add_provider`, `random._inst`). A refactor of these fails AT-FR2, AT-FR6 or AT-FR11 at the bump PR, not silently.
- RR-5: a Faker module imported lazily after the first `harden` (inside a draw, not at construction) is patched only at the next `harden`. None exists in 40.23.0 (AT-FR2 (a) runs after constructing every locale); the source scan lists every module with a binding, so a new lazy import shows up there.
