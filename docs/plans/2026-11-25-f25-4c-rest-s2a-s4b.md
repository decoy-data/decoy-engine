## 2. Guarantee and non-goals

Rev 8.6 G1 to G6 carry unchanged. After the last slice here (S4b) merges:

- R1. `SCRATCH_NATIVE_PENDING` is empty. Every DuckDB connection call, cursor drain (`fetch_scalar`, `fetchall`, `fetchone`, reader pulls), Arrow or Parquet scratch read and footer read in an engine module runs through `scratch_native`, `scratch_native_iter` or an adapter, so a native failure leaves the boundary as a value-free error (rev 8.6 G6).
- R2. No internal out-of-core function takes a `Path` for scratch. `connect_duckdb`, the relation builders, the joiners, the stager, emit and `stream_table` take a `ScratchArena`, or a `ScratchDir` (section 3.0) where a stage scope hands one. `ScratchArena._adopt` and `scratch_access_for` are gone.
- R3. Every engine-made scratch directory named in section 3 is an arena or stage child, 0700 (or the owner-only ACL on win32) at creation under any umask, and every Python-written scratch file is created 0600 by a platform creator (rev 8.6 G1).
- R4. Over the temp budget, or on a resource errno in a scratch write, the job stops, nothing commits, and the error carries a `QuotaReport` (rev 8.6 G3).
- R5. No scratch cleanup in the converted code swallows a failure. Each opener consumes its final cleanup report exactly once and delivers a `RETAINED` one to a named sink (section 3.0).

Non-goals: at-rest encryption (V2-LOG; criterion (d) records it); the sweep (row 74); byte quotas (row 58b); same-UID interference (rev 8.6 L6); out-of-core arenas on Windows before S1w (section 9.2).

Expected size: 26 slices (including the test-migration slices M1, M2, M3), about 5,600 changed lines in total. New public names: `decoy_engine.fileaccess.ScratchDir` (a protocol, the annotation of the public `scratch=` and `temp_dir=` parameters). New internal names: `read_footer` and `duckdb_spill_child` (ooc `_scratch.py`), `ipc_iter_stream` (`fileaccess/adapters/arrow.py`), `ScratchArena.remove_tree`, `consume_reclaim` and `log_retained` (ooc `_scratch.py`), the `scratch_retained` warning code and log event. New source modules: none (section 10, fan-out).

### 3.0 Four shared pieces

Recursive child removal (slice S2a-1c-ii-a0). `ScratchArena.remove` (`fileaccess/_scratch.py:309-323`) unlinks a file or calls `rmdir` on an empty directory; it is not recursive. New `ScratchArena.remove_tree(component) -> CleanupReport`:

- It validates the component with `self._check(component, writes=True)` (`fileaccess/_scratch.py:274-284`), so a path separator, `..` or the arena marker `.decoy-arena` (:55, refused at :280-281) raises before anything is touched.
- It stats the name with no-follow. A symlink or a file at that name is unlinked as a leaf; its target is untouched. A directory is opened by descriptor with `O_NOFOLLOW | O_DIRECTORY`, cleared with `_rmtree_fd` (`fileaccess/_fdtree.py:127-143`), its descriptor closed on every exit (a `try`/`finally`), then the name is removed with `rmdir` relative to the arena descriptor.
- It never raises `OSError`. Success returns `CleanupReport(disposition=Disposition.REMOVED)`. Any `OSError` returns `CleanupReport(disposition=Disposition.RETAINED, retained_bytes=None, retained_inodes=None)`, the same constructor `_reclaim` uses (`fileaccess/_scratch.py:136-138`).
- `ScratchArena` is POSIX-only until S1w (`fresh` raises on win32 at :215), so `_rmtree_fd`'s empty Windows branch is never reached through it. The win32 fallback's own `remove_tree` is in the next piece.

The scratch capability protocol (slice S2a-1c-iii-a0). G6-2's `stage_scratch()` yields a `ScratchArena` on POSIX and, on win32, the fallback in `fileaccess/_scratch_win32.py` (G6/G7 plan B3a), which is not a `ScratchArena`. `scratch_arena()` (`execution/out_of_core/_scratch.py:62-66`) would send that fallback, or its path, to `_adopt`, which opens with `_osflags.DIRECTORY`; that flag is 0 on Windows (`fileaccess/_osflags.py:26-31`, :51), and `os.open` on a directory does not work there. So a stage child cannot reach `connect_duckdb` on win32 today.

- The name `StageDir` is taken: it is the public output-staging protocol in `fileaccess/_types.py:276-315` that `OutputTxn` extends. The scratch protocol is `ScratchDir`, a `typing.Protocol` in fa `_scratch.py`, exported as `decoy_engine.fileaccess.ScratchDir` (the facade), because public `key_facts`, `column_distinct` and `connect_duckdb` name it.
- Methods: `local_path() -> str`, `create_dir(component) -> ScratchDir`, `create_file(component) -> int` (a 0600 or owner-only descriptor from the platform creator), `remove_tree(component) -> CleanupReport` and `reader()`. `ScratchArena` satisfies it (with `remove_tree` from S2a-1c-ii-a0). The win32 fallback satisfies it after S2a-1c-iii-a0, which adds what G6-2 left out. Its `remove_tree` must report, not suppress: today `fileaccess/_protected_dir.py:170-171` and :289-291 swallow removal errors, so the fallback calls `shutil.rmtree(path, onexc=...)` and returns `RETAINED` (None counts) on any recorded failure. A test in `test_scratch_arena.py` asserts it on the Windows lane.
- `scratch_arena()` (ooc `_scratch.py`) returns any object that is a `ScratchDir` unchanged and sends only a real `pathlib.Path` to `_adopt`. A `str` or any other type raises `TypeError`. `connect_duckdb(temp_dir=)` accepts `ScratchArena | ScratchDir | Path` until S4b drops `Path`.
- The protocol stays after S1w: S1w makes `ScratchArena` work on win32 and deletes the fallback, but the public annotations keep naming `ScratchDir`, so no second signature change is needed.

The final cleanup report and its sinks (slice S2b-0). Every converted tree in section 3 sits inside an arena or stage scope whose opener reclaims it at the end. So an early `remove_tree` that fails is not a leak by itself: the opener's reclaim retries the whole tree. The rule: each opener consumes its final report exactly once, through one helper, and delivers a `RETAINED` report to exactly one sink. Today four openers drop it:

The warning carries no column and an empty `detail`.
- `log_retained(report)` emits one structured log event `scratch_retained` with the field `disposition` only (log-hygiene rule: no path, size or name).
- `generation/pool/_events.py:26-33` lists the code. `CleanupReport` and the result types do not change.

### 9.4 Choke point

The rule "every native scratch call is value-free" is enforced by construction at `scratch_native` (`fileaccess/_scratch.py:409`). The guard is the derived-membership sentry in `tests/sentry/test_file_access_boundary.py`, which walks the AST of every engine module for DuckDB connection calls, cursor drains (with `fetch_scalar` from S2a-1c-ii-a) and scratch reads, and fails on any call outside `scratch_native` in a module not in `SCRATCH_NATIVE_PENDING`. The allowlist is that set: 13 names now, a ratchet (`test_pending_set_only_shrinks`), zero after S4b-0. Mutation: M-3.

## 10. Design notes, established solutions, placement

Design notes: rev 8.6 section 4.7 holds (capabilities over ambient paths; one typed `arena` argument, no flag argument; `_adopt` a separate constructor until S4b deletes it). New here: `remove_tree` is a method beside `remove` on the type that owns the descriptor; it returns a report instead of raising because cleanup must not replace a run's primary error (rev 8.6 I5). The final report is consumed once per opener through `consume_reclaim`, so there is one place that turns a report into a warning, and the warning is a constant so building it cannot fail. `ScratchDir` is a structural protocol, not a base class, so the win32 fallback and `ScratchArena` stay unrelated types; it keeps a name distinct from the output `StageDir`. `read_footer`, `ipc_iter_stream` and `duckdb_spill_child` are single-purpose functions beside their siblings.
