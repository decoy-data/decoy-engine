## 2. Guarantee and non-goals

Rev 8.6 G1 to G6 carry unchanged. After S4b and S1w merge:

- R0. A memory failure recognised by its text leaves the strict boundary as its own type around the fixed `MEMORY_TEXT` (`fileaccess/_errors.py:34`), never around the library's text, so a cell that happens to contain a memory marker cannot reach `str(exc)` (S2a-0).
- R1. `SCRATCH_NATIVE_PENDING` is empty. Every DuckDB connection call, cursor drain (`fetch_scalar`, `fetchall`, `fetchone`, reader pulls), Arrow or Parquet scratch read and footer read in an engine module runs through `scratch_native`, `scratch_native_iter` or an adapter, so a native failure leaves the boundary as a value-free error (rev 8.6 G6).
- R2. No internal out-of-core function takes a `Path` for scratch. `connect_duckdb`, the relation builders, the joiners, the stager, emit and `stream_table` take a `ScratchArena`, or a `ScratchDir` (section 3.0) where a stage scope hands one. `ScratchArena._adopt` and `scratch_access_for` are gone. No production caller, including the post-scan stage (`execution/pipeline/_post_scan.py:254`, :361-366, :412-419), still passes a scratch `Path`.
- R3. Every engine-made scratch directory named in section 3 is an arena or stage child, 0700 (or the owner-only ACL on win32) at creation under any umask, and every Python-written scratch file is created 0600 by a platform creator (rev 8.6 G1).
- R4. Over the temp budget, or on a resource errno in a scratch write, the job stops, nothing commits, and the error carries a `QuotaReport` (rev 8.6 G3).
- R5. No scratch cleanup in the converted code swallows a failure. Each opener consumes its final cleanup report exactly once and delivers a `RETAINED` one to a named sink (section 3.0).

Non-goals: at-rest encryption (V2-LOG; criterion (d) records it); the sweep (row 74); byte quotas (row 58b); same-UID interference (rev 8.6 L6); out-of-core arenas on Windows before S1w (section 9.2).

Expected size: 36 planned heads (counting M1 and M2 separately and excluding optional migration splits), about 8,200 changed lines in total. New public names: `decoy_engine.fileaccess.ScratchDir` (a protocol, the annotation of the public `scratch=` and `temp_dir=` parameters). New internal names: `read_footer` and `duckdb_spill_child` (ooc `_scratch.py`), `ipc_iter_stream` (`fileaccess/adapters/arrow.py`), `ScratchArena.remove_tree`, the `ScratchScope` owner protocol and `log_retained` (fileaccess), `retained_warning` (ooc `_scratch.py`), the `scratch_retained` warning code and log event. New source modules: none (section 10, fan-out).

Recursive child removal (slice S2a-1c-ii-a0). `ScratchArena.remove` (`fileaccess/_scratch.py:309-323`) unlinks a file or calls `rmdir` on an empty directory; it is not recursive. New `ScratchArena.remove_tree(component) -> CleanupReport`:

- It validates the component with `self._check(component, writes=True)` (`fileaccess/_scratch.py:274-284`), so a path separator, `..` or the arena marker `.decoy-arena` (:55, refused at :280-281) raises before anything is touched.
- It stats the name with no-follow. A symlink or a file at that name is unlinked as a leaf; its target is untouched. A directory is opened by descriptor with `O_NOFOLLOW | O_DIRECTORY`, cleared with `_rmtree_fd` (`fileaccess/_fdtree.py:127-143`), its descriptor closed on every exit (a `try`/`finally`), then the name is removed with `rmdir` relative to the arena descriptor.
- It never raises `OSError`. Success returns `CleanupReport(disposition=Disposition.REMOVED)`. Any `OSError` returns `CleanupReport(disposition=Disposition.RETAINED, retained_bytes=None, retained_inodes=None)`, the same constructor `_reclaim` uses (`fileaccess/_scratch.py:136-138`).
- `ScratchArena` is POSIX-only until S1w (`fresh` raises on win32 at :215), so `_rmtree_fd`'s empty Windows branch is never reached through it. The win32 fallback's own `remove_tree` is in the next piece.

## 10. Design notes, established solutions, placement

Design notes: rev 8.6 section 4.7 holds (capabilities over ambient paths; one typed `arena` argument, no flag argument; `_adopt` a separate constructor until S4b deletes it). New here: `remove_tree` is a method beside `remove` on the type that owns the descriptor; it returns a report instead of raising because cleanup must not replace a run's primary error (rev 8.6 I5). Each opener holds one `ScratchScope` whose idempotent `reclaim()` returns the final report, and `retained_warning` is the one place that turns a report into a warning, and the warning is a constant so building it cannot fail. `ScratchDir` is a structural protocol, not a base class, so the win32 fallback and `ScratchArena` stay unrelated types; it keeps a name distinct from the output `StageDir`. `read_footer`, `ipc_iter_stream` and `duckdb_spill_child` are single-purpose functions beside their siblings. The two size moves (`duckdb_spill_child`, `open_join_connection`) move code that already has one job; no new abstraction.

Established solutions: rev 8.6 section 4.8 holds (capability directories after `cap-std` and WASI preopens, `mkdtemp`/`mkstemp` creation modes, `flock(2)` liveness as `systemd-tmpfiles(8)` uses it). Descriptor-relative recursive removal is CPython's own `shutil.rmtree` fd-based walk (`os.fwalk`, `dir_fd`), which the engine already mirrors in `_rmtree_fd`. The fallback's reporting removal is `shutil.rmtree(onexc=...)` (Python 3.12; `onerror` on older interpreters, as the engine's supported range requires). Change Function Declaration in its migration form is Fowler's. Search run for this revision: the codebase only (`git grep` on `origin/main` for `connect_duckdb`, `read_metadata`, `fetch_scalar`, `ipc.open_stream`, `ipc.open_file`, `ignore_errors=True`, `scratch_access_for` and `temp_directory`), plus DuckDB's documented `temp_directory` and `max_temp_directory_size` settings for S3b. The inherited-descriptor lock for S3a is `subprocess.Popen(pass_fds=...)` from the standard library.
