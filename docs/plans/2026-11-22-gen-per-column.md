## 1. Frame

Evidence:

- `run_generation` classifies the whole plan once (`src/decoy_engine/generation/_streamed.py:369`, inside `_run_admitted` at `:352`). If any column declines, the whole plan goes to `_run_legacy` (`:377-378`, `:537-592`), which calls `synthesize._generate_tables_from_config` (`src/decoy_engine/generation/synthesize.py:104-237`): every column of every table runs resident, in the per-row Python loop, and the result reason names only the first decline (`_streamed.py:591`, `PlanAdmission.reason()` at `src/decoy_engine/generation/_admission.py:102`).
- So one `derived` column (row-local, no RNG: `src/decoy_engine/generation/_synthesize_derived.py:31-58`) in a 10M-row plan turns every pooled `first_name` column (6.9M rows/s streamed, audit) into the legacy path, and a sink run into a resident one. The same holds for `unique: true` on one column, a `formula`, a `grouped_series` or `group_key` (`src/decoy_engine/generation/_grouped_windowed_generators.py:211-229`), or a per-parent `derived_aggregate` (`src/decoy_engine/generation/relational/_aggregate.py:80-102`, pandas `groupby` at `:145`).
- Admission is not only by kind. A streamable column declines when the column it reads declines: `reference_parent_ineligible` (`_admission.py:217`) and `windowed_date_anchor_ineligible` (`:235`). A plan is then legacy through two hops.
- GSA S2 widens admission on purpose narrowly and per plan: a `provider` or `lookup` column streams only when every table passes a whole-plan check; an unproven lookup schema, an unproven sibling schema, a sibling or relational edge to the new kinds, or a declared cast other than proven numeric text to `int` keeps the whole plan legacy (GSA S2 plan, failure table and admission section). It also adds an "unresolved" admission state for capacity estimates made without run inputs, and `PlanAdmission.key_columns` (S1b). Section 4.1 maps each of these to a per-column outcome.
- GSA streams `provider`, `lookup`, `statistical` and `inherit` and keeps the named exceptions (`unique`, `derived`, `formula`, `grouped_series`, `derived_aggregate`, `group_key`, inherit from its own table) on `_run_legacy`, with codes (GSA section 4, "Routes"). Its non-goal is this row.
- The column input graph already has one resolver: `iter_generate_input_refs` (`src/decoy_engine/config/_generate_relational/__init__.py:543-580`) gives each input edge (consumer, source table and column, `must_be_earlier`, `phase`). The plan check reads it (`src/decoy_engine/plan/checks/_generate_columns.py:387-400`), as do reproducibility (`src/decoy_engine/generation/_reproducibility.py:120`) and numeric typing (`src/decoy_engine/generation/_numeric_typing.py:200`, in the function at `:184`).
- The streamed assembler already hands each stream the sibling values drawn earlier in the same batch (`generation/stream/_batches.py:89-109`, `next_batch_from` at `src/decoy_engine/generation/_column_streams.py:276`, the sibling dispatch in `draw_batch` at `:290-297`). A row-local column can read them with no new seam. #813 also lets a column stay an Arrow array when no later column reads it (`array_columns`, `generation/stream/_batches.py:56`); which columns are read comes from `sibling_read_names` (`generation/stream/_batches.py:51`), which today knows only the registry's `same_batch` options (`generation/stream/_siblings.py`). A `derived` or whole-column reader is not in that set, so section 5 widens the read set at one place.

## 2. Established solutions

Search run (2026-11-22): Spark and Polars expression planning (per-column physical operators inside one plan); SQL window and GROUP BY execution (streaming partial aggregation, two-phase aggregation); Dask and Spark "persist" for a column that more than one consumer reads; topological scheduling of a column DAG (Kahn 1962); SDV HMA1 parent-then-child generation; pandas `groupby().sum()` on `object` dtype. In the codebase: GSA's streams, `KeyPool`, the budget ledger, the legacy column functions.

- **Per-column operators in one plan.** Spark Catalyst and Polars lower each expression to its own physical operator and run a mixed plan; a non-streamable operator is a blocking node, not a reason to run the whole query in a slower engine. This plan follows that: each column gets a route; a column that cannot stream is a blocking node (a whole-column pass) whose output then feeds the streaming nodes.
- **Materialize the blocking input once.** Dask `persist` and Spark `cache` hold a column that a blocking operator needs, so it is computed once and read by every consumer. Here the read set of the whole-column columns is drawn once in pass 1 and served from memory in pass 2, so no stream is drawn twice and the two passes cannot disagree.
- **Streaming GROUP BY.** DuckDB, Polars streaming and every SQL engine compute `sum`, `count`, `min`, `max` and `mean` per key as a fold over the input in one pass, with state O(distinct keys). The per-parent aggregate follows it. The legacy reduction runs on a pandas `object` Series (`relational/_aggregate.py:138-151`), which reduces with Python `+` left to right in row order; a fold in child row order with the same operator gives the same value. No compensated sum is needed (V9 proves it on floats).
- **Column DAG order.** Kahn's algorithm with the declared position as the tie-break gives one order per plan, stable across runs.
- **Parent-first generation** (SDV HMA1, already the engine's table order, `synthesize.py:153` `generation_order`). A per-parent aggregate reverses one edge (the parent's column reads its children), which is the reason the parent's write is deferred (section 5).

Custom code still needed: the per-table column plan and its schedule, the resident feed, and the aggregate fold. No library schedules Decoy's generate kinds. The whole-column values come from the existing legacy functions, unchanged.

## 3. Guarantee and non-goals

After this row:

1. `_run_legacy` and the plan-wide fallback are gone. Every plan runs on the streamed core, resident or with a sink.
2. Each generate column takes one route from a closed set: `streamed`, `row_batch`, `whole_column` or `per_parent_aggregate` (section 4). A column that can stream streams, whatever its siblings or its parent table do.
3. Only the named exceptions take `whole_column`: `unique` and `unique_together` members, `formula`, `grouped_series`, `group_key`, same-table `derived_aggregate`, and the decline reasons listed in section 4 (each with a registered code). `derived` takes `row_batch`. A per-parent `derived_aggregate` takes `per_parent_aggregate`.
4. A whole-column column reads only its declared inputs (from `iter_generate_input_refs`). An undeclared read is refused with a code.
5. Memory is bounded under a ceiling: the whole-column values, the read set they need, and the aggregate state are reserved in the ledger before the table's first row is drawn. A plan that does not fit is refused with `GenerationBudgetExceeded`, before any write.
6. Output is a function of (plan, seed): the same at any batch size, resident or with a sink, and on every rerun.
7. The run card and `quality_metrics["generation_route"]` show each column's route and, for `whole_column`, its code.

Non-goals: streaming `unique` (a bounded distinct-set design is separate); a native kernel for any exception kind; changing any exception kind's values when its inputs are the same; the mask lane's per-column routing (PER-COLUMN-ROUTING); the pinned execution path (`generation/_pinned_execute.py`), which keeps its own loop and is out of this row.

### GSA S2 whole-plan rules, per column

GSA S2 keeps a whole plan legacy when it cannot prove that the streamed lane gives every field of every table the same Arrow type, order and values as the legacy loop (GSA S2 plan, failure table and section 8.8; its AT-S2-2 names the cells: an all-null sequence beside a provider, an empty or all-null reference child, an unrelated table with an inferred nullable field). This row keeps that guarantee field by field. S1 changes the GSA S2 check from a plan boolean into `unproven_fields(plan) -> frozenset[(table, column)]`: the same checks over every field of every table, returning each field it cannot prove instead of stopping at the first. Each returned non-aggregate field takes `whole_column`, and a whole-column field is typed by the legacy rule over its full values with the plan-wide `numeric_plan` and `reader_types` (the same calls `synthesize.py:153-155` makes), so its type is the legacy type, including Arrow `null`. Fields the check proves keep their route. A `per_parent_aggregate` column is the exception: its route comes from its kind, never from the schema check, because only the S4 fold computes its values (`generation/relational/_aggregate.py:75` returns `[None] * n` for that kind on the streamed path at #813). An unproven aggregate field stays `per_parent_aggregate` and the fold reuses #813's aggregate typing. A declared `output_type` goes through the existing cast. Otherwise the op fixes the type for `mean` (`double`) and `count` (`int64`). Other ops use the resolved child column type. Only an unresolved type falls back to inference (`generation/relational/_aggregate.py:60-61`, `generation/relational/_aggregate.py:165-186`, `generation/relational/_aggregate.py:198-210`). Until S4 the execution gate sends the plan to `_run_legacy`. The GSA S2 tests that assert "the plan stays legacy" change to assert this per field; the builder lists each in the PR body.

| GSA S2 case | After this row | Why it is safe |
|---|---|---|
| a field whose streamed type GSA S2 cannot prove (all-null, empty, inferred nullable, legacy sibling typing changes) | that field `whole_column` (`gen_whole_column_schema_unproven`, or the more specific code below) | legacy values and legacy typing over the full column |
| lookup with an inconclusive schema inference | that column `whole_column` (`gen_whole_column_lookup_schema`) | pass 1 draws with the prepared lookup context GSA S2 uses for legacy, so values and type are the legacy ones |
| a declared cast GSA S2 does not prove, on any column | that column `whole_column` (`gen_whole_column_declared_cast`); the existing cast post-pass runs on its full values in pass 1 | same cast code on the same values. If it fails, the error is today's error. A failure in a later table aborts `OutputPublish` (one publish per run, `_streamed.py:517-522`), so nothing is published, as with the legacy loop |
| prepared run, lookup list missing | unchanged public error: the legacy lookup function raises it in pass 1 | same function, same inputs |
| provider or lookup width unknown, bounded ceiling | `GenerationUnboundedError` with `GENERATION_COLUMN_UNBOUNDED` from `_reject_unbounded` (`_streamed.py:249-258`), before any provider or draw | unchanged refusal |
| provider or lookup width unknown, unbounded | that column `whole_column` (`gen_whole_column_provider_width`) | holds one column, not the plan |
| width known, held need does not fit | `GenerationBudgetExceeded` in preflight, before the first draw of the run | section 5, reservations |

Order of the public checks, unchanged from GSA S2 and kept by one function: plan check (including `generate_provider_locale_unsupported`), then the live provider metadata check in admission (a locale the live provider no longer supports raises `GENERATION_PROVIDER_FAILED`, GSA S2 plan line 252), then `_reject_unbounded`, then the preflight fit, then draws. So a live locale mismatch on a provider of unknown width raises `GENERATION_PROVIDER_FAILED` with zero provider draws, not `GENERATION_COLUMN_UNBOUNDED`.

### Exit paths

1. Every column `streamed` or `row_batch`: the GSA streamed lane, resident or sink (`_streamed.py:517-522`). Unchanged shape.
2. A table with `whole_column` columns: pass 1 (the read set and the whole-column values, resident and reserved), then pass 2 (the streamed lane with the held columns fed per batch).
3. A table with a `per_parent_aggregate` column: pass 1 now (the keys its children read); pass 2 deferred until each child table has streamed; then the parent streams with the aggregate column.
4. Refusals before the run's first draw: `GenerationUnboundedError` (unchanged), `GenerationBudgetExceeded` (preflight prices every table's peak, section 5), and the structural codes above (`generation_duplicate_column`, `generation_column_cycle`, `generation_route_unresolved`). `generation_undeclared_read` and `generation_value_type_mismatch` are raised where they happen. All are raised after any `except` block closes.
5. A sink failure mid-table: `OutputPublish` aborts staging, as today (`_streamed.py:519`).
6. A whole-column function raises (for example `unique` cannot reach `n` distinct values, or a declared cast fails): its existing coded error, unchanged, before pass 2 writes the table. If an earlier table has written to staging, `OutputPublish` aborts and nothing is published.

### FK shapes

- `reference` to a parent in the plan whose key column is `streamed`: unchanged (key pool collected while the parent streams).
- `reference` to a parent whose key column is `whole_column` (for example `unique: true` on a faker key): today `reference_parent_ineligible` and the whole plan is legacy. After: the parent key is served from the resident feed, `KeyPool` collects it in pass 2 as for any streamed column, and the child streams.
- `reference` with `min_per_parent`/`max_per_parent` or `distribution: fitted`: `whole_column` in the child, reading the parent key pool. Parent and siblings stream.
- Self-reference (tree over the table's own rows): `whole_column`, reading its own table's key column (`reference_column`) from pass 1. The key column is a declared input (section 5, one read set), so `ReadGuard` allows it.
- `inherit` from a parent: streamed (GSA S3). From its own table: `whole_column`.
- `windowed_date` with `anchor_via` a parent column: `whole_column`; the parent column is collected while the parent streams (parent-column collector, reserved).
- Per-parent `derived_aggregate` (`from_table`, `via`): the child's `via` column is the FK; the fold groups by it; the parent key column is the join key. Composite keys use the key tuple.
- Cross-table FK cycle: refused at plan check today; unchanged.
- A parent outside the plan (a masked or external table): refused today by `generation_order` before any draw (`synthesize.py:250-257`; the legacy loop starts with empty `pools`, `synthesize.py:157`). Unchanged.

### Output surfaces (byte changes; each on a changelog `Breaking:` line)

1. **Columns that ran legacy only because of another column.** In a plan with any declined column, every other column now runs its streamed route. Its bytes become the bytes the same column gives in a plan with no declined column. For kinds whose streamed draw equals the legacy draw (GSA A5, A7, A8: `provider`, `lookup`, `statistical`, `inherit`) nothing changes. For the rest the S2 test V6 measures each kind on the legacy loop and on the streamed lane at the dependency head (GSA S3 merged; the S1 PR records it) and the slice records the kinds that differ, for the changelog line. Expected to differ: pooled `faker` (GSA S1b rule), `categorical` and `distribution` (one persistent stream against the legacy per-column call).
2. **Whole-column columns that read a column from item 1.** Their inputs change, so their values change. Their function and seed do not.
3. **`derived`.** Same values (same expression on the same row's sibling values); it changes only when a sibling changes under item 1. `row_index` in error messages is the whole-table row, as today.
4. **Per-parent aggregate.** Same values for the same child rows (fold in child row order, V9). The parent table is written to the sink after its children.
5. **Route evidence.** `GenerationResult.reason` loses `legacy:<...>`; `columns` and `quality_metrics["generation_route"]["columns"]` are new; the CLI shows a per-column route.

## 5. Design notes

- **Column plan, one per table.** `plan_table_columns(table, admission) -> TableColumnPlan` (new `generation/stream/_column_plan.py`) builds the table's column DAG from `iter_generate_input_refs` (same-table edges for the order, cross-table edges for the collectors). On #813 the resolver skips `reference_column` (it has no `ref_kind`, `config/_generate_options.py:318`, `config/_generate_relational/__init__.py:555-557`), while `self_reference` reads `generated[col["reference_column"]]` (`generation/relational/_self_reference.py:83`). S1 adds the edge at the resolver: a same-table `reference_column` yields an edge with kind `self_key`. The builder lists each resolver caller and shows it ignores or handles the new kind (the plan check must not change its verdicts; V12 covers it). The column plan orders it with Kahn's algorithm (declared position breaks ties), and computes the read set: every column a `whole_column` column reads, transitively, in this table. It also lists, per parent table, the columns whole-column children read (parent-column collectors). A cycle is refused with `generation_column_cycle`. This is the only place routes and order are decided; `run_generation` and the assembler read it.
- **Pass 1.** For a table with `whole_column` columns, pass 1 materializes the closure (every `whole_column` column and every column it reads, transitively) in DAG order across all routes. A `streamed` or `row_batch` member is drawn through its stream over the table's full layout when its turn comes (same streams, same sizes, so the values pass 2 would draw) and its emitted values are kept (post-null, pre-cast, as `emitted` holds them at `generation/stream/_batches.py:109`). A `whole_column` member is computed by the legacy function when its turn comes. So an alternating chain (held formula, then a streamed `windowed_date` anchored on it, then a held formula that reads the date) runs in order. Each stream is drawn once per row in the whole run: pass 2 serves closure members from held values. A `whole_column` member is computed by the legacy function given a `ReadGuard` over the read set and the parent tables built from the collectors. `ReadGuard` is a `Mapping` that raises `generation_undeclared_read` on a key outside the column's declared inputs; its `items()` yields only declared inputs. Each whole-column column's Arrow type comes from the legacy typing (`arrow_table`) of its values, so pass 2's schema is known before the first write.
- **Pass 2.** The one assembler runs every column in DAG order and builds the batch in declared order. A held column is served by `ResidentColumnStream` (slices of the held list at `offset`), so a streamed column that reads it (a `reference` parent, a `windowed_date` anchor) sees it in `emitted` as it sees any sibling. Read-set columns are served from their pass-1 values, not redrawn.
- **Row batch.** `DerivedStream.next_batch_from(offset, size, siblings)` evaluates `apply_derived` per row with the row's sibling values and `row_index = offset + i`. No RNG, so batch size cannot change a value. The assembler needs the Arrow type before the first batch, and the legacy loop infers it from the full column (`_admission.py:107-110` records why #813 declines derived). So `row_batch` applies only to a `derived` column with a declared output type (the GSA output-type rule, cast post-pass per batch). A `derived` column with no declared type takes `whole_column` (`gen_whole_column_derived_type`) and gets the legacy type from its full values.
- **Value-free conversion.** PyArrow puts the offending cell in `ArrowInvalid` text (checked: `[1, "sentinel"]` through `pa.table` shows `sentinel`). The new path converts values to Arrow at two places: the batch build (`generation/stream/_batches.py:114`) and the pass-1 typing of held columns. Both go through one helper, `to_arrow_column(values, type_, table, column)` in `generation/stream/_batches.py`, which lands in S2 with the first held column (S2 is the first head that converts held values), which catches `pa.ArrowInvalid`, `pa.ArrowTypeError` and `OverflowError` and, after the `except` block closes, raises `generation_value_type_mismatch` naming table and column only. A declared output type keeps today's path: `cast_output_values` runs first (`generation/stream/_batches.py:110-114`) and a bad value raises `OUTPUT_TYPE_CAST_FAILED` (`kinds/_output_type.py:216-235`) as on #813. `generation_value_type_mismatch` is for undeclared values whose inferred type conversion fails. V8b checks the declared cast. M11 tests the undeclared conversion in V8c.
- **One read set for the list-or-array rule.** A column that a later column of the batch reads must reach `emitted` as a Python list (pre-cast, the value siblings see). A column a child table reads is collected into its `KeyPool` with post-cast values; `array_columns` already excludes collectors (`generation/stream/_batches.py:63-69`), and that stays a separate rule. A column that is both read and collected gets both representations. On #813 `sibling_read_names` knows only the `same_batch` options, so a `derived` input, a whole-column read-set column, a `reference` parent served by the resident feed, or a provider read by a reader would be left as an Arrow array (any stream with `supports_array`: pooled Faker today, sequence, constant, distribution, categorical and reference after GEN-VECTOR-STREAMS) and missing from `emitted`. S1 makes `TableColumnPlan.batch_reads` (every same-table column some later column reads in the batch: derived inputs, `same_batch` options such as `condition_on` and `anchor`, `self_key` edges, and whole-column read sets, from `iter_generate_input_refs` plus `sibling_input`) the one set, and `array_columns` takes it instead of computing `sibling_read_names`. `sibling_read_names` is deleted; `sibling_input` stays the rule for the `same_batch` options and feeds `batch_reads`. Guard: V8 with an array-capable input (an ordinary pooled Faker column of matching Arrow type, no declared cast, not collected), V2b for the self-key and cast-key cells; mutation M9 drops the derived inputs from `batch_reads`.
- **Per-parent aggregate.** The parent's pass 1 holds its key column (and any column its children read). At the end of pass 1 the deferred parent applies the same key cast as pass 2. It calls `seal_parent_keys(...)` before any child opens a reference stream. Ordinary parents use the same helper to populate `key_pools` (`generation/_streamed.py:512-513`). Whichever S2 lands first moves the table stage into `generation/stream/_table_stage.py`. The other row uses the moved stage and its seal helper. The parent's pass 2 serves the key from held values and does not collect it again. Its pass 2 waits. Each child's pass 2 feeds `AggregateFold` (new `generation/relational/_aggregate_fold.py`): per parent key, the running `sum`, `count`, `min`, `max` (mean is sum over count at finish), updated in child row order with the same Python operators the pandas `object` reduction uses. Null `via` and null values are skipped as `dropna=True` does. At the parent's pass 2 the fold is read by key in parent row order; a parent with no children gets `0` for additive ops and `None` otherwise, as `relational/_aggregate.py:152-155` does. In V9 the parent folds an ordinary child field. The grandparent folds an ordinary parent field. Pass 2 runs child, parent, then grandparent. A direct read of a per-parent aggregate still raises `generate_aggregate_read_before_fill` (`config/_generate_relational/__init__.py:447-490`).
- **Reservations.** One helper, `held_stage_bytes(table, column_plan, ...)`, prices a table's held parts: the closure and the whole-column values (`legacy_table_bytes` over those columns), `table_unique_peak` for unique columns, the parent-column collectors, a deferred parent's sealed keys and the fold state (parent rows times op state width). `_preflight` (`_streamed.py:223`) adds it to each table's stage peak with the lifetimes below, for every table, before the run's first draw, so an over-budget stage in a later table refuses before any write. The live stage reserves the same amounts from the same helper. Lifetimes: closure and whole-column values until the table's pass 2 ends; deferred parent keys and fold state until the parent's pass 2 ends; collectors as today. #813's resident-output floor stays: with no sink, `_refuse_if_over_memory` and `generation_floor_shortfall` (`_streamed.py:274-286`, `_bounds.py:343-372`) still compare the whole output against host memory, and the held parts are added on top of it, never in place of it.
- **Choke point for "no plan-wide fallback".** `run_generation` has one path. A sentry (`tests/sentry/test_generation_single_core.py`) fails if `_generate_tables_from_config` is imported or called anywhere under `src/decoy_engine/generation/` other than `synthesize.py` itself and the pinned path, or if a function named `_run_legacy` exists. Mutation: restore the `if not admission.eligible: return _run_legacy(...)` branch (M1).
- **Choke point for "whole-column reads only declared inputs".** `ReadGuard` is the only mapping passed as `generated` by pass 1. Guard test V4. Mutation: pass the plain read-set dict (M4).
- **Principles.** Single responsibility: admission decides a column's route, the column plan decides order and read sets, the assembler draws batches, the legacy functions keep computing values. The change pain removed: one decline anywhere forcing every column into one slow loop. Open/closed for kinds: a kind that later gets a stream changes its admission row and nothing else.
- **One place per fact.** Column edges: `iter_generate_input_refs`. Route and code per column: `ColumnAdmission`. Order and read set: `TableColumnPlan`. Code summaries: `reasons.route`. Aggregate operators: `apply_derived_aggregate`'s op list, read by the fold (a test fails if the op lists differ).
- **House style.** `TableColumnPlan` is a frozen dataclass; no flag arguments; `ReadGuard` and `ResidentColumnStream` each have one job.
