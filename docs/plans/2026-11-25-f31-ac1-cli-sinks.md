## Defect class

A CLI error sink prints text built from an exception or a value: `str(exc)`, `exc.message`, an
f-string with a cell, a path or a name slot. The sink trusts its caller. The audit counted 60
direct `emit_error` calls (14 f-string messages, 25 names, 3 `.message`, 3 `str()`) and about
177 calls through nine forwarding helpers. The CLI also trusts its own exception classes by type
(`_fixed_text_types()`, `cli/run/_errors.py:126`), and 180 raises of those classes build their
text from values. A copy can also travel inside a structure before it reaches a sink: a gate
finding copies `exc.message` (`cli/extras.py:234`, `cli/gate/_layers.py:225`) into
`context.messages[]` (`cli/gate/_run.py:104`, `:133`).

## Guarantee and non-goals

Guarantee, when AC1c3 (the last slice) merges:

1. `emit_error` (`ui/output.py:217`) prints a `message` or `hint` only when it is a `SafeText`.
   Anything else (a `str`, `WITHHELD`, `None` for a message) goes to one hook,
   `record_sink_miss`.
2. The run failure path (`fail`, `refused`, `bad_parameter`, `interrupted`, `report_error`,
   `finish_error`), gate finding messages and hints in `context.messages[]`, the notify summary
   (`notify.build_run_event`, `error_summary`) and the preflight check list (`_CheckResult`)
   check their text through the same hook.
3. `record_sink_miss` never prints its argument. When `strict_checks_enabled()` is true (tests)
   it raises `SinkMissError`, a `TypeError` subclass whose `site` attribute names the sink
   boundary. Otherwise it logs one value-free warning per exception type and site, and returns
   `label_of(exc)` when an exception is given, else `SafeText.const("Operation failed.")`.
   For an owned CLI exception, `label_of(exc)` calls the classmethod `safe_label()` of a CLI exception class, whose body is
   `return SafeText.const("<ClassName>")`, and `safe_error_label(exc)` for any other exception.
   The label is built on call, never at class definition, because startup imports
   `_config_file` (`ConfigFileError`) through `cli/validate.py:49` and a class-level const would
   load the engine. The fresh-process startup case (AT-12) runs from AC1a1, the first head that
   adds a label.
4. Text stays a `SafeText` until the one renderer at the sink turns it into a `str`. The
   existing run cap and the human-only `capacity:` prefix apply at their original boundaries. Optional hints
   and summaries use `is not None` before checking. Absence omits the field and emits no warning.
5. Exit codes, reason codes, `decoy-error-v1` keys and the human line layout do not change. Approved wording
   changes appear in Behavior changes. Existing names, locations, install remedies and useful structure
   survive wherever their provenance is established.
6. CLI exception classes that the run path trusts carry `SafeText` in their message field. Trust
   by class goes. Constructor signatures keep their argument order and structured arguments.
7. A name or path slot shows text only when it was minted from an identified config field in its
   original spelling. A data value cannot reach a mint.

Non-goals: other structured envelope members beyond the specified gate messages (AC4 canary covers them); warnings
(`add_cli_warning`, `run/_context.py:242`); Click and Typer usage errors that Click formats
itself; `print_exception` under `--verbose` (audit decision 1); log handlers (AC2); the copy
ratchet of CLI terminal copies (AC3); the canary walk over every command (AC4).

## Established solutions

Search run: OWASP Error Handling Cheat Sheet (generic message to the user, detail only to a
protected log), CWE-209 (error message with sensitive information), Google `safehtml` (a sink
accepts only a typed value that a small set of builders can make; plain strings fail at the
sink), RFC 9457 (a stable type and a short title instead of free text), and the CLI's own
choke-point sentries (`tests/sentry/cli_text/test_one_error_emitter.py`, the shrink-only ratchet
in `tests/sentry/_ratchet.py`). The design copies `safehtml`: the type is the proof, the sink
checks the type at runtime, and a static sentry is only a backstop. Nothing new is invented.

## Choke point

One module below both `ui` and `notify`: `src/decoy/_safe_messages.py`. It holds
`checked(value, *, exc=None, site)`, `record_sink_miss`, `SinkMissError`, `render(parts, *,
cap)`, `message_of(exc)` and `label_of(exc)`. `checked` is the only runtime check (`isinstance(value, SafeText)`)
and each output boundary passes its text through it before rendering:

- `emit_error` for `message` and `hint` (`ui/output.py:217`);
- `_result.report_error` and `finish_error` (`cli/run/_result.py:394`, `:443`);
- gate `_message` for `message` and `hint` (`cli/gate/_run.py:133`), and the gate's other
  consumers of `GateFinding.message`: the run refusal summary (`cli/gate/_run.py:106` to `:108`,
  whose bounded typed input uses the shared cap) and `decoy validate`
  (`cli/validate.py:363`, `:393`) and `validate config` (`:187–249`, including its top-level `error`, optional hint and warnings);
- `notify.build_run_event` for `error_summary` (`notify.py:174`);
- `_CheckResult` construction (`cli/preflight.py:118`), so `add_pass`, `add_warn` and `add_fail`
  (`:149` to `:168`) share one boundary.

`notify` and `ui` are independent siblings in `.importlinter:21` to `:33`, so the module sits in
the shared lower layer. Place the shared text module below its lowest caller, including
config/atomic/diagnostic producers. It cannot import those callers to recognize their exception types.
Define the common typed CLI exception interface there and implement it on the owning classes. Dispatch only
through that interface or the public engine API. The slice adds it to the exhaustive layer map and its
snapshot and runs import-linter with no new exception. The engine import inside `_safe_messages.py` is lazy (on
the first `checked` call), so importing `decoy.__main__` still leaves the engine unloaded
(`tests/e2e/library/test_library_fsck.py:142` to `:154`).

Keep the legacy exception constructor's string in `args` for compatibility, separately from the checked
field. A plain legacy value cannot acquire SafeText status through the migration pass-through. Its temporary
type is explicitly str | SafeText (including the renderer input), narrowed at AC1c3. Check SafeText first
and pass through only an exact plain str; WITHHELD and unrelated objects always miss. Migrated exception
constructors require typed input immediately, independent of that temporary output compatibility. Before
`report_error` calls `_write_file` (line 416), check text, present hint and any `HumanLine` override. Keep
fields typed through `finish_error → report_error → emit_error`, including the JSON-plus-stderr
evidence-write branch. Model the capacity prefix as presentation of the checked message on stderr. Rendering
to str and feeding it back into emit_error fails the final contract. A result document is built from
category, reason and error class (`_result.py:196`), independently of the displayed text.

The boundary tests catch an omitted check even when an outer or inner boundary also checks. The provenance
guard catches an unsafe caller even when a release build would substitute a safe fallback.

Guard: `tests/sentry/cli_text/test_safe_text_sinks.py`. It seeds the concrete boundaries above and binds
their real signatures, including `text`, `error_summary`, optional hints, `HumanLine.text`, `GateFinding`
and `_CheckResult` fields. Discover forwarders by AST: a forwarder is any function that passes one of its
own parameters into any protected argument of a sink or of another forwarder (fixpoint over the CLI tree).
It checks the provenance of each protected argument, positional or named. An argument is accepted only
when it is a call to a typed producer (`SafeText.const`, `SafeText.literal_template`,
`render_failure`, `message_of`, `label_of`, a checked
typed template producer with minted slots (a name/path mint by itself is only a slot), or a registry
accessor that returns `SafeText`), a parameter of a forwarder (its
callers are then checked), or a local name whose every assignment in the function is one of
these. Bind positional, keyword-only, renamed and nested helper parameters to their slots. Resolve
same-module and nested definitions by lexical scope as well as imports. Check a typed record field through
its constructor and every supported assignment, and check unpacked tuple results at their producing return
branches. Narrow optional or sentinel-returning accessors such as safe_reason_summary and safe_text_of
before accepting their result. Accept literal None only for optional slots. For
`finish_error(..., **kwargs)` forwarding to report_error, bind the caller’s actual hint and human_line
keywords to the target signature. A kwargs pass-through is not a mapping producer that can be accepted on
its own. Seed bound and unbound accumulator methods, a raw hint forwarded via kwargs, a bad alternate
assignment, and a same-named unrelated function. Check literal constructors take AST string literals,
including inside allowlisted producers. Anything else is flagged, so unknown provenance counts against the
baseline: a literal,
an f-string, `str()`, `.message`, `%`, `+`, `.format()`, a module-level string constant
(`cli/fit.py:423`), and a local assigned from any of these (`msg = f"..."` then
`emit_error(..., msg)`, `cli/reference.py:279` to `:280`). Its self-test seeds each shape,
including those two real ones, an aliased import and a new forwarder in a scratch module, and
asserts each is seen. It reuses the call resolver in `tests/sentry/io_policy/_calls.py` for
imports and aliases. `render` is not a producer: it returns `str` and is called only inside a
sink, after `checked`. A `**mapping` argument to a sink or forwarder is resolved to the function
that builds the mapping (`config_refusal`, `_config_file.py:269` to `:275`, used at
`cli/validate.py:167`, `:316` and `cli/tokenize.py:192`, `:539`); its `message` and `hint`
values are checked once there by the same provenance rule, and a `**` argument the scanner
cannot resolve is flagged. The self-test seeds a raw `message` in such a producer and an
unresolved `**` argument. Keep stable file, qualified function, slot and occurrence counts so replacing one
diagnosed site with two cannot pass. Zero means zero diagnostics for covered shapes. Runtime tests prove
actual handoffs.

## Ordering: migrate first, then reject

The runtime check cannot reject plain strings while plain-string callers remain. So:

1. AC1a1 builds the choke point. `checked` accepts `SafeText`, sends `WITHHELD` and `None` to
   the hook, and passes a plain `str` through unchanged. The guard's shrink-only baseline counts
   every remaining sink argument without a typed producer. AC1a1 migrates the generic run failure path and
   notify summary. For not-yet-converted special branches retain their current classifier and existing text,
   tracked by the ratchet. Never insert a legacy string into a typed slot. Flip each producer and its
   consumers together. If a legacy gate finding still feeds the summary, keep the existing bounded string
   assembly for that input only until its producing slice lands. Remove this branch at AC1d. AC1a2 migrates
   gate findings: the shared translator and every
   consumer of `GateFinding.message`. Their canary tests are green in those slices.
   In particular, PreRunCheckError accepts the transitional union through AC1d. In AC1a2 preserve
   a typed summary as its own field and set string args for existing callers. The run arm forwards
   the field directly. For a remaining raw first finding, the old summary stays explicitly legacy
   and counted. Make the constructor typed-only when the last such producer migrates in AC1d.
   AT-6 runs its strict constructor case on that head. This bridge never promotes a string to SafeText.
2. AC1b1, AC1b2, AC1c1 and AC1c2 migrate the remaining producers. Each slice lowers the
   baseline. AC1a1 inventories future sink slots and constructors too, so enabling a boundary later cannot
   require raising the baseline.
3. AC1d migrates preflight: the 34 checks, the preflight strings the gate copies into findings
   (`cli/preflight.py:231` to `:234` into `cli/gate/_layers.py:137`), and the gate's rewrites of
   check messages after `_CheckResult` construction (`_layers.py:428`, `:438`). It wires the path
   mint into the production preflight path.
4. AC1c3, last, removes the `str` pass-through for every sink, `_CheckResult` included. On that
   head the baseline is zero and is deleted, the strict rejection of AT-1 turns on, and the full
   CLI suite passes. No live producer still hands a plain string to a sink when it flips.

## Design notes

1. AC0 must verify the runtime literal contract on the supported Python versions. The CLI literal sentry
   also checks syntax at the call site. So a fixed message is written at
   the call: `emit_error(state, "setup", SafeText.const("setup needs a terminal; pass --yes to
   accept."))`. A module constant or a helper parameter fails the check. Forwarding helpers take
   a `SafeText` and pass it on; they never build one from a parameter. A CLI registry that owns
   text (mask-secret remedies) stores each entry as a `SafeText.const` written where the entry is
   defined, inside a function cached on first call, never at module scope. Text owned by an
   engine registry (blocked-run reason summaries) is typed by the engine
   (`safe_reason_summary`); the CLI does not copy it.
2. Keep classification independent of display. `_failure_reason` still reads the original engine exception
   once for the document, including translated ImportError/NER cases. Drop its `str(exc) == spec.summary`
   test and `fixed_text` field as their last users migrate. Use the engine renderer for coded errors, coded
   causes and unknowns. In AC1a1 `bad_parameter` passes an approved fixed summary to the result path and
   preserves the caller’s re-raise to Click. `interrupted` passes a literal. Neither path adds an extra
   terminal line. `refused` carries the typed RunRefusal.text once its constructor migrates. RunRefusal
   subtypes with structured inputs keep those inputs. The top-level engine flag report
   (`__main__.py:137–147,185`) also supplies checked text to emit_error in AC1c2. Test the live invalid-flag
   route and its exit, retaining lazy startup. For owned CLI exceptions, retrieve the checked field. Never
   accept raw `.args`, `.message` or arbitrary duck-typed methods as proof. Type only message arguments.
   Preserve the positional/keyword-only parameters, text prefix, metadata and string-valued `args` of each
   real constructor. Keep string views required by existing non-sink callers as projections of the same
   typed source. `ConfigProblem.text` preserves position, count and hints. For language diagnostics, build
   typed text at the existing `lang/_codes.py` and `lang/_errors.py` owner via the public engine API. Do not
   add a reverse import from lang into the CLI. For shared layout descriptors
   (`cli/io/_layout_errors.py:36–49`) keep warning and plain-string consumers working from the same
   definition. Lazy literal factories at individual entries avoid passing a dynamic descriptor template to a
   literal check.
3. The config loader is the only issuer of config-origin evidence. On the same parse that creates
   `PipelineFile`, retain immutable original plain-string fields at declared structural positions, keyed by
   path components and role (e.g. a source table key versus its file path). Skip malformed/non-string fields
   without coercion. A credential, option scalar, row value or sample can never be selected just because it
   has identifier syntax. Define the token in the low-level mint module so the loader can issue it without a
   back import. The two mint entry points require the exact token and matching role. Neither looks up a name
   or path by searching for equal text elsewhere. Register those functions lazily at first use. Keep the
   engine registrar target and place `# pragma: no mutate block` on each registered function definition, as
   required by the proposed pin. AT-4 seeds a direct token construction outside the loader, wrong-role use,
   and direct engine mint outside the registrar; the source guard must flag the unauthorized sites. Test
   actual rejection of a plain string/Path and demonstrate that reading a row or arbitrary config scalar
   cannot issue a token.

   Pass this evidence beside the plain config mapping through run’s existing single-read path
   (`run/_prepare.py:61–75`), aggregate validate (`gate/_layers.py:110–127`) and standalone preflight
   (`preflight.py:656`). Retain the loader's unreviewed-mark refusal for standalone preflight. Existing
   mapping-only callers stay supported. For transformed, injected or programmatic source entries use the
   matching original declaration only while the current role and spelling still agree. Otherwise select the
   fixed no-name/no-path form. Never re-open the file, wrap the engine's dict values, or reconstruct a token
   from a display string. Keep filesystem checks on the existing resolved Path. Test
   missing/readable/nonregular/unreadable branches, credential URLs and normalized-looking relative paths. A
   syntactically valid local name containing spaces, a leading dot/underscore or Unicode still participates
   in normal file processing.
4. Preserve the gate facade's existing string cap API (`cli/gate/_run.py:42`). For typed composition and
   rendering use the same clipping rule from a single owner. If AC0 provides typed clipping, have its public
   bounded-text operation and legacy string projection share that implementation. Keep its single CLI limit
   at 500. Never use a raw string cap as a typed producer. Take 500 characters, then append `...` only on
   overflow. Run bounds the first finding inside its summary, the applicable full run error, and each run
   JSON finding message. Aggregate/config validate findings, general emit_error messages and hints have no
   new cap. Prefix the already bounded text with `capacity: ` only in the human override. Use typed
   composition for summaries and intermediate joins; display strings go only to Rich, JSON, transports or
   the backwards-compatible exception/descriptor string view.
5. AC1a2 migrates **all readers** of the affected gate and compile text on that head. Both validate builders
   render checked message/hint fields through shared gate code, retaining their different envelope keys and
   cap choices. `compile_explain.py:190,345–369` covers shared-destination joins and both
   arbitrary-exception fallback arms. Keep its existing JSON keys and human-only hint. `unmask.py:243–244`
   composes typed text, and `subset.py:231–232` forwards it. `gen/_scaffold.py:164,270–277` must carry typed
   findings through ScaffoldInvalid, the bounded list and final join. Preserve the opt-in filter, location
   and cleanup. CI's adapter continues projecting rule IDs and safe facts. It must never start copying gate
   display text into CI reports.
6. Migrate gate producers by origin. AC1a2 handles compile translation and its readers. AC1b1 handles loader
   and layout diagnostics, AC1c1 handles remaining direct gate producers, and AC1d handles preflight-derived
   findings, including config-layer target-overwrite advisories. When a nested finding or record changes
   type, migrate each reader on that head, even if its command group normally comes later. In particular
   move preflight’s config_refusal extraction at :657 onto AC1b1 when ConfigProblem changes. Use explicit
   message/code fields. Its existing str(message) would silently undo the migration. This includes loader
   and schema problems (`gate/_layers.py:106,158`), target/layout issues, compile errors and hints, the
   SubsetError copy at 351, plan warning strings at 367, model availability (`gate/_models.py:35`) and
   preflight. Retain severity, code, order and location. Use owned typed diagnostics where available, or a
   fixed actionable message for unstructured warning prose. Never wrap an engine-provided string in const.
   For preflight, render the generic check list, both capacity/native JSON projections and each human
   renderer from the checked record. Replace both post-construction assignments at `_layers.py:428,438` with
   construction of a checked replacement. Build the chunked note from the same typed capacity detail that
   the plain route prefixes with `INSUFFICIENT -- `; no string prefix stripping or second estimate.
   Distinguish advisory, insufficient, unsupported and failed estimates using structured verdict, code and
   quantities. Keep the two routes’ severity, `capacity_insufficient` and exit precedence.
7. The mask-secret registry includes the keyed remedy parameter as well as the code-indexed entries. Build
   the known RUN, UNMASK, TOKENIZE, REPORT_VAULT and API text lazily from their single definitions. Move
   `api.py:636,639` (including direct dictionary indexing), reports/_vault, unmask, tokenize, and run
   together. Keep public exception args and ordinary help/scaffold strings as strings. For a missing extra
   retain both the typed unprefixed install message and the prefixed exception view from that one message.
   The gate uses the unprefixed field, without slicing a rendered string. `_plan_error_fields` at
   `gate/_layers.py:85` and `plan_compile_error_fields` at `cli/extras.py:217` must translate once; return
   the optional extra from the shared result. Migrate MissingExtraError construction (including
   require_extra), its prefixed CLI view and all callers on AC1a2. Update all unpackers on that head.
8. AC1c3 removes the transitional pass-through and legacy summary handling. Re-run strict cases with plain
   strings, including empty strings, and release fallback cases with a distinct value in the rejected
   argument and exception message. Check warning records and their arguments carry neither value;
   deduplicate by type and site. Ensure a valid success notification with no summary and an error without a
   hint never enter the hook.
