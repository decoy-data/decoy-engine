## Defect class

A CLI error sink prints text built from an exception or a value: `str(exc)`, `exc.message`, an
f-string with a cell, a path or a name slot. The sink trusts its caller. The audit counted 60
direct `emit_error` calls (14 f-string messages, 25 names, 3 `.message`, 3 `str()`) and about
177 calls through nine forwarding helpers. The CLI also trusts its own exception classes by type
(`_fixed_text_types()`, `cli/run/_errors.py:126`), and 180 raises of those classes build their
text from values. A copy can also travel inside a structure before it reaches a sink: a gate
finding copies `exc.message` (`cli/extras.py:234`, `cli/gate/_layers.py:225`) into
`context.messages[]` (`cli/gate/_run.py:104`, `:133`).

## Guarantee and non-goals

Guarantee, when AC1d merges:

1. `emit_error` (`ui/output.py:217`) prints a `message` or `hint` only when it is a `SafeText`.
   Anything else (a `str`, `WITHHELD`, `None` for a message) goes to one hook,
   `record_sink_miss`.
2. The run failure path (`fail`, `refused`, `bad_parameter`, `interrupted`, `report_error`,
   `finish_error`), gate finding messages and hints in `context.messages[]`, the notify summary
   (`notify.build_run_event`, `error_summary`) and the preflight check list (`_CheckResult`)
   check their text through the same hook.
3. `record_sink_miss` never prints its argument. When `strict_checks_enabled()` is true (tests)
   it raises `SinkMissError`, a `TypeError` subclass naming the call site. Otherwise it logs one
   value-free warning per exception type and site, and returns `safe_error_type(exc)` when an
   exception is given, else `SafeText.const("Operation failed.")`.
4. Text stays a `SafeText` until the one renderer at the sink turns it into a `str`. The
   500-character cap and the `capacity:` prefix apply in that renderer, after the check.
5. Exit codes, reason codes, `decoy-error-v1` keys and the human line layout do not change. Only
   the text of messages that copied values changes.
6. CLI exception classes that the run path trusts carry `SafeText` in their message field. Trust
   by class goes. Constructor signatures keep their argument order.
7. A name or path slot shows text only when it was minted from an identified config field in its
   original spelling. A data value cannot reach a mint.

Non-goals: `context` members other than gate `messages[]` (AC4 canary covers them); warnings
(`add_cli_warning`, `run/_context.py:242`); Click and Typer usage errors that Click formats
itself; `print_exception` under `--verbose` (audit decision 1); log handlers (AC2); the copy
ratchet of CLI terminal copies (AC3); the canary walk over every command (AC4).

## Established solutions

Search run: OWASP Error Handling Cheat Sheet (generic message to the user, detail only to a
protected log), CWE-209 (error message with sensitive information), Google `safehtml` (a sink
accepts only a typed value that a small set of builders can make; plain strings fail at the
sink), RFC 9457 (a stable type and a short title instead of free text), and the CLI's own
choke-point sentries (`tests/sentry/cli_text/test_one_error_emitter.py`, the shrink-only ratchet
in `tests/sentry/_ratchet.py`). The design copies `safehtml`: the type is the proof, the sink
checks the type at runtime, and a static sentry is only a backstop. Nothing new is invented.

## Choke point

One module below both `ui` and `notify`: `src/decoy/_safe_messages.py`. It holds
`checked(value, *, exc=None, site)`, `record_sink_miss`, `SinkMissError`, `render(parts, *,
cap)` and `message_of(exc)`. `checked` is the only runtime check (`isinstance(value, SafeText)`)
and every sink calls it:

- `emit_error` for `message` and `hint` (`ui/output.py:217`);
- `_result.report_error` and `finish_error` (`cli/run/_result.py:394`, `:443`);
- gate `_message` for `message` and `hint` (`cli/gate/_run.py:133`);
- `notify.build_run_event` for `error_summary` (`notify.py:174`);
- `_CheckResult` construction (`cli/preflight.py:118`), so `add_pass`, `add_warn` and `add_fail`
  (`:149` to `:168`) share one boundary.

`notify` and `ui` are independent siblings in `.importlinter:21` to `:33`, so the module sits in
the shared lower layer. The slice adds it to the exhaustive layer map and its snapshot and runs
import-linter with no new exception. The engine import inside `_safe_messages.py` is lazy (on
the first `checked` call), so importing `decoy.__main__` still leaves the engine unloaded
(`tests/e2e/library/test_library_fsck.py:142` to `:154`).

There is no per-site rule. A sink that skips `checked` is caught twice: at runtime by the per-sink
tests of AT-5b, and statically by the guard.

Guard: `tests/sentry/cli_text/test_safe_text_sinks.py`. It finds sinks and forwarders by AST,
not by a list: a forwarder is any function that passes one of its own parameters as the
`message` or `hint` of a sink or of another forwarder (fixpoint over the CLI tree). It flags
any sink or forwarder call whose message argument is a string literal, an f-string, a `str()`
call, a `.message` attribute, a `%` or `+` of strings, or a `.format()` call. Its self-test
seeds each shape and a new forwarder in a scratch module and asserts each is seen. It reuses the
call resolver in `tests/sentry/io_policy/_calls.py` for imports and aliases.

## Ordering: migrate first, then reject

The runtime check cannot reject plain strings while plain-string callers remain. So:

1. AC1a builds the choke point. `checked` accepts `SafeText`, sends `WITHHELD` and `None` to the
   hook, and passes a plain `str` through unchanged. The guard's shrink-only baseline counts every
   remaining plain-string call. The run failure path, gate findings and notify summary are
   migrated in AC1a, so their canary tests are green in AC1a.
2. AC1b and AC1c migrate the remaining producers. Each slice lowers the baseline.
3. AC1c3 removes the `str` pass-through. On that head the baseline is zero and is deleted, the
   strict rejection of AT-1 turns on, and the full CLI suite passes.
4. AC1d migrates preflight and turns on rejection at `_CheckResult` in the same slice.

## Design notes

1. Literal checks are runtime `co_consts` checks in the caller. So a fixed message is written at
   the call: `emit_error(state, "setup", SafeText.const("setup needs a terminal; pass --yes to
   accept."))`. A module constant or a helper parameter fails the check. Forwarding helpers take
   a `SafeText` and pass it on; they never build one from a parameter. A registry that owns text
   (blocked-run summaries, mask-secret remedies) stores each entry as a `SafeText.const` written
   where the entry is defined.
2. `message_of(exc)` returns `safe_text_of(exc)` for an engine exception and the `SafeText` a CLI
   exception stored. CLI exception classes keep their names, constructor argument order and
   `str(exc)` behavior: the message parameter, wherever it sits, is typed `SafeText`, stored,
   and passed as `str(text)` to `args`, as the engine's `DecoyError` does (audit rev 2.1 item
   7). `ConfigFileError` keeps `code` first and its `problems` list.
3. `src/decoy/_safe_mints.py` is the registrar and the only module that calls `SafeName` and
   `SafePath` mints. Its functions take a `ConfigField` (the field key and its original text,
   built only by the config loader in `_config_file.py`), never `str` or `Path`. It calls
   `register_mint_callers` once, on the first mint call, behind a module flag; nothing imports
   it at startup. The engine's `_CLI_REGISTRAR` names this module (AC0 open item 1). Each listed
   function carries `# pragma: no mutate block` on its def line (audit rev 2.1).
4. `render(parts, *, cap)` joins a sequence of checked `SafeText` parts and applies the cap. The
   capacity line passes `(SafeText.const("capacity: "), text)`; `cap_error_text` keeps its rule
   but runs only inside `render`. No code turns a `SafeText` into a `str` before the sink.
5. Until AC1c3, `checked` passes a plain `str` through; the static baseline counts every
   remaining plain-string call and may only shrink. AC1c3 deletes the baseline file and the
   `str` branch.
