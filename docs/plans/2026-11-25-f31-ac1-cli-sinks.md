## Defect class

A CLI error sink prints text built from an exception or a value: `str(exc)`, `exc.message`, an
f-string with a cell, a path or a name slot. The sink trusts its caller. The audit counted 60
direct `emit_error` calls (14 f-string messages, 25 names, 3 `.message`, 3 `str()`) and about
177 calls through nine forwarding helpers. The CLI also trusts its own exception classes by type
(`_fixed_text_types()`, `cli/run/_errors.py:126`), and 180 raises of those classes build their
text from values. A copy can also travel inside a structure before it reaches a sink: a gate
finding copies `exc.message` (`cli/extras.py:234`, `cli/gate/_layers.py:225`) into
`context.messages[]` (`cli/gate/_run.py:104`, `:133`).

## Guarantee and non-goals

Guarantee, when AC1c3 (the last slice) merges:

1. `emit_error` (`ui/output.py:217`) prints a `message` or `hint` only when it is a `SafeText`.
   Anything else (a `str`, `WITHHELD`, `None` for a message) goes to one hook,
   `record_sink_miss`.
2. The run failure path (`fail`, `refused`, `bad_parameter`, `interrupted`, `report_error`,
   `finish_error`), gate finding messages and hints in `context.messages[]`, the notify summary
   (`notify.build_run_event`, `error_summary`) and the preflight check list (`_CheckResult`)
   check their text through the same hook.
3. `record_sink_miss` never prints its argument. When `strict_checks_enabled()` is true (tests)
   it raises `SinkMissError`, a `TypeError` subclass whose `site` attribute names the sink
   boundary. Otherwise it logs one value-free warning per exception type and site, and returns
   `label_of(exc)` when an exception is given, else `SafeText.const("Operation failed.")`.
   `label_of(exc)` calls the classmethod `safe_label()` of a CLI exception class, whose body is
   `return SafeText.const("<ClassName>")`, and `safe_error_label(exc)` for any other exception.
   The label is built on call, never at class definition, because startup imports
   `_config_file` (`ConfigFileError`) through `cli/validate.py:49` and a class-level const would
   load the engine. The fresh-process startup case (AT-12) runs from AC1a1, the first head that
   adds a label.
4. Text stays a `SafeText` until the one renderer at the sink turns it into a `str`. The
   500-character cap and the `capacity:` prefix apply in that renderer, after the check.
5. Exit codes, reason codes, `decoy-error-v1` keys and the human line layout do not change. Only
   the text of messages that copied values changes.
6. CLI exception classes that the run path trusts carry `SafeText` in their message field. Trust
   by class goes. Constructor signatures keep their argument order.
7. A name or path slot shows text only when it was minted from an identified config field in its
   original spelling. A data value cannot reach a mint.

Non-goals: `context` members other than gate `messages[]` (AC4 canary covers them); warnings
(`add_cli_warning`, `run/_context.py:242`); Click and Typer usage errors that Click formats
itself; `print_exception` under `--verbose` (audit decision 1); log handlers (AC2); the copy
ratchet of CLI terminal copies (AC3); the canary walk over every command (AC4).

## Established solutions

Search run: OWASP Error Handling Cheat Sheet (generic message to the user, detail only to a
protected log), CWE-209 (error message with sensitive information), Google `safehtml` (a sink
accepts only a typed value that a small set of builders can make; plain strings fail at the
sink), RFC 9457 (a stable type and a short title instead of free text), and the CLI's own
choke-point sentries (`tests/sentry/cli_text/test_one_error_emitter.py`, the shrink-only ratchet
in `tests/sentry/_ratchet.py`). The design copies `safehtml`: the type is the proof, the sink
checks the type at runtime, and a static sentry is only a backstop. Nothing new is invented.

## Choke point

One module below both `ui` and `notify`: `src/decoy/_safe_messages.py`. It holds
`checked(value, *, exc=None, site)`, `record_sink_miss`, `SinkMissError`, `render(parts, *,
cap)`, `message_of(exc)` and `label_of(exc)`. `checked` is the only runtime check (`isinstance(value, SafeText)`)
and every sink calls it:

- `emit_error` for `message` and `hint` (`ui/output.py:217`);
- `_result.report_error` and `finish_error` (`cli/run/_result.py:394`, `:443`);
- gate `_message` for `message` and `hint` (`cli/gate/_run.py:133`), and the gate's other
  consumers of `GateFinding.message`: the run refusal summary (`cli/gate/_run.py:106` to `:108`,
  which caps with `len` and slicing today and moves to `render`) and `decoy validate`
  (`cli/validate.py:363` for JSON, `:393` for the human line, which concatenates a string);
- `notify.build_run_event` for `error_summary` (`notify.py:174`);
- `_CheckResult` construction (`cli/preflight.py:118`), so `add_pass`, `add_warn` and `add_fail`
  (`:149` to `:168`) share one boundary.

`notify` and `ui` are independent siblings in `.importlinter:21` to `:33`, so the module sits in
the shared lower layer. The slice adds it to the exhaustive layer map and its snapshot and runs
import-linter with no new exception. The engine import inside `_safe_messages.py` is lazy (on
the first `checked` call), so importing `decoy.__main__` still leaves the engine unloaded
(`tests/e2e/library/test_library_fsck.py:142` to `:154`).

There is no per-site rule. A sink that skips `checked` is caught twice: at runtime by the per-sink
tests of AT-5b, and statically by the guard.

Guard: `tests/sentry/cli_text/test_safe_text_sinks.py`. It finds sinks and forwarders by AST,
not by a list: a forwarder is any function that passes one of its own parameters as the
`message` or `hint` of a sink or of another forwarder (fixpoint over the CLI tree). It checks
the provenance of the argument in both slots, positional or named. An argument is accepted only
when it is a call to a typed producer (`SafeText.const`, `SafeText.literal_template`,
`render_failure`, `safe_text_of`, `message_of`, `label_of`, a `_safe_mints`
function, or a registry accessor that returns `SafeText`), a parameter of a forwarder (its
callers are then checked), or a local name whose every assignment in the function is one of
these. Anything else is flagged, so unknown provenance counts against the baseline: a literal,
an f-string, `str()`, `.message`, `%`, `+`, `.format()`, a module-level string constant
(`cli/fit.py:423`), and a local assigned from any of these (`msg = f"..."` then
`emit_error(..., msg)`, `cli/reference.py:279` to `:280`). Its self-test seeds each shape,
including those two real ones, an aliased import and a new forwarder in a scratch module, and
asserts each is seen. It reuses the call resolver in `tests/sentry/io_policy/_calls.py` for
imports and aliases. `render` is not a producer: it returns `str` and is called only inside a
sink, after `checked`. A `**mapping` argument to a sink or forwarder is resolved to the function
that builds the mapping (`config_refusal`, `_config_file.py:269` to `:275`, used at
`cli/validate.py:167`, `:316` and `cli/tokenize.py:192`, `:539`); its `message` and `hint`
values are checked once there by the same provenance rule, and a `**` argument the scanner
cannot resolve is flagged. The self-test seeds a raw `message` in such a producer and an
unresolved `**` argument. Because unknown provenance is flagged, a zero baseline means every sink
argument has a typed producer, which is what the flip needs.

## Ordering: migrate first, then reject

The runtime check cannot reject plain strings while plain-string callers remain. So:

1. AC1a1 builds the choke point. `checked` accepts `SafeText`, sends `WITHHELD` and `None` to
   the hook, and passes a plain `str` through unchanged. The guard's shrink-only baseline counts
   every remaining sink argument without a typed producer. The run failure path and the notify
   summary are migrated in AC1a1. AC1a2 migrates gate findings: the shared translator and every
   consumer of `GateFinding.message`. Their canary tests are green in those slices.
2. AC1b1, AC1b2, AC1c1 and AC1c2 migrate the remaining producers. Each slice lowers the
   baseline.
3. AC1d migrates preflight: the 34 checks, the preflight strings the gate copies into findings
   (`cli/preflight.py:231` to `:234` into `cli/gate/_layers.py:137`), and the gate's rewrites of
   check messages after `_CheckResult` construction (`_layers.py:428`, `:438`). It wires the path
   mint into the production preflight path.
4. AC1c3, last, removes the `str` pass-through for every sink, `_CheckResult` included. On that
   head the baseline is zero and is deleted, the strict rejection of AT-1 turns on, and the full
   CLI suite passes. No live producer still hands a plain string to a sink when it flips.

## Behavior changes

1. A message that quoted `str(exc)` of an engine error now shows `render_failure(exc)`: the
   registry summary and refs for a coded error, the declared `SafeText` for an uncoded error that
   carries one, the type label otherwise.
2. A message that quoted a CLI exception's text now shows the `SafeText` the raise built.
3. Path and name slots keep their text when minted from a config field in its original spelling,
   and show `<withheld>` when the mint refuses (for example a URL with credentials).
4. A gate finding built from a `PlanCompileError` shows the rendered text in `run` and
   `validate`, human and JSON; its code, location and the missing-extra translation are
   unchanged.
5. `fail()` special cases (`cli/run/_errors.py:144` to `:169`), from the audit table, corrected:

   | Case | Producer of the `SafeText` | Text |
   |---|---|---|
   | out of memory | `SafeText.const` at the `fail` branch | kept |
   | coded capacity refusal | `render_failure(exc)`; the code is in the summary | registry summary |
   | `AtomicWriteError` | `describe` (`_atomic.py:201`) returns `SafeText`: the code as a const per branch plus the optional OS reason from `errno` names; no path slot, because the class has none | kept |
   | `LayoutError` | its factories build the `SafeText` message; `message_of(exc)` reads it | kept where it held no value |
   | `PostScanBlockedError` | the engine renders the registered summary: `safe_reason_summary(namespace, code)` at `cli/io/_integrity_report.py:224`; an unknown reason uses a local `SafeText.const` fallback; no registry entries are copied into the CLI | kept |
   | mask-secret errors | `secret_error_text` and `SECRET_REMEDIES` (`_mask_secret_guidance.py:124` to `:133`) hold `SafeText` entries, built lazily on first use by a cached function, because `__main__.py:29` imports `cli/init.py`, which imports this module at line 28, and a module-scope `SafeText.const` would load the engine at startup; a known code gets its registered remedy; an unknown code gets one fixed `SafeText.const` message with no code in it, because the code's spelling (checked at `:126` to `:133`) does not prove where it came from and a mint takes only a loader-made `ConfigField` | kept for known codes; fixed text for unknown |
   | CLI refusal or config file error | `message_of(exc)`; type label if absent | kept where it held no value |
   | any other exception | `render_failure(exc)`; 500-character cap in `render` | registry summary or type label |

6. An absent notify summary stays absent: `error_summary=None` adds nothing to `detail`. A
   present summary is `label_of(exc)` (`cli/run/_errors.py:270` sends `type(exc).__name__`
   today). The text is the same for builtins, engine types in the closed set and CLI classes.
   A third-party class outside the closed set now shows its closed label (for example
   `Exception`) instead of its own name.
7. A plain string at a sink after AC1c3, in a release build, prints the type label or
   "Operation failed." and logs one warning line with the type name and site.

| Failure | Detected by |
|---|---|
| A new command prints `str(exc)` through a new wrapper | runtime check (strict raises in its tests); AT-5a forwarder fixpoint |
| A sink added later skips `checked` | AT-5b covers each boundary by name; a new `err_console.print` with `error(...)` is already a site of `test_one_error_emitter.py` |

| A registry of typed text loads the engine at startup | registries are built lazily; AT-4 fresh-process case on AC1b2 |

## Design notes

1. Literal checks are runtime `co_consts` checks in the caller. So a fixed message is written at
   the call: `emit_error(state, "setup", SafeText.const("setup needs a terminal; pass --yes to
   accept."))`. A module constant or a helper parameter fails the check. Forwarding helpers take
   a `SafeText` and pass it on; they never build one from a parameter. A CLI registry that owns
   text (mask-secret remedies) stores each entry as a `SafeText.const` written where the entry is
   defined, inside a function cached on first call, never at module scope. Text owned by an
   engine registry (blocked-run reason summaries) is typed by the engine
   (`safe_reason_summary`); the CLI does not copy it.
2. `message_of(exc)` returns `safe_text_of(exc)` for an engine exception and the `SafeText` a CLI
   exception stored. CLI exception classes keep their names, constructor argument order and
   `str(exc)` behavior: the message parameter, wherever it sits, is typed `SafeText`, stored,
   and passed as `str(text)` to `args`, as the engine's `DecoyError` does (audit rev 2.1 item
   7). `ConfigFileError` keeps `code` first and its `problems` list.
3. `src/decoy/_safe_mints.py` is the registrar and the only module that calls `SafeName` and
   `SafePath` mints. Its functions take a `ConfigField` (the field key and its original text,
   built only by the config loader in `_config_file.py`), never `str` or `Path`. It calls
   `register_mint_callers` once, on the first mint call, behind a module flag; nothing imports
   it at startup. The engine's `_CLI_REGISTRAR` names this module (AC0 open item 1). Each listed
   function carries `# pragma: no mutate block` on its def line (audit rev 2.1).
4. `render(parts, *, cap)` joins a sequence of checked `SafeText` parts, applies the cap and
   returns `str`. It runs only inside a sink, after `checked`, at final serialization. The
   capacity line passes `(SafeText.const("capacity: "), text)`; `cap_error_text` keeps its rule
   but runs only inside `render`. Text composed before a sink stays typed: the gate refusal
   summary (`cli/gate/_run.py:106` to `:108`) is a `SafeText.literal_template` with the first
   finding's `SafeText` in a slot, so it reaches the next sink through `PreRunCheckError` still
   typed, and the 500-character cap applies when that sink renders it. No code turns a
   `SafeText` into a `str` before the sink.
5. Until AC1c3, `checked` passes a plain `str` through; the static baseline counts every
   remaining plain-string call and may only shrink. AC1c3 deletes the baseline file and the
   `str` branch.

## Pre-mortem

1. AC1c rewrites a message so it no longer tells the user what to fix: the registry table and
   the AC4 usability cells catch it; templates keep names and paths through mints.
2. A forwarder hides behind `functools.partial` or a dict of callables: the runtime check still
   catches it under strict in that command's tests after AC1c3; the guard docstring names the
   limit.
3. A builder keeps a test green by asserting the fallback text: the reviewer diff check lists
   every changed assert against the behavior-change numbers.
4. CLI-SPLIT or #411 moves the files mid-slice: AC1c1 and AC1d wait for those merges, and the
   flip waits for AC1d.
5. The engine renames the `_CLI_REGISTRAR` target: AT-4 fails at first mint; AC0 checks the name
   first.
6. The flip in AC1c3 turns many tests red at once: the baseline is zero before the flip, so a red
   test names a runtime-only route the guard missed; it is fixed at its producer in AC1c3.
