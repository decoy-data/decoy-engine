## Defect class

A CLI error sink prints text built from an exception or a value: `str(exc)`, `exc.message`, an
f-string with a cell, a path or a name slot. The sink trusts its caller. The audit counted 60
direct `emit_error` calls (14 f-string messages, 25 names, 3 `.message`, 3 `str()`) and about
177 calls through nine forwarding helpers. The CLI also trusts its own exception classes by type
(`_fixed_text_types()`, `cli/run/_errors.py:126`), and 180 raises of those classes build their
text from values.

## Guarantee and non-goals

Guarantee, when AC1d merges:

1. `emit_error` (`ui/output.py:217`) prints a `message` or `hint` only when it is a `SafeText`.
   Anything else (a `str`, `WITHHELD`, `None` for a message) goes to one hook,
   `record_sink_miss`, in the same module.
2. The run failure path (`fail`, `refused`, `bad_parameter`, `interrupted`, `report_error`,
   `finish_error`), the notify summary (`notify.build_run_event`, `error_summary`) and the
   preflight check list (`_PreflightAccumulator`) check their text through the same hook.
3. `record_sink_miss` never prints its argument. Under the engine strict switch (tests) it
   raises `TypeError` naming the call site. Otherwise it logs one value-free warning per
   exception type and site, and returns the original exception's type label when one is given,
   else `SafeText.const("Operation failed.")`.
4. Exit codes, reason codes, `decoy-error-v1` keys and the human line layout do not change. Only
   the text of messages that copied values changes.
5. CLI exception classes that the run path trusts carry `SafeText`. Trust by class goes.

Non-goals: the `context` members of the error object (AC4 canary covers them); warnings
(`add_cli_warning`, `run/_context.py:242`); Click and Typer usage errors that Click formats
itself; `print_exception` under `--verbose` (audit decision 1); log handlers (AC2); the copy
ratchet of CLI terminal copies (AC3); the canary walk over every command (AC4).

## Established solutions

Search run: OWASP Error Handling Cheat Sheet (generic message to the user, detail only to a
protected log), CWE-209 (error message with sensitive information), Google `safehtml` (a sink
accepts only a typed value that a small set of builders can make; plain strings fail at the
sink), RFC 9457 (a stable type and a short title instead of free text), and the CLI's own
choke-point sentries (`tests/sentry/cli_text/test_one_error_emitter.py`, the shrink-only ratchet
in `tests/sentry/_ratchet.py`). The design copies `safehtml`: the type is the proof, the sink
checks the type at runtime, and a static sentry is only a backstop. Nothing new is invented.

## Choke point

One function, `record_sink_miss(value, *, exc=None, site)`, in `src/decoy/ui/output.py`, and one
runtime check, `isinstance(value, SafeText)`, at each sink entry: `emit_error` (message and
hint), `_result.report_error`, `notify.build_run_event` and the three `_PreflightAccumulator`
methods. Every sink calls the same private `_checked(value, exc, site)` in `ui/output.py`, which
returns the value or the hook's result. There is no per-site rule: a sink that skips
`_checked` is caught by the guard below.

Guard: `tests/sentry/cli_text/test_safe_text_sinks.py`. It finds sinks and forwarders by AST,
not by a list: a forwarder is any function that passes one of its own parameters as the
`message` or `hint` of a sink or of another forwarder (fixpoint over the CLI tree). It flags
any sink or forwarder call whose message argument is a string literal, an f-string, a `str()`
call, a `.message` attribute, a `%` or `+` of strings, or a `.format()` call. Its self-test
seeds each shape and a new forwarder in a scratch module and asserts each is seen.

## Behavior changes

1. A message that quoted `str(exc)` of an engine error now shows `render_failure(exc)`: the
   registry summary and refs for a coded error, the declared `SafeText` for an uncoded error that
   carries one, the type label otherwise.
2. A message that quoted a CLI exception's text now shows the `SafeText` the raise built.
3. Path and name slots keep their text when the engine mint accepts them, and show
   `<withheld>` when it refuses.
4. `fail()` special cases (`cli/run/_errors.py:144` to `:169`), from the audit table:

   | Case | After AC1 |
   |---|---|
   | out of memory | `SafeText.const`; text kept |
   | coded capacity refusal | `render_failure(exc)`; the code is in the summary |
   | `AtomicWriteError` | `literal_template` with a `paths=` slot; text kept |
   | `LayoutError` | `literal_template`; code kept; message from `message_of(exc)` or the summary |
   | `PostScanBlockedError` | `SafeText.const`; text kept |
   | mask-secret errors | `SafeText.const` per code (fixed text today); text kept |
   | CLI refusal or config file error | `message_of(exc)`; type label if absent |
   | any other exception | `render_failure(exc)`; 500-character cap kept |

5. An absent notify summary stays absent: `error_summary=None` adds nothing to `detail`.
6. A plain string at a sink in a release build prints the type label or "Operation failed."
   and logs one warning line with the type name and site.

## Design notes

1. Literal checks are runtime `co_consts` checks in the caller. So a fixed message is written at
   the call: `emit_error(state, "setup", SafeText.const("setup needs a terminal; pass --yes to
   accept."))`. A module constant or a helper parameter fails the check. Forwarding helpers take
   a `SafeText` and pass it on; they never build one from a parameter.
2. `message_of(exc)` in the new `src/decoy/_safe_messages.py` returns `safe_text_of(exc)` for an
   engine exception and the `SafeText` a CLI exception stored. CLI exception classes keep their
   names and `str(exc)` behavior; the constructor takes a `SafeText` first argument, stores it,
   and passes `str(text)` to `args`, as the engine's `DecoyError` does (audit rev 2.1 item 7).
3. `src/decoy/_safe_mints.py` is the registrar and the only module that calls `SafeName` and
   `SafePath` mints. It calls `register_mint_callers` once at import, with keys for its own
   functions only. Its functions take `pathlib.Path` or an approved identifier type, not `str`.
   `decoy/__main__.py` imports it before any command module. The engine's `_CLI_REGISTRAR`
   names this module (AC0 open item 2). Each listed function carries
   `# pragma: no mutate block` on its def line (audit rev 2.1).
4. The run path keeps `cap_error_text` on the rendered string inside `report_error`, after the
   check, so the cap never needs a new `SafeText`.
5. Until AC1c flips the sinks, `emit_error` accepts `SafeText | str`; the static baseline counts
   every remaining plain-string call and may only shrink. AC1c deletes the baseline file and the
   `str` branch.
