### 1.2 Problem

Three kinds of over-built code remain on main:

1. **Handlers that turn a failure into a quieter result.** A2 and A5 are reachable. Six more are
   unreachable handlers that tell the reader a failure is possible when it is not.
2. **Surface and shims with no consumer.** Public names, `run_pipeline` keywords, re-export
   modules and CLI capability probes for an engine the exact pin already guarantees.
3. **Guard facts kept in up to four places.** Every ordinary change to an allowlisted site edits
   the in-code constant, the JSON baseline and sometimes a registry row. In the CLI, nine guards
   also assert JSON equals constant, reason text included.

### 4.2 A5: the unified-slice exception boundary

- **Today.** `E:execution/_unified_slice.py:359-361` catches every `Exception` from plan build,
  compile, shadow run and output assembly. It logs the class name and returns `None`, so the
  pandas oracle reruns. `UnifiedSliceInvariantError` and `PoolBuildFailed` are already handled
  first. A pyo3 `PanicException` is a `BaseException` and already propagates.
- **Step 0 (measure before building; recorded in the build report).**
  - Temporarily make the handler record `type(exc).__qualname__` and the raising frame's module
    into a scratch file.
  - Run `ET:physical/`, `ET:parity/`, `ET:native/` and the `ET:unit/execution/` suites, and
    list every exception class that reached it.
  - Classes with a coded decline meaning become the decline set. Today the expected members
    are `ShadowDifference` (coded, `physical/_shadow_diff_codes.py:214`) and the compile-time
    declines `compile_physical_plan` raises with a reason code. Anything else found there is a
    lane bug, which the slice either fixes or lists as a blocker.
- **Fix.** Replace `except Exception` with `except _LANE_DECLINES as exc:`. `_LANE_DECLINES` is a
  module-level tuple of the classes from step 0, and each member is commented with the code
  family it carries. The log line stays.
- **AT.** `ET:physical/test_unified_slice_exception_boundary.py::test_unexpected_exception_propagates`:
  monkeypatch the shadow coordinator to raise `KeyError`; `run_pipeline` must raise `KeyError`.
  The existing `test_unexpected_exception_reroutes_to_legacy` asserts the opposite: it is
  rewritten to raise a member of `_LANE_DECLINES` and still expects a reroute.
- **Mut.** Widen `_LANE_DECLINES` to `(Exception,)` → the AT goes red.
- **Output check.** The parity suites (`ET:parity/`) must stay green with the narrowed boundary.
  If one now raises, the lane has a bug that the catch-all was hiding, and the slice stops and
  reports it (`bugfix.md`).
