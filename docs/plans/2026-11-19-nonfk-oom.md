## 1. Problem and guarantee

Today a single non-FK mask table that the chunked gate declines runs on the full-frame route
(unified slice or pandas oracle) at any size. Input and output are both resident and nothing
prices the job before the read. The FK side has a byte estimate, a probe and a reject-before-read
(`_pipeline_routing.py:425-566`); the non-FK side has none (`decide_execution_route` returns
`full_frame, no_relationships` at `:566`).

This row promises three things, and only these:

- **G1 (part a).** Under `auto`, a non-FK mask table at or above the auto-chunk threshold whose
  only non-chunk-stable columns are *carried passthrough* columns (section 4.1) takes the chunked
  lane. Each carried column comes back as the source column, type and values exact.
- **G2 (part b, V1 portion b1).** Under `auto`, a masked integer-with-nulls, decimal or binary
  column no longer blocks the chunked lane when its strategy is in the masked-type admission table
  (section 4.2). Output equals the full-frame oracle value for value and type.
- **G3 (part c).** Under `auto`, a job with no FK edges whose resident set (section 4.3) cannot
  fit the effective host or cgroup kill ceiling is refused with
  `ExecutionError(code="nonfk_full_frame_capacity_exceeded")`. The code is in
  `CAPACITY_REASON_CODES`, so `decoy run` exits 5 with no CLI code change. A job that fits, or that
  is not proven beyond the kill ceiling, runs exactly as today. The 0.85 admission ceiling can
  prove a fit, but crossing it alone never refuses: the interval from 0.85 of available memory
  through the kill ceiling is `unverified`. What "before" means depends on the entry point:
  - `run_pipeline` with lazy Parquet sources: refused **before the whole read**, on a strict
    lower bound from the footer (row count and schema), ahead of `read_resident_fallback` and of
    the executor's `resolve_resident_sources`.
  - `run_pipeline` with a `source_loader`: the engine has a schema and no row count
    (`_pipeline_context.py:190-191`), so there is no bound before the loader runs. These jobs get
    verdict `unverified` and run as today (AT-C19).
  - `run_pipeline` with resident `pa.Table` sources: the input is already in memory. Refused
    before the engine makes its own copies: before any output staging, sink, cast run, spool or
    pandas conversion. A transform-bearing table is checked at the single transform preparation
    choke point before its whole-table pandas conversion, including a lazy resident-fallback
    source that has just materialized.
  - `decoy run` (CLI): the CLI reads every `path:` source whole before it calls the engine
    (CLI `cli/run/_execute.py:288`, `_native_gate.source_is_materialized`; engine
    `execution/capacity.py:5-9`). So the CLI read itself is not guarded. The engine refusal still
    comes before the full-frame peak (about 3.5 times the input, record section 2.7), which is
    the run that gets killed today. Section 13 Q6 says how RUN-STREAM C1l closes the CLI read.
  - The subset stage writes scratch Parquet before routing (`pipeline/_subset_stage.py:1-7`). A
    refusal after it leaves no scratch: the subset scope removes its root on every exit (AT-C6b).

Non-goals (a review finding here is a follow-up, not a blocker):

- Arrow-exact ingest for every masked integer column on the full-frame oracle (part b2, section 5).
- Pricing generate tables in a generate+mask non-FK job (they have `GenerationBudgetLedger`).
- FK jobs. Their routing and refusals are unchanged.
- The unified slice domain (record limit 4, item C4) and the sub-100k cliff.
- Making the full-frame oracle carry passthrough columns exactly (owner question Q2).
- Pricing a CSV or fixed-width lazy source before read (no footer). It runs as today, verdict `unverified`.
- Guarding the CLI's own source read (Q6: RUN-STREAM C1l owns it).
- `decoy validate preflight` predicting the new refusal (owner question Q4).
- `execution_mode="full_frame"` stays the override and is never priced. Only the governor
  (`_governor.py:546`) and the probe child (`_probe.py:262`) pass it today; no CLI flag does.

Expected size: about 15 source files touched, 2 new source modules, 1 new bench script, 1 new
runtime code, 4 new route reason codes, 2 new `RouteDecision` fields, 1 new `ProbeResult` field,
1 new `PhysicalPlanInputs` field, one new `PreparedSources` field, one new root public export
(`detect_effective_memory_bytes`) and an internal `execution.pipeline` facade for the new names.

## 3. Established solutions

Search run: web search for memory admission control that estimates and rejects before execution
(Impala, Trino, Spark), plus the codebase's own routing designs.

- Impala admission control decides admit, queue or reject from a per-query memory estimate before
  execution, and lets the operator cap the estimate (`MAX_MEM_ESTIMATE_FOR_ADMISSION`). Its own
  docs say estimates are not enforced and recommend a measured cap (`MEM_LIMIT`) over a bare
  estimate. Sources: [Impala admission control](https://impala.apache.org/docs/build/plain-html/topics/impala_admission.html),
  [MAX_MEM_ESTIMATE_FOR_ADMISSION](https://impala.apache.org/docs/build/html/topics/impala_max_mem_estimate_for_admission.html),
  [IMPALA-5104](https://issues.apache.org/jira/browse/IMPALA-5104).
- Spark has no built-in general pre-execution memory admission; a "gatekeeper" over plan
  statistics is a proposal only ([gatekeeper model for Spark SQL](https://www.positioniseverything.net/building-a-gatekeeper-model-for-spark-sql/)).
  The search returned nothing usable for Trino.
- In this repo: the OOM-avoidance redesign (`docs/plans/2026-07-10-oom-avoidance-routing-redesign.md`
  section 13) already pairs a conservative static estimate (`_mem_estimate.fits`) with a measured
  two-point probe (`_probe.probe_peak_bytes`) that can recover a job the estimate over-prices, and
  a "clearly busts" pre-filter (`MIN_PLAUSIBLE_K_FULL_FRAME`).
- The chunked carry (`_chunked_carry.py`) already follows the Arrow rule that a column no kernel
  touches is passed by reference, never converted.

Design followed: Impala's estimate-then-admit-or-reject shape, with the estimate backed by this
repo's measured probe (the "measured cap" Impala recommends). No new estimator, no new probe, no
new carry mechanism. The only new code is the decision that composes them for non-FK jobs and the
planner's carried-column exemption.

## 4. Design

### 4.1 (a) Carried passthrough columns join the chunked lane

`_planner._runtime_source_rejections` (`_planner.py:473-499`) rejects a table when any source
column has a non-chunk-stable type. The exemption: a column in the table's **carried set** is
skipped by that loop. The carried set is computed by one new public function in
`_chunked_carry.py`, `carried_columns(columns_cfg, source_schema, registry, policy) -> frozenset[str]`:
passthrough columns (configured `strategy: passthrough`, or unconfigured and kept under the
`passthrough`/`warn` policy) minus `read_set(...)`. `CarryPlan` construction in `run_mask_chunked`
is changed to call the same function, so the planner and the lane cannot disagree on which
columns are carried. That shared function is the choke point (section 6).

Carry is enabled only for the stock adapter (`is_stock_adapter`). `run_pipeline` never takes a
caller adapter, and the auto lane passes the context's `PandasExecutionAdapter`; AT-A5 pins that.

Covered types: integer with nulls, decimal, binary, large_binary, fixed_size_binary, dictionary,
list, large_list, struct, map. The remaining decline message already maps to the registered route reason
`chunked_source_dtype_unstable` (`translate_chunked_rejection` in `physical/_reasons.py`), so every
decline carries a registered reason and S2 adds no new code for it.

Nested sources need `profile/_walk.py:169` fixed first: `nunique` on an unhashable cell raises.
`walk_dataframe` threads each column's Arrow type into `_walk_column` (a new `arrow_type`
argument, taken from the source schema the reader already holds). When the type is list,
large_list, fixed_size_list, struct or map, `distinct_count` is `None` and `nunique` is not
called. No `try/except`: a type check names the case, a catch would hide a different failure.
This changes no existing output (those sources crash today). A small nested table on the
full-frame route must then be exact or a coded refusal, never a crash (AT-A9).

### 4.2 (b) Masked columns of those types

**Call: b1 is V1, b2 is not.**

b1 (V1, size S). A table-driven admission in the planner: `CHUNK_STABLE_MASKED_SOURCE_TYPES`, a
mapping from strategy to the source type classes it reads exactly on every chunk, with an output
type the schema rule already pins:

| Strategy | Admitted source classes | Why chunk-stable |
|---|---|---|
| `hash`, ungated (`when` is `None`) | int with nulls, decimal, binary | keys on exact Arrow ints (`_exact_int_sources.py:46-68`, ungated hash only); output pinned `string` (`_chunked_schema_rule`); probe: 0 diffs on int with nulls; decimal and binary unproven until their cells are green |
| `redact` (string `redact_with`) | int with nulls, decimal, binary | constant output; pinned `string`; probe: 0 diffs |
| `faker` (deterministic REUSE) | int with nulls | the c5c-a fix hands the handler exact Arrow ints (`test_c5c_a_nullable_int_faker.py`) |

Not admitted: `hash` with its own `when:` (the exact-int registration covers ungated hash only,
and a gated hash on an integer column is refused at admission today); `truncate` on binary (it
emits the Python `repr` text, section 0, follow-up F5).

A masked column is admitted only when it is also not in any other entry's read set (a `when:`
predicate or sibling reference would see the per-chunk pandas dtype). Every row in the table needs
its parity cell (AT-B1); a row whose cell is not green is removed, never relaxed.

b2 (not V1). The record's wording, "keep ints Arrow-exact (`to_pandas_fk_safe` mapping)", applied
to every masked integer column on the full-frame oracle. Not small: it changes the pandas dtype
every integer-reading handler receives (`float64` to `Int64`) on the full-frame route for every
table size, so numeric-output strategies (`bucket_perturb`, `top_code`, `bucketize`, `shuffle`,
`formula`, `derived`) change output type or value, every golden with an int-with-nulls column
moves, and each handler needs an Int64 audit. It also changes output bytes, so it cannot ship in
1.0.x under ROADMAP rule 2 (1.x is byte-identical). Recommendation: hold to 2.0. Tables it would
have widened stay on full-frame and are covered by G3. Owner question Q1.

### 4.3 (c) The resident-fit decision

New module `execution/pipeline/_resident_fit.py`. S1 introduces its pure lower-bound primitive; S4b adds the decision functions around it. All decision logic is in free functions (mutmut skips decorated class bodies). The module has these seams:

```text
lower_bound_bytes(specs) -> int                              # pure: no IO or host reads
resident_fit_verdict(facts: ResidentFitFacts) -> ResidentFit     # pure: numbers in, verdict out
gather_resident_fit(ctx, decision, additional_resident=()) -> ResidentFit
store_resident_fit(ctx, decision, additional_resident=()) -> RouteDecision
check_pre_read(config, sources, tables, kill_ceiling) -> None      # footer facts, may raise
check_pre_transform(config, sources, graph, execution_mode, kill_ceiling) -> ResidentFit | None
                                                                # no transform or pandas call
require_resident_fit(fit: ResidentFit) -> None                   # calls shared error builder
```

`store_resident_fit` alone decides applicability, calls `gather_resident_fit`, raises a refusal and replaces `RouteDecision.resident_fit`. It runs at the end of `_pipeline_context.decide_route` and again from `_pipeline_mixed_route._fall_back` after `mixed` becomes `full_frame`, with the generated Arrow tables as `additional_resident`, before `run_full_frame_route` can resolve sources. There is no mixed-specific capacity predicate. The physical compiler never gathers: `_live_inputs.py:148` copies the stored verdict into `PhysicalPlanInputs.resident_fit`; the compiler only reads it and stays pure (`physical/_compiler.py:1-5`).

The full-frame decision is in scope when `execution_mode == "auto"`, a mask table and non-empty resident set exist, the graph has no FK edge, and `decision.route == "full_frame"`. These conditions live only in `store_resident_fit`; callers do not copy them. Every phase builds `ResidentFitFacts` and calls the same `resident_fit_verdict`; no gatherer implements a ceiling comparison. Runtime refusing results pass to `require_resident_fit`; it and the physical direct-call guard use one value-free `nonfk_full_frame_capacity_error` builder in the existing `_errors.py`.

**Resident set.** The mask tables the full-frame executor will hold: every mask table, minus the
chunked table when `route_chunked`, minus `split.dispatched` when a multi-table split applies.
Today the split is decided inside the executor (`_pipeline_generate_mask.py:171-190`), after
`with publish:`. Slice S4a moves that one call into `decide_route` and stores the result on
`RouteDecision.split`; the executor reads it and no longer decides. Its inputs (`cast_run is None`
becomes "the plan has no declared columns", the same predicate `open_cast_run` uses) are all known
before execution.

For a mixed runtime decline, the resident set also includes every table in `pregenerated`; those tables remain live while the continuation resolves and converts mask sources. Because the in-scope job has no FK edge, pregenerated generate outputs contribute `input_bytes` only, never a pandas term; only mask sources that full-frame converts get full `LB`.

**Ceilings.** `H = detect_effective_memory_bytes()` is the host or cgroup kill ceiling. `A = H * RESIDENT_ADMISSION_FRACTION`, with fraction 0.85, is the conservative admission ceiling (Q3). `A` can prove `FIT`, never `INSUFFICIENT`; `[A, H]`, including both endpoints, is `UNKNOWN` and runs. The detector is exported from `decoy_engine.execution.out_of_core` (catalog class 6), not imported from `_budget`. These are not the 25% out-of-core budget: with no bounded fallback the question is whether the run crosses `H`. `--max-memory` sets only the out-of-core budget (CLI `_resources.py:114-119`), so both ceilings ignore it; honoring it is V2-LOG and S5 documents the scope.

**Lower bound.** `LB = input_bytes + pandas_bytes`, both strict:

- `input_bytes`: `pa.Table.nbytes` of each resident table (the caller's table stays live for the
  whole run). A dictionary column whose chunks share one dictionary buffer counts it once
  (`nbytes` would count it per chunk). For a lazy table, the fixed-width part only: rows times the type's byte width, plus
  4 offset bytes per row for each variable-width column.
- `pandas_bytes`: the full-frame route converts every column to pandas (oracle ingest and the
  unified slice both do a whole-table `to_pandas`). Rows times the per-cell width pandas needs:
  the numpy width for numeric and temporal columns (8 for int with nulls, which becomes
  float64), 1 for bool, 1 for dictionary codes (pandas narrows the codes, so 1 byte is the
  floor), 8 (one object pointer) for string,
  binary, decimal and nested.

Rows and schema come from the Parquet footer for a lazy table, so `LB` needs no read. S1 adds `lower_bound_bytes` as a pure function over supplied facts, with no file IO, probe or host read; `execution.pipeline` re-exports it and the bench imports that facade. S4b calls the same function while gathering `resident_fit_verdict` facts, with no second formula. If a workload disproves the bound, S1 lowers that type's pandas term before merge.

**Pre-transform lower bound.** `prepare_transform_sources` is the only production caller of `prepare_resident_transforms`, so it is the choke point. After fallback materialization and immediately before preparation, it calls `check_pre_transform`, which alone scopes the check to `auto`, a mask table and no FK edge. For each transform-bearing resident table, the strict bound is all live resident input bytes plus that table's whole-frame `pandas_bytes`; use the maximum across the serial loop. This charges `to_transform_frame` without predicting row-changing output. A bound above `H` refuses before `apply_resident_table`; otherwise it runs. Store the result on `PreparedSources.pre_transform_fit`; `store_resident_fit` folds it into the final verdict so `[A, H]` stays `UNKNOWN`. On a chunked final route it carries that verdict without gathering full-frame facts. This is one check at the one transform call site, not a second full-frame predicate.

**What the code says about the probe** (finding 2). Risk columns make `probe_peak_bytes` return
inconclusive (`_probe.py:364-372`), but at scale none are flagged, because `distinct_count` comes
from a 10,000-row head sample (section 0). So the fix has two parts:

- Risk is computed on the sample: a column is at risk when `distinct_count` divided by the
  sampled non-null count is at or above `UNIQUENESS_SATURATION_THRESHOLD`, or the full-scale
  ratio is (today's rule). A column whose sampled non-null count is 0 is not at risk (there is
  nothing to saturate). A helper `sampled_uniqueness_risk` sits beside
  `uniqueness_saturation_risk` in `_probe.py`. The FK caller is unchanged.
- `probe_peak_bytes` gains `risk_policy: Literal["skip", "measure"] = "skip"`. `"skip"` is
  today's behaviour (FK path). `"measure"` runs both points and returns a conclusive result with
  the new `ProbeResult.uniqueness_risk: bool` set. A small-N probe under-states a saturating
  column, so its measured non-fit is a trustworthy refusal, and its fit is not proof.

**Verdict ladder** (first match wins; each verdict has a registered code and a
`CapacityEstimate` token):

P. Pre-read (lazy Parquet mask tables, no FK edge in the graph). The route is not decided yet,
   so step P never charges the pandas copy for a table that may still run chunked:
   - In `read_resident_fallback`, before `materialize_source`: the tables it is about to read,
     priced at `input_bytes` only. A table forced to full-frame whatever the route (for example a
     vault run) is priced at the full `LB`. Non-mask lazy tables read there count at
     `input_bytes`, because they are resident too. `sum > H` refuses; `sum` between `A` and `H`
     does not.
   - In `gather_resident_fit`, for lazy mask tables **not in `decision.keep_lazy`**: the same set
     `resolve_resident_sources` reads whole in the executor (`_pipeline_full_frame.py:157`). One
     predicate, read from the decision, never recomputed. The route is known here, so these
     tables are priced at the full `LB`.
   Nothing has been read in either case.
T. Before resident transforms, the choke-point check above charges the transform pandas copy.
   `transform_LB > H` refuses; otherwise preparation continues. A lazy resident-fallback source reaches T after its unavoidable whole read but before its first transform copy.
1. `LB < A`, `estimate_peak_bytes(specs, "full_frame") * (1 + K_CALIBRATION_ERROR_BAND) < A`
   and no risk column: **fits** (`nonfk_full_frame_fits`, FIT). Runs. No probe.
2. `LB > H`: **refused** (`nonfk_full_frame_capacity_exceeded`, INSUFFICIENT). The job cannot
   fit even with nothing but its input and one pandas copy live.
3. Every resident table is a resident `pa.Table` and file access is ambient: run
   `probe_peak_bytes(..., risk_policy="measure", mem_cap_bytes=H)`, other arguments as
   `resolve_probe_recovery` passes them.
   - When `LB < A`, a no-risk estimate whose upper calibration edge is below `A` is **probe fits** (`nonfk_full_frame_probe_fits`, FIT).
   - An estimate strictly above `H * (1 + K_CALIBRATION_ERROR_BAND)` is **refused** (INSUFFICIENT), with or without a risk column; the entire error band must clear `H`.
   - Everything between those thresholds, a fit with risk, or an inconclusive result falls to 4. Small-N string dedup can over-state a risk-flagged peak, so the gap is not proof.
4. Otherwise (lazy CSV or fixed-width, a `source_loader`, strict file access, probe
   inconclusive, or any lower bound or measured estimate in the gap): **unverified**
   (`nonfk_full_frame_unverified`, UNKNOWN). Runs, as today. Recorded, never silent.

The ladder never refuses on the upper-biased static estimate alone (FM1). It refuses only on a
strict lower bound beyond `H` or a measured estimate beyond `H` by the calibration error band.
`A` is admission-only. No comparison with `A` can produce a refusal.

**Outputs.** `ResidentFit(verdict, code, table_count, estimated_bytes, lower_bound_bytes, admission_ceiling_bytes, kill_ceiling_bytes)` goes on `RouteDecision.resident_fit` and into `quality_metrics["resident_fit"]`: tokens, counts and bytes only. `verdict` is `FIT`, `INSUFFICIENT` or `UNKNOWN`, the `CapacityEstimate` vocabulary (`execution/capacity.py`); a shared enum is V2-LOG. Verdict 4 logs one value-free line: `resident fit unverified: <code>`.

**Refusal.** `ExecutionError(code=reasons.runtime.NONFK_FULL_FRAME_CAPACITY_EXCEEDED, message=...)`. The message has the registered summary, lower-bound or measured and kill-ceiling byte counts, and remedies. It is numbers-only and raised outside `except` (`__cause__` and `__context__` are `None`). It can arise from `read_resident_fallback` (P), `prepare_transform_sources` (T), or `store_resident_fit` during initial or mixed-fallback routing. No output publish, cast run, source resolution or spool follows a refusing verdict. The subset scope removes existing scratch; probe resources are already torn down.

**Exit 5.** The new code joins `errors.CAPACITY_REASON_CODES` (`errors.py:517`). The CLI's
`exit_code_for` reads that set (CLI `src/decoy/cli/exit_codes.py:211-212`), so no CLI code
changes; the CLI docstring and `decoy explain exit-codes` text list the set by name and get a
documentation PR (slice S5). `errors.py` is at 600 lines: the builder keeps it at 600 (the code
joins an existing line of the set) or adds a new census entry; no existing ceiling moves.

## 5. Failure modes

- FM1 False refusal: the static model (slope 4.0, measured 3.45 on numeric data) over-prices
  pooled strings by up to 3x. Closed by the ladder: static alone only admits against `A`;
  refusal needs a strict lower bound beyond `H` (steps P, T and 2) or a measured estimate beyond
  `H` by the calibration band (step 3). AT-C2, AT-C3 and AT-C4.
- FM2 Under-pricing: a job that passes and still dies. Residual, same as today. S1 and S5 measure
  it; step 4 records every run that was not verified.
- FM3 Refusal after staging: a stage directory, scratch Parquet or spool left behind. Closed by
  raising in `read_resident_fallback`, `prepare_transform_sources` or `store_resident_fit`, before
  any engine output staging; the subset scope cleans its own scratch. AT-C6, AT-C6b, AT-C20 and
  AT-C21.
- FM4 The split decided twice and disagreeing with the resident set. Closed by S4a: one decision
  on `RouteDecision`. AT-S1 and the guard test G-2.
- FM5 Physical compiler drift or impurity: the compiler recomputes the verdict, or gathers facts
  (a memory read, a probe child) after publish. Closed by the stored verdict: the compiler reads
  `PhysicalPlanInputs.resident_fit` and nothing else; the code is registered in
  `physical/_reasons.EXECUTION_ERROR_CODES`. AT-C9 and the G-4 import guard.
- FM6 A value in the refusal or the metrics block. Closed by numbers-only construction. AT-C7 and
  the existing value-free sentry over `ExecutionError` emitters.
- FM7 A carried column that pandas code reads. Closed by `read_set`: a `when:` or sibling reference
  keeps the column off the carried set. AT-A4.
- FM8 Route-dependent output type at the threshold: a 99,999-row table keeps `double` for an
  int-with-nulls passthrough, a 100,000-row table now gets `int64`. Recorded under
  ROUTE-OUTPUT-CONTRACT (`docs/compatibility-contract.md`); owner question Q2 offers closing it.
- FM9 Probe cost on a job that will be refused anyway. Bounded: step 3 runs only when step 1 fails,
  about 1-2% of a full run (`_pipeline_routing_signals.py:390`).
- FM10 Lazy sources cannot be probed. A Parquet lazy table is refused pre-read when its footer
  lower bound exceeds `H` (step P), else reaches step 4. CSV and fixed-width reach step 4.
  AT-C13, AT-C16.
- FM15 Near-unique columns hide from the risk check because distinct counts are sampled. Closed by
  the sample-ratio risk rule; a fit with risk columns is `unverified`, a measured non-fit
  refuses. AT-C17.
- FM16 The lower bound is not a bound for some type (a pandas width guessed too high). S1
  introduces the pure formula and measures peak against `LB` on every workload; mutation 13
  shows AT-C2's kill-ceiling boundary notices a raised width.
- FM11 Nested sources crash profiling. Fixed in S2. AT-A6.
- FM12 A multi-table job with one oversized full-frame table and several chunked ones. Priced on the
  resident set only. AT-C5.
- FM13 `auto_chunk=False` sends every large table to full-frame; the guard applies (the run would be
  killed otherwise). AT-C8.
- FM14 A builder widens the masked-type table without a parity cell, or loosens a cell. The matrix
  is derived from the table (G-1), so a row without a green cell fails.
- FM17 A resident-fallback source materializes and then its transform copy crosses the kill
  ceiling before the normal route decision exists. Closed at the one transform preparation
  choke point. AT-C20.
- FM18 A mixed job declines after generation and enters full-frame without pricing its lazy mask
  source or the still-live generated tables. Closed by restamping the replaced decision through
  `store_resident_fit`. AT-C21.
- FM19 A job between 0.85H and H is refused even though it runs today. Closed by separate `A` and
  `H` fields and boundary cells at both ceilings. AT-C2 and AT-C4.

## 13. Owner questions (recommended answer first)

1. **Q1 Part b2.** Hold the broad Arrow-exact integer ingest to 2.0. It changes full-frame bytes

   tables it would have widened are refused cleanly by G3 or run when they fit.
   Alternative: pull it before the freeze as its own L row.
2. **Q2 Full-frame passthrough fidelity.** Today the full-frame route rounds int-with-nulls above
   2^53, narrows decimal precision and changes dictionary index width on passthrough columns
   (section 2). After this row a large table gets the exact type and a small one does not.
   Recommend: a separate small before-freeze row that makes the full-frame route carry passthrough
   columns the same way, closing FM8. Alternative: record the difference under
   ROUTE-OUTPUT-CONTRACT and leave it to 2.0.
3. **Q3 Admission fraction, not refusal ceiling.** Recommend `A = 0.85H` for proving FIT; it
   leaves room for the interpreter, the CLI's own copy of the input and other processes. Keep
   the refusal ceiling fixed at the detected cgroup or host kill ceiling `H`: a strict lower
   bound must exceed `H`, and a measured probe must exceed `H` by the calibration error band,
   before the engine refuses. Evidence between `A` and `H` is UNKNOWN and runs as today. S1
   numbers may move the 0.85 admission fraction; any change is an owner call and must not lower
   the refusal ceiling.
4. **Q4 Preflight.** `decoy validate preflight` does not read data, so it cannot probe. Recommend:
   it reports the step-2 lower-bound refusal as `INSUFFICIENT` and anything else as today, in a

5. **Q5 Unverified runs.** Recommend recording verdict 4 in `quality_metrics` and the log only.
   Alternative: also a user-visible warning (changes the warnings list, a freeze item). With the
