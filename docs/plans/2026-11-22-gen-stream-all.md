## 1. Frame

Evidence (audit, measured on the Dell 26-core node, 10M rows unless stated):

- The streamed lane generates a pooled `first_name` column to Parquet at 6.9M rows/s (1.46 s). Of the per-row cost, the pick is 48 ns: `values[idx].tolist()` 14 ns plus `pa.array(values)` 34 ns (`src/decoy_engine/generation/_faker_pool.py` `PooledSelector`, `src/decoy_engine/generation/_streamed.py` `_table_batches`). RNG indices plus `pyarrow.compute.take` cost 3.5 + 9 = 12.6 ns/row for the same output.
- Faker types outside `POOL_ELIGIBLE_FAKER_TYPES` run per row: email about 8.6k rows/s, phone about 65k rows/s. A 10M-row email column takes about 20 minutes.
- Pooling only starts at `N_THRESHOLD = 50_000` rows (`_faker_pool.py:236`). The comment there records why: the pool is always built at `DEFAULT_POOL_SIZE` (10,000 Faker calls), so a 1k-row column paid 10x its own cost.
- `provider` (npi about 80k rows/s), `lookup`, `statistical` and `inherit` are declined by `ADMISSION_MATRIX` (`src/decoy_engine/generation/_admission.py:46`). One declined column sends the whole plan to `_run_legacy` (`_streamed.py:580`) with result reason `legacy:<table.col:reason>`, so one `lookup` column makes a 10M-row table resident and pandas-free but Python-list-bound.
- `derived` (about 25k rows/s) and `grouped_series` (about 28k rows/s) are slow but need a sibling-row or sort seam this row does not build.

Why the four kinds are streamable now (read at `70881ad79`):

- `provider` (`src/decoy_engine/generation/kinds/_provider.py`): its three draw paths are pool (`PoolBuilder` + `PoolSampler` REUSE), keyed (native per-row `generate(source_value=i)`) and batch (one Faker seeded once, then sequential calls). Each is a function of the row ordinal or of one sequential stream, so a persistent stream gives the same bytes as one whole-column call.
- `lookup` (`kinds/_lookup.py:271`): `random.Random(ctx.base_int("py")).choices(k=n)`. `choices` draws one `random()` per pick, so k calls of size b on one persistent `Random` equal one call of size n. It needs `lookup_lists` pinned in the plan, which the plan compile already does.
- `statistical` (`generation/statistical/_sample.py:389`): `sample_column(spec, n, col_seed, parent_values, start=)` reseeds per row with `col_seed + start + i`; `generation/window.py` already reads windows through `start`.
- `inherit` (`generation/relational/_inherit.py`): a left join on the parent key through `lookup_parent_values`. It needs the parent's key-to-value map, which the streamed lane can collect while it writes the parent (the same collector seam `reference` uses for its parent key set).

## 2. Established solutions

- **Index then take.** Arrow's documented gather is `pyarrow.compute.take(values, indices)` (Arrow compute "Selections"); numpy `Generator.integers` gives the indices. This is the dictionary-decode pattern (Arrow `DictionaryArray`, Parquet dictionary pages): store a small value table once, emit integer codes, gather. No custom kernel.
- **Pool sampling for synthetic text.** SDV's `AnonymizedFaker` (RDT) builds a bounded set of Faker values and samples from it when `cardinality_rule` is not `unique`; Mimesis documents the same speed trade for providers. Decoy already uses this pattern (`_faker_pool.py`, harness in `scripts/faker-determinism/`); this row widens its type set and drops its threshold.
- **Prefix-stable streams.** numpy `Generator` and Python `random.Random` are sequential: drawing b then c values equals drawing b+c. The streamed lane's existing streams (`_column_streams.py`) rely on this; the new streams use the same rule and the same test shape (`tests/unit/generation/test_generate_determinism_ratchets.py`).
- **Bounded join for inherit.** A hash map built from the parent while it streams, then probed per child batch, is the standard build/probe hash join (Graefe 1993, "Query evaluation techniques"); the memory budget is the parent's key-value pairs, reserved in the existing budget ledger.

## 3. Guarantee and non-goals

After this row:

- A plan whose generate columns are all of the kinds `sequence`, `categorical`, `faker`, `reference`, `constant`, `distribution`, `windowed_date`, `provider`, `lookup`, `statistical` or `inherit` runs on the streamed lane, resident or with a sink, and never on `_run_legacy`.
- A pooled column's values are produced by `pc.take(pool, indices)`; no Python list of row values exists for it unless a sibling, a collector or a declared cast needs one.
- Every Faker type that the harness certifies for a locale pools at any row count, with pool size `P = min(rows, 10_000)`. `pooled: false` and `unique: true` still opt out.
- Output is a function of (plan, seed) only: the same at any batch size, resident or sink, and on every rerun. Proved by A3 and A7.
- A declined plan names each declined column with a coded reason (`generation.legacy.<kind>`), carried on `GenerationResult.declines` and on the run card.

Non-goals: streaming `unique`, `derived`, `formula`, `grouped_series`, `derived_aggregate`, `group_key` (named exceptions, section 4); a native Rust Faker; changing the pool size knob; the mask path's Faker (see NATIVE-THREADS-DEFAULT); CSV output speed (see CSV-WRITE-FAST).

## 8. Acceptance tests (each fails before its slice)

S1:

- **A1 certified only.** For every `(type, locale)` in the widened set, `pool_eligible` is True only if the pair is in `certified_pairs.json`; the eligible set is derived from that file (one root), and a pair removed from the file stops pooling. Fail-before: email is not eligible.
- **A2 take parity.** For a pool type already eligible today at 120,000 rows, the take path output equals the list path output byte for byte (Parquet file digest), including a column with `null_probability: 0.1`. Passes before and after (control); its mutation is in the class table.
- **A3 batch invariance.** For each pooled type, rows in {1, 9,999, 10,000, 10,001, 120,000} and batch sizes {1, 7, 4096, rows}, the output digest is the same at every batch size and between resident and sink runs. Fail-before: rows < 50,000 are per row, and per-row equality across batch sizes holds, so the fail-before is the email row (not pooled, digest differs from the pooled expectation recorded in the test).
- **A4 width bound.** A fake provider whose pool holds one value over the type's `FAKER_VALUE_CAPS` refuses in budget mode before any row is written.
- **A9 coded declines.** A plan with one `derived` column runs legacy with `GenerationResult.reason == "legacy:generation.legacy.derived"` and `declines == ("t.c:generation.legacy.derived",)`; the strings contain no value. Fail-before: free-text reason.
- **A10 speed (performance gate, not unit).** On the Dell node, generate 10M rows of one `email` column to Parquet in under 3 s (audit: about 20 min today), and one `first_name` column in under 1.0 s (1.46 s today). Recorded in the slice record with the commit; run through `vm-run`, never in the unit suite.

S2:

- **A5 provider and lookup parity.** For each provider draw path (pool, keyed, batch) and for `lookup`, the streamed output at batch sizes {7, 4096} equals the legacy output of the same plan at `70881ad79` byte for byte (golden digests captured from main in the test, not hand-written).
- **A6 admitted.** A plan of `sequence` + `provider` + `lookup` columns reports route `streamed`. Fail-before: `legacy:...lookup...`.

S3:

- **A7 statistical windowed.** A statistical column with and without `condition_on` gives the same values streamed at batch 7 as resident legacy. Fail-before: declined.
- **A8 inherit join.** A parent of 10,001 rows and a child of 30,000 rows with `inherit` on two columns: every child row's inherited values equal its parent row's values (join check), and output equals legacy. A parent map larger than the budget refuses with `GenerationBudgetExceeded` before the first write. Fail-before: declined.
- **A11 fidelity accumulator.** The fidelity warning fires for a deliberately bad spec and not for a good one, streamed and resident.

## 9. Frozen contracts and compatibility

## 10. Pre-mortem

- A user joins two generated tables on an email column and gets fan-out from repeats. Named in the changelog with the `unique: true` fix; the run card already shows pooled columns (no new surface).
- A Faker upgrade changes a new type's pool values. The harness goldens catch it in CI on the pin bump; this is the existing process for the 10 types.
- A locale has a tiny value set for a type (for example `postcode` in a small locale), so `P` values hold many duplicates. Same as today's pooled types; the pool is built by sequential draws, duplicates included, and that is deterministic.
- `_batches.py` drops a declared cast for an Arrow-path column. A2 covers a declared output type; the builder adds one case per `restore_declared` branch that a faker column can take.
- The inherit map for a 100M-row parent does not fit memory. Budget mode refuses; unbounded mode (no budget) holds the map, which the resident legacy path held anyway (as a full parent table, larger).
- ROUTE-LABEL-TRUTH chooses different code names. The codes live in `reasons`; one rename PR changes both, and the CLI copies none (CLI sentry `tests/sentry/test_engine_reason_code_copies.py`).

## 11. Open questions for the owner

1. Identifier types (`uuid4`, `ssn`, `credit_card_number`, `iban`, `ean`, `isbn10/13`, `license_plate`): pool them too, or keep them per row as a named exception? Recommended: keep per row, because a repeated identifier breaks a key column; they are not the slow types in the audit (uuid4 is fast).
2. Small columns: for `rows <= 10,000`, emit the pool in build order (recommended; it costs at most the per-row draw and keeps full diversity) or always draw indices (simpler code, adds repeats to small tables)?
3. Statistical fidelity on the streamed lane: score a bounded accumulator over the whole column (recommended; exact for the histogram metrics it uses) or score only the first 100,000 rows?
