## Part 1. Audit

### Scope and threat model

Only accidental leaks are in scope. A leak is a cell value, an expression's text, or a secret
that reaches an outbound text stream through an ordinary code path. Hostile in-process objects
(a crafted `__str__`, a malicious plugin) are V2.

Outbound text streams:

- engine log records (file handler, console handler, any host-attached handler);
- exception messages (every engine message is outbound, because the CLI prints it);
- `warnings.warn` text;
- report documents (run result, progress events, telemetry, records, scan and profile output);
- CLI stdout, stderr and the `--json` document;
- CLI notify payloads, per-channel results, delivery warnings and CLI log handlers.

Engine handler output includes cached traceback text. A host formatter can populate
`record.exc_text` before the engine handler sees the record.

### Method

1. `sites.py`: an AST walk over every `.py` file under engine `src/decoy_engine` (963 files) and
   CLI `src/decoy` (198 files). Each site gets a class (raise, log, warn, terminal,
   exception-text copy, `__str__`). Each interpolated expression gets a tag: EXC (an
   except-bound name or exception text), VALUE (a name such as `value`, `cell`, `row`, `expr`,
   `text`), LOC (a path, URI or DSN name), IDENT (any other name). A site's risk is its worst
   tag: leak (EXC or VALUE), review_loc (LOC), safe_ident (IDENT only), safe_const (no
   interpolation).
2. `copies.py`: every copy of exception text and the sink it flows to. An exception name is an
   `except ... as NAME` binding, or a function parameter named `exc`, `err`, `e`, `error`, `ex`,
   `exception`, `cause` or `inner`, or annotated with an exception type. A copy is `str()`,
   `repr()` or `format()` of that name, an f-string `{NAME}`, `% NAME`, a text attribute
   (`.args`, `.message`, `.msg`, `.detail`, `.raw_message` and others), or a traceback
   formatter.
3. `registry_share.py`: which raise sites keep their message under the registry rule (AE1).
4. A read of every existing choke point and sentry, listed below.

The site counts (step 1) are heuristic. Samples of 30 "leak" raises showed many false positives:
names such as `key`, `x` and `default` that hold config identifiers, and coded raises whose fields
are only locations. Read the raise and terminal "leak" rows as an upper bound. The copy counts
(step 2) have high precision, because the pattern is exact.

## Part 2. Plan

### Guarantee

Under default flags, a planted secret placed in a cell, an expression literal, a config default or
a connection secret (including a notify URL password) does not appear in any engine or CLI outbound text stream, for each failure
shape in the canary corpus, through each entry point in the corpus. Three sinks are closed by
construction for every failure, not only corpus shapes: the CLI `decoy run` error text, every
`emit_error` message, and every record that passes an engine handler (exception args and
`exc_info` and cached `exc_text`). Notify results expose only the hostname for URL targets. The copy ratchet stops new exception-text copies in both repos.

Not guaranteed: the copies left after AE5 and AC3 (49 engine, 50 CLI). Each is listed as V2-LOG
in `engine-triage.tsv` and `cli-triage.tsv`, with its sink. They stay counted by the ratchet.

### Non-goals

- Hostile in-process objects (V2).
- E0b, the `decoy-safe-output/v1` wire line. It stays parked.
- The Platform slices of F31. They stay parked.
- The 99 V2-LOG copies above.
- Engine DEBUG log-file traceback stripping beyond `SafeRecordFilter`. Admin logs are V2 under
  the V1 bar; logged V2-LOG.
- Pre-formatted f-string log messages (`internal/memory.py:54`) and `str(exc)` passed as a `%s`
  argument. The filter cannot see them. `test_log_interpolation.py` stays their guard.
- New reason codes. The registry stays read only.
- Giving reason codes to the 933 uncoded project raises.
- F34, the text-span scanner over output data.
- Deliberate data outputs (decision 5).

### Behavior

1. `decoy_engine.safe_output.SafeText`: a frozen type. Three constructors build one, and nothing
   else does:
   - `SafeText.const(literal)`: a string literal. An AST sentry checks that each argument is an
     `ast.Constant`.
   - `SafeText.template(literal, *, names=..., paths=..., counts=...)`: a literal template with
     named slots. A name slot goes through `approve_name` (decision 3). A path slot goes through
     the locator rule (decision 7). A count slot takes an `int`. The template itself is checked
     by the same AST sentry.
   - `approve_name` (`reasons/_record.py:84-97`) checks shape only, so a cell value such as a
     person's name passes it. The literal sentry therefore also rejects any slot argument that
     the AE2 tagger tags VALUE or EXC. A slot takes names from config and schema objects only.
   - `render_failure(exc)`.
2. `render_failure(exc) -> SafeText` picks one of four named helpers. Each is a separate function,
   so a mutation can target each one:
   - `_render_coded(exc)`: a `DecoyError` with a reason code gives its registry summary plus its
     refs, through `SafeText.template`.
   - `_render_registered(exc)`: an uncoded project error whose class is in the value-free message
     registry gives its message.
   - `_render_cause(exc)`: anything else whose `__cause__` chain carries a coded error gives the
     outer type label plus the coded cause's summary.
   - `_render_label(exc)`: anything else gives the type label from `safe_error_type`.
   - If any helper raises, the renderer returns `_render_label(exc)`.
3. Where a coded error's refs come from. Today refs live only on `ReasonRecord`. The renderer
   must not call `capture_failure(exc)`: that function changes state (`reason_adapter.py:525-546`).
   With a failure scope open it calls `scope.capture`, so rendering a handled warning mid-run
   could become the run's primary failure. With no scope open, `_remember` writes onto the
   exception. Call `reason_from_exception(exc)` directly. It returns the captured record on a hit
   and classifies a miss without writing (`reason_adapter.py:278-286`). The renderer
   reads refs from `record.context.object_ref` and `record.context.storage_ref`
   (`reasons/_record.py:116-127`). These are already closed and approved. It reads no exception
   attribute directly.
4. `decoy_engine.safe_output.SafeRecordFilter`, a `logging.Filter` (stdlib logging cookbook,
   "Using Filters to impart contextual information"). It runs in `filter()`, before that handler's formatter:
   - an `args` item that is a `BaseException` becomes its type label;
   - replace cached `exc_text` on every record, even when `exc_info` is absent. With live
     traceback data, keep only the type label and file:line frames. Otherwise clear the cache.
     Clear `exc_info` before formatting. A stock formatter appends a populated cache on its
     own (Python 3.11 `logging/__init__.py:691-699`);
   - `stack_info` is kept, because it holds only code locations.
   The engine attaches it in `_new_engine_handler`. It is public so a host attaches it to its own
   handlers.
5. Keep `fail(ctx, exc)`. It uses the original exception for the exit category and reason
   (`cli/run/_errors.py:159-215`). Build and check its outbound `SafeText` after classification.
   AC1 migrates every `emit_error` message, including forwarded messages and ordinary setup
   refusals (`cli/setup/__init__.py:125,128`). Use literals for fixed messages, templates for
   approved fields and `render_failure` for exceptions. Trace forwarded text back to its producer.
   Check messages in `emit_error`, the run failure path and the notify builder through one
   hook, `record_sink_miss` in `ui/output.py`. An absent optional notify summary stays absent. On a plain string,
   discard it. In tests, raise `TypeError`. In production, log the miss by type once. Emit the
   original exception's type label if available. Otherwise emit `SafeText.const("Operation failed.")`.
   AC2 changes `_host_only` to use `urlsplit(url).hostname` with the existing unknown-host
   fallback. Use this one helper for URL target displays, including warnings and results.
6. A shrink-only ratchet on exception-text copies in both repos.

### Registry contents when AC1 merges

AE1 seeds the registry by rule, not by hand: a project class is admitted when every raise of it
has no EXC or VALUE tag and sits in no function with an exception-text copy. Measured at engine
`3426165fb` (`engine-registry-share.tsv`, 2523 raise sites with a message).

`registry_share.py` follows factory calls. A raise whose callee is a function
(`raise violation(_P.CODE, ...)`, `raise _refuse(...)`, `raise deny(...)`) counts as coded when
the factory takes a `code`, `reason` or `ReasonCode` parameter, or when its returned call passes
`code=` or `reason=`. Otherwise it resolves to the one project class the factory returns. The
`route` column says which rule applied. Round 1 missed this and put the factory raises in the
label bucket. The script now finds 347 factory raises; Dennis's recompute counted 348.

| Outcome under the renderer | Direct | Factory | Sites | Share |
|---|---:|---:|---:|---:|
| coded: registry summary plus refs | 1021 | 263 | 1284 | 50.9% |
| uncoded, class admitted: own message kept | 269 | 12 | 281 | 11.1% |
| type label only | 886 | 72 | 958 | 38.0% |

58 of 112 project classes are admitted. The 958 label-only sites split into three groups:

- 644 stdlib or third-party classes: `ValueError` 366, `AssertionError` 100, `TypeError` 87,
  `OSError` 25, `PydanticCustomError` 22 and others.
- 242 raises of excluded project classes: `SignedEvidenceError` 126, `PhaseContractError` 33,
  `ModelPackLoadError` 15, `NameHintLoaderError` 13, `UnifiedSliceInvariantError` 11 and others.
- 72 factory raises that do not resolve to one class: `deny` 23, `from_exception_data` 11,
  `from_problems` 10, `_wrap_sftp_error` 7 and others.

The round 1 claim that most label-only sites are stdlib invariants does not hold. Only 187 are
`AssertionError` or `TypeError`. The 366 `ValueError` raises are spread over `execution/` (64),
`profile/` (33), `_progress_events.py` (23), `generation/` (20) and others, and some are reached
from config. AE5 removes tainted raises, so more classes are admitted, and re-runs
`registry_share.py` to record the new table.

Gate rule, in two parts:

1. The AC1 PR states this table at the pinned engine head. It lists the label-only sites
   reachable from a user-config or user-input error and admits each one or gives it a template.
2. A test enforces it: the AC4 usability cells (acceptance test 4) run one bad-config or
   bad-input scenario per command group and assert the output carries a reason code or a
   registered message, not only a type label.

### Design notes

- Established practice. The OWASP Logging Cheat Sheet says to exclude sensitive data and
  exception detail from logs and to sanitize at the logging layer, not at each call. Python's
  `logging.Filter` on a handler is the stdlib place for that; structlog does the same thing with
  a processor chain. We use the stdlib filter because the engine does not use structlog and a
  host's handlers are stdlib handlers. RFC 9457 is the model for error text: a stable type and
  title from a registry, and separate closed occurrence fields. `ReasonRecord` already follows it.
- `SafeText` follows "parse, don't validate": a sink takes a type that only safe constructors
  make. In the CLI the type is checked at run time, because there is no mypy gate.
- One place per fact: reason summaries stay in the registry and the renderer reads them; the
  value-free message registry is the only list of classes whose message may print. The engine does
  not know the CLI.
- No new flags that switch behavior. The renderer has one output per exception.

### Pre-mortem

Assume the program shipped and a leak was still found. Likely causes, and what stops each:

| Failure | Stopped by |
|---|---|
| A platform or host handler prints engine records raw | `SafeRecordFilter` is public; the corpus attaches a host handler; platform adoption is a parked F31 slice |
| A new command prints `str(exc)` in its own way | runtime `SafeText` checks; AC3 ratchet; the CLI corpus walks the live command tree |
| A builder writes `SafeText.const(str(exc))` | the literal-only AST sentry |
| A builder passes a cell value as a `names=` slot | the literal sentry rejects a VALUE or EXC tagged slot argument; residual risk: a value reached through a name the tagger does not tag, such as an untyped helper's return |
| Rendering a handled error changes the run's primary failure | the renderer reads through `reason_from_exception` only; a test renders inside `failure_scope()` |
| A registered class gains a value interpolation | the registry sentry |
| A V2-LOG copy carries a value to a sink | not stopped in V1; listed in the triage files and counted by the ratchet |
| Error text becomes too vague and users cannot fix their config | the registry table gate on AC1; templates keep names and paths; coded summaries |
| The corpus passes because a failure shape never triggered | class 8: each cell asserts its reason code before absence; red-on-main cells named |
