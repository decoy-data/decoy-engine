## Part 1. Audit

### Scope and threat model

Only accidental leaks are in scope. A leak is a cell value, an expression's text, or a secret
that reaches an outbound text stream through an ordinary code path. Hostile in-process objects
(a crafted `__str__`, a malicious plugin) are V2.

Outbound text streams:

- engine log records (file handler, console handler, any host-attached handler);
- exception messages (every engine message is outbound, because the CLI prints it);
- `warnings.warn` text;
- report documents (run result, progress events, telemetry, records, scan and profile output);
- CLI stdout, stderr and the `--json` document;
- CLI notify payloads, per-channel results, delivery warnings and CLI log handlers.

Engine handler output includes cached traceback text. A host formatter can populate
`record.exc_text` before the engine handler sees the record.

### Method

1. `sites.py`: an AST walk over every `.py` file under engine `src/decoy_engine` (963 files) and
   CLI `src/decoy` (198 files). Each site gets a class (raise, log, warn, terminal,
   exception-text copy, `__str__`). Each interpolated expression gets a tag: EXC (an
   except-bound name or exception text), VALUE (a name such as `value`, `cell`, `row`, `expr`,
   `text`), LOC (a path, URI or DSN name), IDENT (any other name). A site's risk is its worst
   tag: leak (EXC or VALUE), review_loc (LOC), safe_ident (IDENT only), safe_const (no
   interpolation).
2. `copies.py`: every copy of exception text and the sink it flows to. An exception name is an
   `except ... as NAME` binding, or a function parameter named `exc`, `err`, `e`, `error`, `ex`,
   `exception`, `cause` or `inner`, or annotated with an exception type. A copy is `str()`,
   `repr()` or `format()` of that name, an f-string `{NAME}`, `% NAME`, a text attribute
   (`.args`, `.message`, `.msg`, `.detail`, `.raw_message` and others), or a traceback
   formatter.
3. `registry_share.py`: which raise sites keep their message under the registry rule (AE1).
4. A read of every existing choke point and sentry, listed below.

The site counts (step 1) are heuristic. Samples of 30 "leak" raises showed many false positives:
names such as `key`, `x` and `default` that hold config identifiers, and coded raises whose fields
are only locations. Read the raise and terminal "leak" rows as an upper bound. The copy counts
(step 2) have high precision, because the pattern is exact.

## Part 2. Plan

### Guarantee

Under default flags, a planted secret placed in a cell, an expression literal, a config default or
a connection secret (including a notify URL password) does not appear in any engine or CLI outbound text stream, for each failure
shape in the canary corpus, through each entry point in the corpus. Three sinks are closed by
construction for every failure, not only corpus shapes: the CLI `decoy run` error text, every
`emit_error` message, and every record that passes an engine handler (exception args and
`exc_info` and cached `exc_text`). Notify results expose only the hostname for URL targets. The copy ratchet stops new exception-text copies in both repos.

Not guaranteed: the copies left after AE5 and AC3 (49 engine, 50 CLI). Each is listed as V2-LOG
in `engine-triage.tsv` and `cli-triage.tsv`, with its sink. They stay counted by the ratchet.

### Non-goals

- Hostile in-process objects (V2).
- E0b, the `decoy-safe-output/v1` wire line. It stays parked.
- The Platform slices of F31. They stay parked.
- The 99 V2-LOG copies above.
- Engine DEBUG log-file traceback stripping beyond `SafeRecordFilter`. Admin logs are V2 under
  the V1 bar; logged V2-LOG.
- Pre-formatted f-string log messages (`internal/memory.py:54`) and `str(exc)` passed as a `%s`
  argument. The filter cannot see them. `test_log_interpolation.py` stays their guard.
- New reason codes. The registry stays read only.
- Giving reason codes to the 933 uncoded project raises.
- F34, the text-span scanner over output data.
- Deliberate data outputs (decision 5).

### Behavior

Items 1 and 2 are superseded for AE1 by "AE1 rev 2 (2026-11-24)".

1. `decoy_engine.safe_output.SafeText`: a frozen type. Three constructors build one, and nothing
   else does:
   - `SafeText.const(literal)`: a string literal. An AST sentry checks that each argument is an
     `ast.Constant`.
   - `SafeText.template(literal, *, names=..., paths=..., counts=...)`: a literal template with
     named slots. A name slot goes through `approve_name` (decision 3). A path slot goes through
     the locator rule (decision 7). A count slot takes an `int`. The template itself is checked
     by the same AST sentry.
   - `approve_name` (`reasons/_record.py:84-97`) checks shape only, so a cell value such as a
     person's name passes it. The literal sentry therefore also rejects any slot argument that
     the AE2 tagger tags VALUE or EXC. A slot takes names from config and schema objects only.
   - `render_failure(exc)`.
2. `render_failure(exc) -> SafeText` picks one of four named helpers. Each is a separate function,
   so a mutation can target each one:
   - `_render_coded(exc)`: a `DecoyError` with a reason code gives its registry summary plus its
     refs, through `SafeText.template`.
   - `_render_registered(exc)`: an uncoded project error whose class is in the value-free message
     registry gives its message.
   - `_render_cause(exc)`: anything else whose `__cause__` chain carries a coded error gives the
     outer type label plus the coded cause's summary.
   - `_render_label(exc)`: anything else gives the type label from `safe_error_type`.
   - If any helper raises, the renderer returns `_render_label(exc)`.
3. Where a coded error's refs come from. Today refs live only on `ReasonRecord`. The renderer
   must not call `capture_failure(exc)`: that function changes state (`reason_adapter.py:525-546`).
   With a failure scope open it calls `scope.capture`, so rendering a handled warning mid-run
   could become the run's primary failure. With no scope open, `_remember` writes onto the
   exception. Call `reason_from_exception(exc)` directly. It returns the captured record on a hit
   and classifies a miss without writing (`reason_adapter.py:278-286`). The renderer
   reads refs from `record.context.object_ref` and `record.context.storage_ref`
   (`reasons/_record.py:116-127`). These are already closed and approved. It reads no exception
   attribute directly.
4. `decoy_engine.safe_output.SafeRecordFilter`, a `logging.Filter` (stdlib logging cookbook,
   "Using Filters to impart contextual information"). It runs in `filter()`, before that handler's formatter:
   - an `args` item that is a `BaseException` becomes its type label;
   - with live `exc_info`, replace `exc_text` with the type label and file:line frames.
     Clear `exc_info` before formatting. Without live traceback data, discard any untrusted cache.
     **V2-LOG** Each later filtered handler must keep the sanitized `exc_text` from the first handler. A stock formatter appends a populated cache on its
     own (Python 3.11 `logging/__init__.py:691-699`);
   - `stack_info` is kept, because it holds only code locations.
   The engine attaches it in `_new_engine_handler`. It is public so a host attaches it to its own
   handlers.
5. Keep `fail(ctx, exc)`. It uses the original exception for the exit category and reason
   (`cli/run/_errors.py:159-215`). Build and check its outbound `SafeText` after classification.
   AC1 migrates every `emit_error` message, including forwarded messages and ordinary setup
   refusals (`cli/setup/__init__.py:125,128`). Use literals for fixed messages, templates for
   approved fields and `render_failure` for exceptions. Trace forwarded text back to its producer.
   Check messages in `emit_error`, the run failure path and the notify builder through one
   hook, `record_sink_miss` in `ui/output.py`. An absent optional notify summary stays absent. On a plain string,
   discard it. In tests, raise `TypeError`. In production, log the miss by type once. Emit the
   original exception's type label if available. Otherwise emit `SafeText.const("Operation failed.")`.
   AC2 changes `_host_only` to use `urlsplit(url).hostname` with the existing unknown-host
   fallback. Use this one helper for URL target displays, including warnings and results.
6. A shrink-only ratchet on exception-text copies in both repos.

### Design notes

- Established practice. The OWASP Logging Cheat Sheet says to exclude sensitive data and
  exception detail from logs and to sanitize at the logging layer, not at each call. Python's
  `logging.Filter` on a handler is the stdlib place for that; structlog does the same thing with
  a processor chain. We use the stdlib filter because the engine does not use structlog and a
  host's handlers are stdlib handlers. RFC 9457 is the model for error text: a stable type and
  title from a registry, and separate closed occurrence fields. `ReasonRecord` already follows it.
- `SafeText` follows "parse, don't validate": a sink takes a type that only safe constructors
  make. In the CLI the type is checked at run time, because there is no mypy gate.
- One place per fact: reason summaries stay in the registry and the renderer reads them; the
  value-free message registry is the only list of classes whose message may print. The engine does
  not know the CLI.
- No new flags that switch behavior. The renderer has one output per exception.

Status: plan. "AE1 rev 2.1" below amends this section after Dennis R1. This section replaces the AE1 parts of "Behavior" items 1 and 2, "Registry

#### Why AE1 changes

AE1 (engine PR #793, head `35bf22559`) failed three code reviews. Round 1 (Dennis) found that the
registry rule read only `raise Call`, that the literal sentry matched only the bare name, and that
the registry covered only the engine. Codex round 2 found eight more shapes. Codex round 3 found
five more at `35bf22559`: an import alias erased by a local rebinding in another function,
factory return alternatives, a saved bound `.const` method, a local `@` filename withheld, and an
alias chain longer than the resolver's six passes.

The diagnosis holds. A class entered the registry, and a string became `SafeText`, when a static
proof said the code was safe. Each shape the proof did not model counted as safe, so every miss
failed open. Each round fixed the named shapes and the next round found new ones, because Python
has more ways to bind a name than a hand-written analyzer models. Recurring defect 5 limits a
guard scanner to listed accidental shapes, but here the scanner is the only thing between a cell
value and the terminal, so an unlisted shape is a leak, not a known gap.

Rev 2 inverts the default. Text prints only when the running program proves where it came from.
Anything the check cannot prove is withheld. The static sentries stay, but only to reject code
early. Nothing passes because a sentry found no problem.

#### Established solutions

#### Guarantee and non-goals

Guarantee: `render_failure(exc)` returns only (a) text from a string constant written in engine or
CLI source, (b) a name minted by a reviewed function through `SafeName.identifier`, (c) a local
path that passed the `SafePath.local` parser, minted by a reviewed function, (d) a registry
summary and refs for a reason code, or (e) a type label. An unproven value is withheld, never
printed.

Non-goals: deliberate evasion inside engine code (`object.__new__(SafeText)`, writing
`__dict__`, editing `co_consts`, a crafted pickle; V1 threat model and recurring defect 5); a cell
value that a reviewed mint function passes on as a name (the review of the allowlist covers it);
Python runtimes other than CPython.

#### Design

1. `SafeText.const(text)` and `SafeText.template(fmt, *, names=None, paths=None)` (superseded by 2.1) check the
   argument at run time. `text` (or `fmt`) must be a `str` and must be the same object (`is`) as
   a `str` constant in the calling frame's `f_code.co_consts`. Verified on CPython 3.10.20 and
   3.11.2: a literal, a folded `"ab" + "cd"`, an implicit concatenation, an f-string with no
   field, a literal inside a lambda or comprehension all pass. A row value, an f-string with a
   field, a wrapper function's parameter, `functools.partial`, a saved alias of `const`, a saved
   bound method of an instance, and a module-level constant read by name all fail. One known
   pass: a runtime value that CPython interned to the same object as a constant in the caller
   (single characters such as `"a"`). The printed text then equals a literal in that code, so
   nothing new is disclosed. The parameter type is `LiteralString` for readers.
2. A failed check never prints the argument. Under the strict switch it raises `TypeError` that
   names the calling code location only. Without it, `const` and `template` return the module's
   `WITHHELD` singleton and log one value-free warning per code location, like the CLI's
   `record_sink_miss`. The renderer treats `WITHHELD` as no message, so dispatch falls to the
   cause or the label.
3. The strict switch is a private module flag. The engine test `conftest.py` turns it on with an
   autouse fixture; the CLI test conftest does the same after AC0. Production never sets it.
4. Slots take typed values only. `names=` takes `SafeName`, `paths=` takes `SafePath`. A plain
   `str`, an `int`, or any other type is withheld (`TypeError` under strict). The `counts=` slot is
   dropped; no AE or AC slice needs it, and a later slice that does adds a `SafeCount` with the
   same caller gate.
5. (superseded by 2.1) `SafeName.identifier(name)` runs `approve_name` and `SafePath.local(path)` runs the parser in
   item 8. Both also check the caller: the key `module:function` (from `f_globals["__name__"]`
   and `f_code.co_name`) must be in `MINT_CALLERS`, a frozenset in `_safe_text.py`. A key not in
   the set is withheld. On CPython 3.10 the key cannot tell apart two functions with the same
   name in one module; the sentry in item 10 rejects such a duplicate for any listed key. The
   private `_mint` used by the renderer for refs uses the same gate.
6. (superseded by 2.1) The CLI adds its keys once through `register_mint_callers(keys)`, a public engine function
   that accepts only `decoy_cli.` keys and can run once per process. A CLI sentry pins the call
   site and its key list (AC1).
7. Exceptions carry `SafeText` instead of being trusted by class. `DecoyError.__init__` keeps a
   `SafeText` first argument in `self._safe_text` and passes `str(text)` on to `args`, so
   `str(exc)` and pickling behave as today. `safe_text_of(exc)` returns that `SafeText` or `None`.
   `_render_registered` becomes `_render_declared`, which reads only `safe_text_of(exc)` and never
   calls `str(exc)`. `VALUE_FREE_CLASSES` and its sentry are deleted. A class that overrides
   `__str__` or `__repr__` no longer matters, because the renderer never calls either. To avoid an
   import cycle, `_error_base.py` imports `_safe_text` inside `__init__` (superseded by 2.1).
8. (superseded by 2.1) `SafePath.local(path)` rules, in order: `os.fspath`, must be `str`, printable, 1 to 512
   characters. A Windows drive or UNC path (`PureWindowsPath(s).drive` not empty) is local and
   printed. A leading `//` is withheld. If `urlsplit(s).scheme` is not empty: `file` with an empty
   or `localhost` netloc and no query prints the path part; any other scheme is withheld. A query
   or netloc is withheld. `#` and `@` in a local path are allowed. Probe results (both runtimes):

   | Input | Result |
   |---|---|
   | `/data/orders@2026.csv`, `relative/x.csv`, `report#1.csv` | printed |
   | `C:\data\x.csv`, `C:/data/x.csv`, `\\server\share\x.csv` | printed |
   | `file:///data/x.csv` | printed as `/data/x.csv` |
   | `s3://u:p@b/k`, `postgresql://u:p@h:5432/db`, `https://h/x?sig=abc` | withheld |
   | `//host/share/x`, `file://remote/x`, `/data/x.csv?token=1` | withheld |
   | `user:pw@host:5432/db`, `host:5432/db`, `str(Path("s3://u:p@b/k"))` (`s3:/u:p@b/k`) | withheld |
   | `orders:2026.csv` | withheld (reads as a scheme; accepted cost) |

9. `SafeText.__reduce__` returns a private reconstructor, so a `SafeText` survives the engine's
   process pool. It does not re-check provenance; a crafted pickle is out of scope.
10. Static sentries, reject only:
    - `test_safe_text_literals.py`: every attribute read of `.const` or `.template` (superseded by 2.1) on any
      receiver must be the function of a call whose first argument is a `str` literal. Any other
      use (saved, passed, called with a non-literal) is a finding, and so is
      `getattr(x, "const")` or `getattr(x, "template")`. The same rule covers
      `.identifier` and `.local` (superseded by 2.1) outside `MINT_CALLERS`, and `_mint` outside `_render.py`

      function, and a VALUE or EXC tag on a mint argument is a finding (recurring defect 10).
    These sentries find mistakes before review. The runtime check is the guarantee.
11. `UnknownReasonError` is raised after the `except KeyError` block closes, so `__context__` is
    `None` (recurring defect 3).

#### Path rules (B1)

`SafePath.local_display(path)` runs reject rules first, then accepts. `.drive` is never used.

1. `os.fspath`; must be `str`, printable, 1 to 512 characters, no leading or trailing whitespace.
2. Withhold any `?`.
   Rule 2b: withhold any `;` or `=`. Use the leaf's shared `_NAME_FORBIDDEN` from
   `reasons/_record.py:80`, moved verbatim. For paths only these two matched characters
   trigger 2b, so ordinary path separators and `orders@2026.csv` still pass.
3. Withhold a userinfo shape, `[^/\\]*:[^/\\]*@`, at the start or after any `/` or `\`. Dennis's
   rule anchors it after `//` or `\\`; any separator is stricter and also withholds
   `dir/u:p@h`.
4. Withhold `://` unless the string starts with `file:///` or `file://localhost/`; those print the
   path from its first `/` after the authority.
5. Withhold a leading `//`.
6. Accept a Windows drive path, `^[A-Za-z]:[\\/]`, or a UNC path, `^\\\\[^\\/@:?]+\\[^\\/@:?]+`
   (no `@`, `:` or `?` in host or share).
