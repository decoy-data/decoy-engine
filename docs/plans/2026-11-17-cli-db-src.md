## 1. Guarantee and non-goals

### 1.1 What this change promises

1. A pipeline config may declare a source `sources.<table>: {type: postgres, connection_ref:
   <secret ref>, schema: <ident>, table: <ident>}`. The config holds no host, user, password
   or database name. The whole libpq connection string is behind `connection_ref`, an F13
   secret reference (`env:NAME` or `file:/PATH`) resolved through the engine's default secret
   provider registry.
2. `decoy run` stages every postgres-sourced table of the pipeline from **one** Postgres
   snapshot (one transaction, one REPEATABLE READ snapshot) to Parquet in an engine protected
   scratch directory. Then it runs the unchanged file pipeline over that Parquet. The scratch
   is removed on every exit path, including Ctrl-C and a failed run.
3. CONFIG-EXPLICIT holds for Postgres. Every column of each relation must be declared in
   `tables[].columns` (or by the declared-column rules already in the engine), and every
   declared column must exist. The check runs on the Postgres catalog **before any data row
   is read**. The snapshot itself refuses if the relation's columns changed between that check
   and the snapshot.
4. Value-free. The connection string, the password, the host and the resolved secret never
   appear in an error, a log line, the run card, `--json` output, the run folder, telemetry or
   a traceback chain (`__cause__` and `__context__` are `None` on every refusal). Errors carry
   a registered reason code and a config location (`sources.<table>.<field>`) or a relation
   location (`schema.table[.column]`). The reference text is not echoed either (F13 practice).
5. The engine never fetches the DuckDB `postgres` extension during a run. `decoy setup
   --postgres` installs it once into a Decoy-owned directory. A run with the extension absent
   is refused with exit 1 and a hint that names that command.
6. Both repositories get a merge-required `pg-gate` CI job. It runs every `pg_integration`
   test against a GitHub Actions Postgres service container and fails on any skip.

### 1.2 Non-goals (findings here become follow-ups, not blockers)

- More than one Postgres connection per pipeline (refused in V1, owner Q3).
- Consistency between a Postgres table and a file table (documented, not guaranteed).
- A `WHERE` filter, a column subset, a custom `ORDER BY`, a SQL query or a view expression as a
  source. The relation is read whole. Subsetting stays the subset stage's job.
- `decoy validate`, `decoy ci check` and `decoy validate preflight` opening a database
  connection (owner Q4). They keep the local, no-network posture of
  `C:src/decoy/cli/preflight.py:362`.
- Postgres as a target (row 86), Postgres for `decoy scan`, `--evidence-out` with a Postgres
  source (owner Q8), the F13 external adapters (row 83), the platform.
- Streaming straight from Postgres without staging (V2). The staged Parquet already feeds the
  chunked and out-of-core routes.
- Hostile in-process attackers or a hostile database server (V1 threat model: accidental leaks
  only).

## 4. Behaviour

### 4.1 Config

```yaml
sources:
  customers:
    type: postgres
    connection_ref: env:DECOY_PG_DSN      # whole conninfo or URI is in the variable
    schema: public
    table: customers
  orders:
    type: postgres
    connection_ref: env:DECOY_PG_DSN
    schema: public
    table: orders
tables:
  - name: customers
    columns: [...]      # every column of public.customers; passthrough allowed
  - name: orders
    columns: [...]
```

`PostgresSource` (new member of `SourceDescriptor`): `type: Literal["postgres"]`,
`connection_ref: str` (required, marked `x-decoy-locator`, added to `SOURCE_LOCATOR_FIELDS`),
`schema: str`, `table: str` (both required; no default from the table key, in the
CONFIG-EXPLICIT spirit). `extra="forbid"`, strict strings, `hide_input_in_errors=True`. The
model checks shape only (non-empty strings). The identifier rule, the reference grammar and the
one-connection rule are a plan check (4.2), because `config` cannot import `connectors` or
`secret_providers` (same or lower tier in `.importlinter`).

### 4.2 Compile-time check (`decoy validate`, compile layer)

New `plan/checks/_postgres_sources.py`, run in the compile layer, raises the first of:

- `source_postgres.identifier_invalid` at `sources.<t>.schema` or `.table` when the name fails
  the primitive's identifier rule (checked by building a `RelationSelection`, the one rule).
- `source_postgres.multiple_connections` at `sources.<t>.connection_ref` when two postgres
  sources carry different `connection_ref` text.
- the existing bad-reference refusal when `connection_ref` does not parse (`parse_ref`), and
  the existing unknown-provider refusal when its scheme is not in the default registry (so
  `vault://` is refused, as F13 already pins).

No secret is read and no connection is opened at compile time.

### 4.3 Engine staging

New public context manager `stage_postgres_sources(config, settings) ->
Iterator[StagedSources]` in `execution/pipeline/_postgres_source.py`:

1. No postgres source: yields the config unchanged and opens nothing.
2. Resolves `connection_ref` once with `prepare_secret(..., requirements=(POSTGRES_DSN_V1,))`.
   The new requirement `postgres-dsn-v1` accepts non-empty UTF-8 without NUL up to 8 KiB and
   takes the material raw when the reference names no encoding (owner Q6). The prepared secret
   is closed as soon as the `SecretStr` is built.
3. Reads the catalog columns of every relation through the new public
   `relation_columns(config, relations)` in `postgres_snapshot` (same offline extension load,
   same read-only ATTACH, same ambiguity rules, no data row).
4. Runs `prepare_declared_sources(DeclarationRequest.for_supplied(config, schemas))` on those
   names. An undeclared column, a declared-but-missing column or an undeclared table raises the
   existing `source_file.*` refusals, before any row is read.
5. Opens `protected_scratch_dir(settings.scratch_parent, prefix="decoy-pg-")`, then calls
   `snapshot_tables_to_parquet` once with one `RelationSelection` per table, `columns` equal to
   the checked catalog list and the new field `whole_relation=True`. Inside the snapshot
   transaction, `_check_types` refuses with the new `connector.relation_shape_changed` when the
   relation's column set differs from the selection. This closes the check-then-snapshot
   window.
6. Yields `StagedSources(run_config=..., declared_config=...)`. `run_config` is the config with
   each postgres descriptor replaced by `{type: file, format: parquet, path: <staged>}`.
   `declared_config` is the input config, unchanged, for records. On exit the scratch directory
   and the DuckDB spill are removed.

`PostgresSourceSettings` (frozen, strict types): `extension_directory`, `scratch_parent`
(optional), `memory_limit`, `threads`, `row_group_size=100_000`, `statement_timeout_s=3600`,
`deadline_s=21600` (owner Q7).

`POSTGRES_SOURCE_USAGE_CODES` (public frozenset of existing reason refs): the connector codes
that mean "fix the config, the database objects or the setup": `relation_not_found`,
`column_not_found`, `ambiguous_name`, `unsupported_column_type`, `value_not_representable`,
`extension_unavailable`, `extension_untrusted_location`, `relation_shape_changed`. The CLI maps
these to exit 1 and every other connector code to exit 3. The engine owns the classification;
the CLI copies no code string.

Any engine reader that meets an unstaged `type: postgres` descriptor raises
`source_postgres.unstaged` at `sources.<t>.type`. The refusal sits in `build_profile_source`,
so `source_columns`, `run_pipeline`, profiling and capacity all reach it. A run route never
treats the table as empty.

`install_postgres_extension(directory)` in the new `connectors/postgres_extension.py` is the
only engine function that may fetch the extension (DuckDB `INSTALL postgres` into that
directory, signature checks on). `postgres_extension_installed(directory) -> bool` checks
without network. `postgres_snapshot` keeps its offline guarantee.

Hardening of the primitive (defect class 3): every `raise PostgresSnapshotError(...) from None`
inside an `except` block (`src/decoy_engine/connectors/postgres_snapshot.py:242`, `:256`,
`:327`, `:408`, `:492`, `:509`, `:513`, `:516`) moves after the block closes, so DuckDB's
exception text (which can echo the connection string) never rides as `__context__`.

### 4.4 CLI

- `decoy run` (plain and `--chunked`): in `prepare`, after the mask-secret guard and the layout
  refusals and before the DuckDB staging block, when the raw config has a postgres source: run
  `check_static_before_acquire` on the raw config, enter the engine `stage_postgres_sources` on
  the run's `ExitStack`, then continue as the DuckDB path does. The full gate
  (`check_before_run`) runs on `run_config`, so preflight and capacity see real Parquet sizes.
  `ctx._ev_config_dict` keeps `declared_config`, so no scratch path reaches a record.
- `--duckdb-source` naming a table keeps its behaviour (the flag replaces that table's source
  before staging). Staging handles the postgres sources that remain (owner Q9).
- `--evidence-out` with a postgres source: refused, exit 1 (owner Q8).
- Every non-run reader (`decoy.mask()`, `demo`, `report fidelity --config`, `report
  integrity`, `detokenize`, `subset`, `scan --config`) meets the refusal in
  `_require_local_io_endpoints` (the existing I/O choke point) with `source_postgres.unstaged`,
  exit 1. A reader that bypasses it reaches the engine refusal (4.3).
- `decoy validate`, `ci check`, `validate preflight`: the config and compile layers check the
  postgres source. Preflight keeps its existing "non-file type; skipping local file check" and
  "capacity not checked" passes. No connection (owner Q4).
- `decoy setup --postgres`: installs the extension into `$DECOY_HOME/duckdb-extensions`
  through the engine installer, prints the directory, exit 0. `--json` adds
  `{"postgres_extension": "installed" | "present"}`. A failure exits 3 with a fixed text.
- Exit codes: `exit_code_for` maps `PostgresSnapshotError` by `POSTGRES_SOURCE_USAGE_CODES`
  (1 or 3). `source_postgres.*` and secret-provider refusals are config errors (1). The run
  classifier in `cli/run/_errors.py` gets the same arm (held equal by
  `tests/unit/test_exit_code_for.py`).

## 5. Enumerations

### 5.1 Exit paths

- 0: snapshot staged, run completed, scratch removed (`C:src/decoy/cli/exit_codes.py:163`).
- 1: compile refusals (`source_postgres.identifier_invalid`, `source_postgres.multiple_connections`, bad or unknown secret reference); secret not resolvable (`env` unset, file unreadable or too open); `postgres-dsn-v1` material invalid; CONFIG-EXPLICIT refusals (`source_file.undeclared_column`, `source_file.declared_column_missing`, `source_file.undeclared_table`); any code in `POSTGRES_SOURCE_USAGE_CODES`; `source_postgres.unstaged` on a non-run command; `--evidence-out` with a postgres source.
- 3: `source_unreachable`, `catalog_read_failed`, `export_failed`, `deadline_exceeded`, `value_guard_failed`, `duckdb_unavailable`, and a failed `decoy setup --postgres` install.
- 5: capacity refusal from the post-staging gate, priced on the staged Parquet.
- 130: Ctrl-C during the snapshot or the run; the primitive interrupts DuckDB and the scope removes the scratch (`src/decoy_engine/fileaccess/_protected_dir.py:268`).

### 5.2 Routes

- Resident `run_pipeline` (plain `decoy run`): reads the staged Parquet through `read_source` (`C:src/decoy/cli/_sources.py:389`).
- `--chunked` and the automatic streaming route: Parquet chunks from the staged file (`C:src/decoy/cli/_sources.py:414`).
- Out-of-core FK route and the isolated subprocess route: the same staged `run_config`. The scope outlives the subprocess because it is entered on the parent's `ExitStack`.
- Subset and `--sample` stages: operate on the staged Parquet, unchanged.
- Engine entry with an unstaged postgres descriptor (a platform or library caller that skips staging): refused at `src/decoy_engine/profile/_readers.py:507`.
- Non-run CLI readers: refused at `C:src/decoy/cli/run/_execute.py:238`.

### 5.3 FK shapes

- Scalar FK between two postgres tables: both read in one snapshot, never torn (primitive gate 1, `tests/connectors/test_postgres_snapshot.py:71`).
- Composite FK whose child is a postgres table: its child columns count as declared (`src/decoy_engine/profile/_declared_columns.py:46`), so the catalog check accepts them.
- Self-referencing FK in one postgres table: one relation, one snapshot.
- FK between a postgres table and a file or generated table: no consistency promise across sources (non-goal, documented); masking FK semantics unchanged.

### 5.4 Descriptor fields

- `type`: `"postgres"`, the discriminator (`src/decoy_engine/config/_sources.py:343`).
- `connection_ref`: F13 secret reference; locator field, never echoed, never resolved before staging.
- `schema`: Postgres schema identifier; primitive rule, exact case.
- `table`: Postgres relation identifier (table, view, materialized view, partitioned or foreign table, as `_CATALOG_SQL` allows); exact case.
- No `path`, `format`, `columns`, `where` or `order_by` field (`extra="forbid"`).

### 5.5 Output surfaces

- stderr error line and the `--json` error object (`decoy-error-v1`): code plus location only.
- Run card and the `--json` success document: table names and row counts only; no scratch path, no reference text.
- Run folder records (RESULT document, run record): built from `declared_config` (`C:src/decoy/cli/run/_prepare.py:431`).
- Engine log lines: `postgres_snapshot published relations=%d` and `failed code=%s location=%s` (`src/decoy_engine/connectors/postgres_snapshot.py:522`), plus one new staging line with counts only.
- OTel telemetry: codes and counts only (existing CLI redaction sentries).
- `decoy setup --postgres` output: the extension directory path (a Decoy-owned path, not a secret).

## 6. Frozen contracts

- Exit integers 0 to 6 and 130 keep their meaning; no new exit code.
- `SourceDescriptor` gets one more union member. That is additive under the compatibility contract; existing configs parse and hash as before.
- `snapshot_tables_to_parquet` signature unchanged. `RelationSelection.whole_relation` defaults to `False`, so existing callers behave the same.
- `SecretRequirement` gets `implicit_encoding: str | None = None` as its last field; existing requirements are unchanged.
- Reason codes: four new codes (`source_postgres.identifier_invalid`, `source_postgres.multiple_connections`, `source_postgres.unstaged`, `connector.relation_shape_changed`), all `since=UNRELEASED`. Existing code specs (outcome, retry) are unchanged. `REGISTRY_VERSION` and the reason manifests are not touched; the release stamps them.
- `decoy-error-v1` schema and the `--json` success shapes snapshot are unchanged, except `decoy setup --json`, which gains one optional key (shape changelog entry in C2).
- New public engine names go on the frozen-surface map in the slice that adds them: `PostgresSource`, `PostgresSourceSettings`, `StagedSources`, `stage_postgres_sources`, `POSTGRES_SOURCE_USAGE_CODES`, `relation_columns`, `install_postgres_extension`, `postgres_extension_installed`, `POSTGRES_DSN_V1`.
- No cap, pin ceiling, ratchet, sentry baseline or allowlist count is raised (class 11).

## 10. Design notes

- Principles: one place per fact (identifier rule in the primitive, declared-column rule in
  `profile`, code classification in the engine, exit map in `exit_code_for`); dependency
  direction by layer (config stays shape-only because it cannot import `connectors`). Pattern
  followed: the CLI `--duckdb-source` stage-then-gate flow and the engine
  `execution/pipeline/` pre-run stages.
- New structure: one stage function. A second database source later would add its own
  `stage_*` beside it; nothing generic is built now. Typed context: `PostgresSourceSettings`
  instead of a long parameter list. No flag argument: `whole_relation` is a field on the
  selection model, read by the guard.
- Choke points.
  - Unstaged postgres descriptors. Engine: `build_profile_source` is the one reader dispatch;
    guard AT-E1; mutation: delete the postgres branch (the descriptor falls to
    `NotImplementedError` and AT-E1 fails on the code). CLI: `_require_local_io_endpoints` is
    the one I/O choke point; guard AT-C6; mutation: drop the postgres check (AT-C6 fails).
  - Pre-read declared check: inside `stage_postgres_sources`, before the scratch exists; guard
    AT-E4; mutation: move the check after the snapshot (the spy sees a `COPY`).
  - Value-free errors: the primitive raises outside `except`; guard AT-E3; mutation: restore one
    `from None` raise inside an `except` block.

## 15. Pre-mortem

- The `pg-gate` job passes with everything skipped because a module-level skip counts as a
  pass: the job lists the marked files (scope guard) and runs `junit_ran.py`, as the
  `determinism` job does.
- `INSTALL postgres` in the test fixture fails on a runner without network: the fixture fails
  under `DECOY_REQUIRE_PG=1` instead of skipping, so the job turns red, not green.
- The extension does not match the pinned DuckDB after a DuckDB bump: the load fails closed
  with `extension_unavailable`, and the guide tells the user to re-run `decoy setup
  --postgres`. DuckDB installs under a per-version folder, so old files do not shadow new ones.
- A builder weakens AT-E9 to check only the error text: the gate checks that logs, traceback
  chains and the staged listing are all asserted.
- `regression-gate` keeps running the docker-backed `pg_integration` tests on push. That is on
  purpose: its `-m` expression does not change, so `gates.sh` and the M5 agreement rule stay as
  they are. `pg-gate` is the merge-required lane.
- Large relations fill the system temp directory: `scratch_parent` follows the run's existing
  row staging, and capacity is priced on the staged Parquet by the full gate.
- DELIV changes `run/_prepare.py` while C1 is in review: C1 rebases after the DELIV CLI slices
  (Q10).
- The secret material stays as a Python `str` in `SecretStr` for the run: accepted under the V1
  threat model; V2 note.
