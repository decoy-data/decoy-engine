## 2. Established solutions

Search run (2026-11-22): Apache Beam `CombineFn`; Great Expectations validation results; AWS Deequ analyzers; dbt tests; Spark accumulators; streaming GROUP BY partial aggregation (DuckDB, Polars streaming); symmetric hash join; Spark `FileOutputCommitter`; the proxy pattern (Gamma et al., *Design Patterns*). In the codebase: `ValidatorCollector`, `OutputEvidenceAccumulator`, `_CallableSinkAdapter`.

- **Combine functions.** Beam's `CombineFn` (`create_accumulator`, `add_input`, `merge_accumulators`, `extract_output`) is the standard form for a check that sees elements one at a time and gives one result. Each validator becomes one fold of this form. The resident route calls it with one span; the streamed routes call it once per batch. Merge is not needed: every route delivers a table's rows in order, on one thread.
- **Exact count, capped sample.** Deequ computes checks from analyzer states that combine across partitions. Great Expectations reports `unexpected_count` (exact) beside `partial_unexpected_index_list` (a capped sample). This plan follows that split: the count is exact and the index list is a capped prefix.
- **Two-sided key checks in any order.** A symmetric hash join (Wilschut and Apers 1991) keeps state for both inputs and matches whichever side arrives second, so neither table must come first. The keyed folds follow it: parent keys go in a key map, child rows whose parent has not arrived go in a pending map, and each side probes the other. Both maps are reserved against one budget.
- **Validate before commit.** Spark's `FileOutputCommitter` and Decoy's `OutputPublish` (`src/decoy_engine/execution/_chunked_output_sink.py:128-178`) stage output and make it visible once, at the end. Decoy already has the correct pre-commit policy seam: `observed_commit` runs the post-scan gate at `src/decoy_engine/execution/_publication_observer.py:132-149` before its `try: sink.commit()` block. The validation session binds beside that gate and finishes there. A `ValidatorFailedError` therefore unwinds through `OutputPublish.__exit__`, which aborts the stage, without being mislabeled as a COMMIT failure.
- **Proxy at the write boundary.** A capability-preserving proxy observes `write` and, only when the inner sink has it, `write_batches`. Commit policy stays in `observed_commit`; the proxy's commit and abort methods only forward. This puts observation on the published-byte path without giving a legacy sink a method it did not have.

Custom code still needed: the fold form of each of the 11 validators, one session that owns them, and the sink proxy. No library computes Decoy's validator verdicts. The folds reuse the verdict code that exists today.

## 3. Guarantee and non-goals

After this row:

1. A `validators:` block never changes the route, with two named exceptions. A job with validators takes the route the same job takes without them: unified slice, auto-chunk (resident and streamed), full frame, mixed route, physical full-frame, mixed and generation drivers, sequential FK, out-of-core FK, multi-table split, and generation with a sink. The exceptions: (a) quarantine with the `validation_fail` trigger removes rows, so it stays resident (code `quarantine_enabled`, unchanged); (b) a plain callable sink (not a `TransactionalSink`) cannot take back a written table, so a job with validators and a callable sink takes a resident route, which validates before the first write (new route code `validators_need_transactional_sink`).
2. Every configured validator runs on the bytes the route publishes. It reads the output, the source, or both, as its shape says (section 4).
3. On the streamed and bounded routes, validator state is bounded: per finding at most `FINDING_INDEX_CAP` row indices plus counters; for `leak_check` at most one source batch per table in flight; for a keyed check one key map and one pending map, reserved against the validation session's `resolve_budget` ceiling, with a coded refusal when they would not fit. This ceiling is separate from, and not charged to, `GenerationBudgetLedger`.
4. A failing validator fails the job (`ValidatorFailedError`, CLI exit 3) and nothing is published. On a transactional sink route the bound session finishes in `observed_commit`, before commit evidence and the inner commit; the ordinary publish unwind aborts the stage. On a resident route `execute_route` finishes it before `settle` and before a callable receives any table.
5. `quality_metrics["validation"]` is the one result. One function (`ValidationSession.finish`) builds it, on every route; `execute_route` stores it. The report is a function of (config, published bytes): the same at any chunk size, in any table order, and on any route that publishes the same bytes.
6. The run card and `decoy run --json` show every configured check with its result (passed, failed or skipped), including passes (S4).
7. `leak_check` records each column and table it does not check, with a registered code. A column named in `columns:` that it skips raises a `QualityWarning` and shows on the run card (S4). The run still exits 0, as the audit asks.

Non-goals: quarantine on the streamed routes (row removal after a streamed write needs its own design); new validator kinds; any verdict rule change (thresholds, `TRANSFORMATIVE` classes); `post_validation` and `fidelity_report` routing (separate rows); `decoy validate` running validators on data; `generate_tables_streamed` (`src/decoy_engine/generation/_plan_entry.py:290`), the generation-only entry that takes no `validators:` block and does not go through `run_pipeline`.

### Exit paths

1. All validators pass: the report is built; the run goes on to commit (sink) or returns (resident).
2. A validator fails and quarantine does not cover it: `finish` raises `ValidatorFailedError(report)`. On a transactional sink route this happens at the start of `observed_commit`, before its commit-failure recorder and before `sink.commit()`. The exception unwinds through the existing publish context, which calls `observed_abort`; nothing is committed and the validator refusal is not recorded as a COMMIT failure. CLI exit 3.
3. A validator fails and quarantine `validation_fail` is configured: resident route only (the D8 path, `_pipeline_finalize.py:410-470`, unchanged).
4. Parameter error (bad regex, missing `allowed_values`, unknown validator, `leak_check` naming a generate table): raised when the session opens, before any source read, as today (out-of-core does this at `_validate_batch.py:203-205`).
5. `leak_check` with no source for a table in scope: `ValueError` as today (`_leak_check.py:236-241`), raised at open.
6. New refusals. Each is a `ValidatorStateError` (a `DecoyError`) with a registered runtime code, raised after any `except` block closes:
   - `validator_key_state_over_budget`: the key map plus pending map estimate exceeds the key-state budget. Checked before the first scoped batch is written, and again as the maps grow.
   - `validator_source_pairing_mismatch`: the source rows read for a `paired` fold differ in count from the published rows of that table.
   - `validator_table_not_observed`: at commit, or before a resident route returns, a table in a validator's scope published rows the session did not observe (counts differ), or the session never finished. This is the construction guard for guarantee 2.

### Routes and what each one feeds the session

`execute_route` (`src/decoy_engine/execution/_pipeline_route_dispatch.py:59-105`) binds the session beside `bind_gate` and wraps `ctx.sink` once before dispatch. After the route returns and before `settle`, it feeds every table in `result.outputs` that has no folding observer yet, then calls `finish`. A streamed route normally finished already in `observed_commit`; `finish` is idempotent. After `settle`, the same choke point calls a plain callable once per resident output table. No route-specific driver owns completion.

Observation is per table, not per run. The first complete observer of a table owns its folds and records the table as folded. Any later observer of that same table only counts rows and verifies identity; it never adds the rows to a fold again. Therefore a split run can fold a streamed table through the proxy and a resident table through the choke point, while a resident table later handed to a callable is only count-checked. V4 has a split row that would double the findings if this rule regressed.

The source for a `paired` fold on a proxy route comes from the run's source view: a resident `pa.Table` is sliced at the published offset (no copy); a lazy source is read a second time, scoped columns only, one batch at a time. A sequential table supplied only by `source_loader` is different: `resolve_sequential_loader` already exposes one `tee` callback at `_pipeline_sources.py:127-159`. `execute_sequential_route` composes the post-scan and validation tee callbacks, and the validation tee projects only the paired columns from the one resident table the loader returned into protected scratch. The route does not call `source_loader` a second time and does not keep a second whole-table copy. The fold later reads that narrow tee in batches. V5 counts loader calls and fails unless each table is loaded once. Out-of-core already holds `raw_batch` at `yield out`, so it feeds `observe_pair` there and marks the table as paired-fed; the resident choke never feeds `paired` for that table again. `leak_check` never checks FK child columns (`_leak_check.py:242-243`), the only columns the join rewrites, so `out` at `yield out` carries the published values of every column it checks.

### Output surfaces (byte and shape changes; each on a changelog `Breaking:` line)

1. **Route.** A job with validators runs the route it runs without them, so its output bytes are that route's bytes. The differences between routes are the ones already listed in `tests/parity/SEMANTIC_DIFFERENCES.md` (for example `hash` and `categorical` Unicode normalization on the native kernels). A validator now judges the bytes that are published.
2. **`ValidatorFinding`** gains `failing_row_count: int` (exact). `failing_row_indices` holds the first `FINDING_INDEX_CAP` = 10,000 failing positions in row order. When quarantine with `validation_fail` is configured, the list is complete, because quarantine removes those rows. The cap depends on the config, never on the route.
3. **`ValidationReport`** gains `results: tuple[ValidatorResult, ...]`, one per configured entry, in order. `findings`, `passed` and `validators_run` keep their meaning.
4. **`elapsed_ms`** is the summed fold time across the run (it was the time of one call).
5. **`detail`** strings are built from the totals at `finish`. The out-of-core regex swap (`_validate_batch.py:242-255`) goes away. The wording does not change.
6. **`parent_window_respected`** parses with one format per table column (section 5). For a column whose values all match the first value's format, verdicts are unchanged. For a column with mixed formats, values that do not match the first value's format now parse as `NaT` on every route (they already did on full frame, where the first value set the format for the whole column), so a mixed-format column gives the full-frame verdict at any chunk size.
7. **Plan hash.** The physical plan hash no longer includes the validator count (`physical/_inputs.py:333`).
8. CLI: a `Checks` fact on the run card and a `validation` member in `decoy run --json` (S4).

## 5. Design notes

- **One fold per validator, one session per run.** Each validator module exports a fold class with `add(span: RowSpan)` and `finish() -> tuple[ValidatorFinding, ...]`. `RowSpan` is a frozen dataclass: row offset, output batch, source batch or `None`. The old function name stays as the registry entry point (open the fold, add one span, finish), so the registry signature and existing imports keep working. There is no second copy of any verdict rule.
- **The session is the only caller of folds.** `ValidationSession` (`validators/_session.py`, exported from `decoy_engine.validators`) is bound once in `execute_route` with the config, source view and validation-state ceiling. Entry points: `observe(table, output, source)` (a complete resident table), `observe_published(table, batch)` (the proxy), `observe_pair(table, source, output)` (out-of-core), `finish() -> ValidationReport`, `tee_reader()` (loader-backed paired columns), and `needs_resident(sink) -> bool` (exception 1b). It tracks `folded_tables`, paired-fed tables and row counts. `validate()` is bind, one `observe` per table, then `finish`.
- **Resident completion choke point.** In `_pipeline_route_dispatch.execute_route`, immediately after any executor returns and before `settle`, `complete_resident_validation(session, result.outputs, ctx)` observes each not-yet-folded table and calls `finish`. This covers sequential and out-of-core without a sink, mixed resident output and all physical drivers. After `settle`, the same block calls a plain callable proxy once per output table. The callable's observation is a count-check because the resident table was already folded. Guard test: V4 route matrix. Mutation: remove the resident completion call (M12).
- **Pre-commit completion choke point.** `bind_validation_session` uses a `ContextVar` beside `bind_gate`. `observed_commit` calls `active_validation_session().finish()` after `gate.before_commit(sink)` and before it reads publication evidence or enters `try: sink.commit()`. `ValidatorFailedError` is therefore a validation failure, never a COMMIT failure. Abort remains owned by `OutputPublish` and the sequential executor's existing failure unwind. The proxy does not finish or abort.
- **Capability-preserving write proxy.** `observe_sink(sink, session)` in `validators/_sink.py` selects one of three narrow shapes: callable only; write/commit/abort; or the four-member `TransactionalSink` with `write_batches`. Only `write` and `write_batches` add observations. Commit and abort, when the selected inner shape has them, only forward. `__getattr__` delegates an attribute only when the inner sink has it, so helpers such as `bounded_write_batches`, staged-openers and publication evidence survive without fabricating protocol members. A write/commit/abort-only inner sink has no proxy `write_batches` and still fails `isinstance(proxy, TransactionalSink)`. Guard test: V7. Mutations: bypass observation (M5) and put `write_batches` on the three-member proxy (M13).
- **One proxy-aware sink-kind resolver.** `post_scan_sink_kind` in `config/_post_scan.py` follows the observer's read-only `inner_sink` marker, with cycle protection, then returns the real class token. `_pipeline_route_dispatch`, both readability calls in `pipeline/_post_scan.py`, and `physical/_snapshot.py` already go through this function; none inspect `type(sink)` independently. Thus wrapped `ParquetTransactionalSink` and `StagingSink` stay readable, and the physical plan hash keeps the inner kind. V4 covers both wrappers and proves the integrity gate ran. Mutation: return the proxy class token (M14).
- **Choke point for "validators never pick a route".** Every routing read is deleted (section 4 table). A sentry (`tests/sentry/test_validators_do_not_route.py`) walks the AST of every module under `src/decoy_engine/execution/` and fails on: any subscript or `.get` of the `validators` key; any name, parameter or attribute spelled `validators`, `validators_requested`, `config_validators`, `validators_config` or `validators_ooc_*`, including truthiness tests (`if validators:`, `bool(validators)`, `not validators`, `len(validators)`); any import of `decoy_engine.validators` other than the public names. The allowlist holds exact `(path, function, public name)` identities for lifecycle wiring in `execute_route`, commit wiring in `observed_commit`, loader tee wiring in `execute_sequential_route`, and the `session.needs_resident` call in sequential eligibility. The sentry checks every caller of those public helpers, so the allowlist cannot become a bypass. Mutation: re-add the check at `:253` (M6), or `if validators:` at `_pipeline_routing.py:144` (M10).
- **Keyed folds in any order.** Each keyed fold keeps a key map (filled from parent batches) and a pending map. For `fk_intact`, the pending value is the exact child count plus the first `FINDING_INDEX_CAP` row indices. For `parent_window_respected`, the pending value is an arrival-ordered list of every child observation needed after the parent arrives, each `(row_index, parsed_date)`; repeated children with one parent key append and never replace an earlier child. Before each append, the fold reserves that observation's estimated bytes against the session's existing key-state budget and refuses with `validator_key_state_over_budget` if it would cross the ceiling. When a parent arrives, the fold evaluates every list item and releases that key's list. Each failure increments one exact counter. The fold offers the row index to its shared capped-smallest-index accumulator. This accumulator retains the lowest `FINDING_INDEX_CAP` indices regardless of parent-key resolution order. `finish` emits those retained indices sorted in row order. Thus retained pending child state is bounded by the resolved validation budget even when many children share one parent key. Parent arrival order cannot change the report. `reconciliation_holds` keeps per-key child sums and counts and compares them to the parent cells when both sides have finished, so it is order-free. There is no parent-first rule and no refusal for order.
- **One date format per table column.** `parent_window_respected` takes the first non-null value of each date column it reads (the parent start and end columns, the child column), calls `guess_datetime_format` once, and passes `format=` to `to_datetime` on every batch of that column; `format="mixed"` when the guess is `None`, which is what `to_datetime` does for a whole column in that case. The format is fold state, set by the first batch that has a non-null value.
- **Key-state budget, one early figure.** `bind_validation_session` calls `resolve_budget(ctx.out_of_core_budget_bytes)` once in `_pipeline_route_dispatch.py` and gives its `budget_bytes` to the session. The session owns that separate ceiling and refuses before a key-state allocation crosses it. It does not use the out-of-core faker-pool carve and `GenerationBudgetLedger` does not count validator reservations. That deliberate independent ceiling avoids a late dependency on a ledger constructed at `generation/_streamed.py:365-373`; total generation memory can therefore include both the generation ceiling and the validator ceiling, and V6 measures the combined RSS. No fraction or second budget formula is introduced.
- **Where the new calls go (no 600-line module grows).** `_pipeline_route_dispatch.py` (under the cap): bind, proxy wrap, resident completion, callable delivery and report storage (about +35). `_publication_observer.py` (202): active-session finish (about +5). `config/_post_scan.py` (under the cap): proxy-aware resolution (about +12). `_pipeline_routing.py` (566): net negative. `out_of_core/_rewrite_pass.py` (387): one line moved. `_pipeline_finalize.py` (478): net negative or flat. No edit to `_pipeline_auto_chunk.py` (600), `generation/_streamed.py` (600) or `_sequential.py` (679 of 680). `_pipeline_context.py` (600) and `_chunked_output_sink.py` (600) only lose lines. `_transactional_sink.py` (598) is not edited: the proxy lives in `validators/_sink.py`. A test pins each of those five files at or below its count at `70881ad79`.
- **Principles.** Single responsibility: verdict rules stay in each validator module; bookkeeping, order and budget live in the session; publishing knows only that a proxy observes it; routing knows nothing about validators. The change pain removed: nine copies of one decline, a second validator engine for out-of-core, and a hook per route. Open/closed for routes: a new sink route needs no validator edit. Dependency inversion: the session receives its budget and source reader.
- **One place per fact.** Shape: the registry entry. Cap: `FINDING_INDEX_CAP` in `validators/_types.py`. `leak_check` skip reasons: `plan_scope` in `validators/_scope.py`, which the CLI also calls for `decoy validate`. Report: `ValidationSession.finish`. Date format: the fold's first non-null value. Sink identity through an observer: `post_scan_sink_kind` only.
- **House style.** Typed `RowSpan`, no loose argument lists. No flag arguments: `observe`, `observe_published` and `observe_pair` are named entry points over one core.

## 13. Pre-mortem

- A route publishes through a path that does not use the observed sink (for example a new internal collector that writes a file itself): `observed_commit` refuses with `validator_table_not_observed`, because the session never observed those rows. A resident route that omits outputs is caught by the same count invariant. A loud failure, not a silent skip.
- A sink helper is reached through the proxy's `__getattr__` and writes a table itself (not through `write` or `write_batches`): the count check in `observed_commit` refuses. A unit test lists the inner-sink methods that write and asserts the proxy overrides each.
- A user relies on the full index list for more than 10,000 failures: the count stays exact, and the changelog names quarantine as the way to get every row.
- A native route's output differs from pandas on a validated column (Unicode normalization on `hash`): the verdict follows the published bytes. The parity file already names the difference.
- `reconciliation_holds` on a very large parent, or a child-first order with a large pending map: the budget refuses before the first scoped write. The message names the table and says to set `execution_mode: full_frame` or give the run more memory.
- A lazy CSV source with `leak_check` on a streamed route is read twice (scoped columns only). V6 records the cost; a resident or Parquet source avoids most of it.
- Out-of-core starts rewriting a non-key column after the mask step: the paired fold reads `out` at `yield out`, after every rewrite, so it still reads published values.
- A proxy hides the readable identity of an engine sink: every decision and the physical snapshot call `post_scan_sink_kind`, whose V4 mutation returns the proxy token and fails both wrapped-sink rows.

## 14. Plan decisions

1. `FINDING_INDEX_CAP` is 10,000 per finding with an exact count. The cap depends on configuration, not route, so evidence is route-independent.
2. `leak_check` naming a `keep` column emits a warning and exits 0, as the audit specifies. It is not a configuration error.
3. A plain callable sink with validators runs resident. Validation finishes before the callable receives any table, preserving the guarantee that a validation failure publishes nothing.
