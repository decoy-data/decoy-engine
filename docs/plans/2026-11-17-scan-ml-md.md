## 1. Guarantee and non-goals

Guarantee. After M-2b, an engine config that turns NER on and names no model uses
`en_core_web_md` 3.8.0 for `pre_scan`, `post_scan`, `text_redact` and `text_mask`, through one
constant (`DEFAULT_NER_MODEL`). A scan decides a hit at md's own calibrated rate 0.122. A host that
lacks md is refused before any row is read, with a code that names the fix; nothing falls back to sm
on its own. A config that names `en_core_web_sm` keeps sm and its 0.211. No output surface gains a
field, and none carries a cell value. After M-3, every CLI install hint names the engine's default
model and its pinned wheel, never an unpinned `spacy download`.

Non-goals:

- No new calibration method and no change to either measured rate. 0.211 and 0.122 stay; no
  constant moves to make a test pass.
- No `en_core_web_lg` or `en_core_web_trf` support. They stay refused for scans with
  `provider.ner_model_uncalibrated`.
- No fix for the md miss at 1 cell in 10 (0.085 against 0.122) and no fix for `location` hits on
  organization names. Owner questions Q4 and Q5 record them as known limits.
- No `decoy models install` command. That is row 32a part C1. This row only changes which model C1
  and the `-ner` image install, through the same constant.
- No change to the `-ner` image plan beyond the model it carries (row 90a, CLI `plan/rel-image`).
- No raised cap, pin ceiling, sentry baseline or allowlist. The one new sentry has a fixed, exact
  allowlist of the sites this plan names. New reason codes, if review adds any, take
  `since=UNRELEASED`; none is planned.

Size: M-2a1 9 production files and about 250 changed lines; M-2a2 10 production files (one new
module) and about 450 changed lines; M-2a3 2 production files and about 400 changed lines (most in
tests) plus a 284-line fixture; M-2b 1 production file plus
`examples/ner_redaction_demo.py`, the frozen schema snapshot, docs and about 300 changed lines; M-3
(CLI) 3 production files and about 150 lines. Public names added to `decoy_engine.detection`:
`DEFAULT_NER_MODEL` and `NER_MODEL_WHEELS` (re-exports of existing names, MED-7), `NerSurface`
(2.3) and `resolve_ner_model` (2.3). The private module alias `NER_MIN_RATE` is removed.

### 2.2 Plan hash

The config dumps keep their current rule: `ner_model` is dropped at the default
(`config/_pre_scan.py:90`, `config/_post_scan.py:118`), and `pre_scan` is not hashed. So:

- configs that never set `ner_model` keep their `pipeline_config_hash` and now run md. The hash
  records config intent, not model identity. Model identity lives in the records: every report, the
  detector-run log and the run result carry `ModelRef`. Two runs with one hash and different models
  are told apart there. M-2b updates the docstring of `test_scan_ml_hash_stability.py` and the plan
  hash note in `docs/compatibility-contract.md` to say this;
- configs that set `post_scan.ner_model: en_core_web_sm` now dump it, so their hash changes once;
- configs that set `post_scan.ner_model: en_core_web_md` stop dumping it, so their hash changes once.

The hash-stability test lists both moved cases by name with the reason (owner question Q3).

### 2.3 One model resolution (M-2a1) and one not-installed message (M-2a2)

Today the model a config resolves to is computed in seven places: `resolve_ner_config`
(`execution/_strategies/_ner_config.py:63`), `_text_mask.py:124`, `out_of_core/_mask_group_c.py:329`
(its docstring already logs the fold as a follow-up), `plan/_checks.py:421`,
`plan/_seed_envelope.py:276`, `verification/postmask/_model_findings.py:76`
(`block.get("ner_model") or DEFAULT_NER_MODEL`) and the omit-at-default checks at
`config/_pre_scan.py:90` and `config/_post_scan.py:118`.

M-2a1 adds one resolver in `detection/ner.py`, beside the constant:

- `resolve_ner_model(value: str | None) -> str`: `None` or empty resolves to the default; anything
  else goes through `validate_ner_model_name` (`detection/types.py:24`);
- `resolve_column_ner(ner_value) -> tuple[str | None, list[str] | None]`: the column
  `provider_config.ner` semantics that `resolve_ner_config` holds today (false for off, `true` for
  the default, a mapping for a named model and entity filter), moved down and calling
  `resolve_ner_model`;
- `is_default_ner_model(name: str) -> bool` for the two omit-at-default checks.

Every surface calls it: `resolve_ner_config` becomes a one-line delegate (kept for its execution
callers), `_text_mask.py`, `_mask_group_c.py`, `plan/_checks.py`, `plan/_seed_envelope.py` and
`_model_findings.py` call `resolve_column_ner` or `resolve_ner_model`, and the config omit checks call
`is_default_ner_model`. `_ner_rate.ner_rates(model=None)` and `_model_status.ner_status(model=None)`
resolve through it (M-2a2). The resolver sits in `detection`, the lowest layer every caller already
imports, so no caller adds an import-linter ignore (`plan` calling `execution` would have needed
one). `plan/_checks.py` is at its 700-line hard max; the fold removes lines there, so it shrinks.

After M-2a3, `DEFAULT_NER_MODEL` is read in exactly four places, and A-1 holds this list and no
other: its declaration and the resolver in `detection/ner.py`, the re-export in
`detection/__init__.py`, and the two config field-default declarations `PreScanConfig.ner_model`
(`config/_pre_scan.py:65`) and `PostScanConfig.ner_model` (`config/_post_scan.py:83`), which stay
plain defaults so the frozen JSON schema keeps showing the default value. A-13 checks that every
route resolves the same model.

The not-installed message today names nothing useful: `refuse()` (`detection/_model_status.py:136`)
raises with the registry text "NER model not installed.", and `ensure_ner_available`
(`detection/ner.py:217`) names a Python symbol and says `text_redact` for a `text_mask` column.
M-2a2 adds one builder in `detection/ner.py`:

- `NerSurface` (an enum: `PRE_SCAN`, `POST_SCAN`, `TEXT_REDACT`, `TEXT_MASK`) maps each surface to
  its opt-out key (`pre_scan.ner_model`, `post_scan.ner_model`,
  `provider_config.ner.model`, `provider_config.ner.model`) and its display name;
- `model_not_installed_message(model, surface)` returns the text: the surface, the refused model
  name, the wheel URL from `NER_MODEL_WHEELS` for that model (or "no pinned wheel; install it from
  a local wheel" when there is none), and "or set `<opt-out key>` to an installed calibrated model".

`ensure_ner_available(model, surface=None)` and the scan refusal both use it; the run-time call
inside `detection/ner.py:282` passes no surface and gets the column wording
(`provider_config.ner.model`), since the plan check has already refused with the exact surface.
`load_detectors` takes a `surface` argument from its two callers (`profiling/_model_pass.py:138`,
`verification/postmask/_model_findings.py:77`) and builds `ModelUnavailableError` with that message
and the existing code. The message is value-free: the model name is a validated package name
(`detection/types.py:24`), the URL is a constant, and the key is a constant. No cell, path or config
value other than the model name enters it.

### 2.4 Resume carries the resolved model identity (M-2a2)

`build_fingerprint` (`delivery/resume/_fingerprint.py:74`) takes caller-chosen `components` and
needs only one; the config hash omits `ner_model` at the default. A caller that passes no engine
version could therefore resume an sm-started run, keep its completed sm tables and finish the rest
with md. M-2a2 closes this inside the engine:

- a new `plan/_ner_models.py` (exported from `plan/__init__.py`; `_fingerprint.py` imports it from `decoy_engine.plan`) holds `run_ner_models(config) -> tuple[tuple[str, str], ...]`: for
  each NER surface the run uses (pre-scan with `ner` in `detectors`, post-scan with `ner` in
  `detectors`, every `text_redact` and `text_mask` column with NER on), the surface name and the
  model from the 2.3 resolver. Column surfaces are grouped by strategy, so no table or column name
  enters the fingerprint;
- `build_fingerprint` appends one engine-owned component per surface:
  `("decoy-ner:<surface>", "<model>==<version>")`, with several models in one surface joined in
  sorted order and the version from `installed_model_version` (a metadata read, no spaCy import), or
  `unavailable` when no package is installed;
- a caller component whose name starts with `decoy-ner:` raises the existing value-free
  `ValueError`, so a caller cannot forge or mask the identity;
- `plan_resume` (`delivery/resume/_plan.py:102`) already compares `components` and refuses with
  `RESUME_FINGERPRINT_CHANGED`; nothing changes there.

The record shape `decoy-resume-run/v1` is unchanged (components are already a list of string pairs).
A resume record written before M-2a2 for a run with NER lacks the component and is refused once,
which is the intended result. A run with no NER surface gets no added pair, so its fingerprint is
byte-identical to today.

## 3. Established solutions

Search run (2026-11-17, plus the M1 survey in `plan/scan-ml` section 4.3): spaCy model cards for
`en_core_web_sm` and `en_core_web_md` 3.8.0 (same OntoNotes NER training data; md adds 20k static
word vectors; both MIT); Microsoft Presidio's default NLP engine configuration (it ships
`en_core_web_lg` as the default and documents swapping to a smaller model for size); pip's
hash-checking mode (`--require-hashes`); the Neyman-Pearson fixed-false-positive approach behind the
Q7 rule (Tong, Feng and Li 2018), already cited in `detection/_ner_rate.py`.

What the design follows:

- Default model choice: a published pretrained spaCy pipeline, chosen by measured recall at a fixed
  false-positive bound (the vault comparison plus #616). Presidio shows a vector model as the
  default is normal practice; md is the size trade between sm and lg.
- Supply chain: the wheel is not on PyPI, so it is pinned by URL plus SHA-256 and installed with
  `--no-deps` from a checked local file (the existing ner-gate loop and the C1 design). This is
  pip's hash-checking model.
- One default in one place: a constant read by every site, with a literal sentry, per
  `cross-cutting-concerns.md`.

Custom code left (revision 3 added it): the one resolver, the one not-installed message builder, the NER-surface list `run_ner_models` and the engine-owned fingerprint components. Beyond those, only changing the constant, removing a duplicated literal and an alias, and
one sentry test.

## 7. Measurement and where tests run

Tests run only on VMs (or the Mac), never on the devbox. The `ner` tests need spaCy and both wheels,
which the lock-faithful `$DECOY_VENV` may not have. A run therefore builds a separate venv from the
lock with the `ner` extra and installs every pinned wheel by hash, the same steps as ner-gate. It
never touches `$DECOY_VENV`:

```text
VMRUN_LINUX=1 ~/bin/vm-run engine <wt> 'set -e
  d=$(mktemp -d)
  export UV_PROJECT_ENVIRONMENT=$d/venv
  uv sync --frozen --extra dev --extra ner
  $d/venv/bin/python -c "from decoy_engine.detection.ner import NER_MODEL_WHEELS as w; [print(p.url, p.sha256) for p in w.values()]" > $d/wheels.txt
  while read -r url sha; do f=$d/$(basename "$url"); curl -fsSL -o "$f" "$url"; echo "$sha  $f" | sha256sum --check -; uv pip install --python $d/venv/bin/python --no-deps "$f"; done < $d/wheels.txt
  DECOY_REQUIRE_NER=1 $d/venv/bin/python -m pytest -m ner --tb=short -q
  rm -rf "$d"'
```

This is the ner-gate job's command (`.github/workflows/ci.yml:265`, `pytest -m ner` over all of
`tests/`), so the VM selects the same tests CI does.

`VMRUN_LINUX=1` keeps the measurement on the same OS and architecture as ner-gate. Non-ner tests use
the normal form, `~/bin/vm-run engine <wt> '$DECOY_VENV/bin/python -m pytest ...'`.

The M-2a3 cost record (A-4) comes from a test-local helper that reuses `_ner_rate.ner_rates`, the
corpus loaders, and `clopper_pearson_upper` and `ceil_to_thousandth` from `test_ner_min_rate.py`;
nothing is re-implemented. Timings use `time.perf_counter` and `resource.getrusage` peak RSS in a
fresh subprocess per model, three repeats, median recorded. The record states the VM, CPU, Python
and spaCy versions, and lands as `docs/records/2026-11-<dd>-ner-md-default-evidence.json` (dated
on the day it is measured).

Stop rule for M-2b: M-2b starts only after the owner has seen the M-2a3 record and answered Q4 and
Q5. If md's org-name `location` rate in A-4 is above 0.5, or md's scoring time is more than 3x
sm's, M-2b stops and goes back to the owner. Why 0.5: the vault sample measured 0.137 on 284
names; a fixture rate above half would mean md flags most organization-name columns as locations
in almost every schema that has one, so the Q4 "known cost" answer would rest on the wrong number.
Why 3x: sm and md share one pipeline and differ only by static vectors, so a gap that large
points at a setup fault, not at the model.

## 14. Pre-mortem

- A parity or golden test starts comparing md output with an sm golden and is "fixed" by moving the
  golden. Guard: M-2a pins every model-specific test to sm first (A-2), so M-2b moves no expected
  value outside A-7 to A-10.
- ner tests skip on the VM because the venv lacks spaCy, and the slice reports green. Guard:
  `DECOY_REQUIRE_NER=1` in the section 7 command and in ner-gate.
- A builder lowers md's 0.122 so the 1-in-10 fixture flags. Guard: a non-goal; M-T2 recomputes the
  rule from the digested corpora and fails on any edit.
- A second default appears in the CLI or the image. Guard: A-11, and rel-image's rule that C1 is the
  only install path.
- Users upgrade and NER scans start failing on sm-only installs. Guard: the refusal names the fix and
  the opt-out; the CHANGELOG `Breaking:` line and the guide say it.
- md is slower or heavier than expected on small CI runners. Guard: A-4 records it before the switch,
  and the section 7 stop rule.
