### Fixed (residual-PII checks fail closed, POSTMASK-FAIL-CLOSED, 2026-11-24)

- The resident-frame residual-PII check now reports an error finding when its source comparison raises, as the batch check already did. Before, the failure read as a clean check.
- Both residual-PII checks report a source comparison that raised on a column the run may write, even when no detector fires on it. One writer query (`decoy_engine.plan.column_access.written_columns_by_table`) names the written columns per table: each entry's own target, joint_mask siblings, composite bundles, `derive` targets and every FK child key column. `run_pipeline` asks it once, over the run's own graph and registry, and the post-scan reads that answer. A passthrough column is exempt from the source comparison only when the query proves no other writer owns it, so a passthrough on a joint_mask sibling, an FK child key or a table with an unknown writer is now compared. Both checks compare and count list, map and struct cells in one form, so a list never equals its one element and a constant list counts as one value on either path.
- A source distinct count that failed is no longer read as a varied source. The column is graded as both a constant and a varied source. When the two final grades differ the finding is an error, and when they agree that grade stands, so unchanged hash output with an email hit stays `fail`.
- The detectors and the post-scan runner read every cell as text through one rule. Bytes of any kind, including numpy fixed-width bytes and Arrow binary columns, decode as strict UTF-8, so a byte-encoded email reads as the email. Bytes that are not UTF-8 raise `UnreadableCellError` (a `DecoyError` and a `ValueError`) with fixed text and the new code `runtime/cell_unreadable`, and the check reports an error finding.
- A post-scan check that cannot compare a source cell no longer turns a blocking finding into a warning. A coded engine error inside the policy comparison propagates unchanged.
- The resident column suite reads nullable integer columns as exact integers, as the staged batch reader does, so a nine-digit number with a null in its column no longer reads as a float and goes unscanned.
- A deferred (report-only) post-scan whose suite raised now reports the error class in `pass_failed_with` with a verdict, where the run used to continue with no report. Under `post_scan.ner_findings: fail` that `check_error` blocks the run, because the NER findings it would have judged are unknown.
- A relationship that cannot be read now raises from the gate's tee and quarantine hooks instead of being left for the check.
- One comparison authority (`decoy_engine.internal.cell_identity`, PM-1) decides whether a source cell is the same value as its output cell and counts distinct cells, on the frame, standalone and batch paths. The frame path reads the frame cells before any Arrow conversion, so `{"k": None}` and `{}` stay two values and a column Arrow refuses keeps its identity. Numbers compare at their exact value, so `Decimal("0.1")` is not the float 0.1 and an int past 2**53 is not its nearest double; dates and durations compare as exact attoseconds whatever their unit, calendar months stay apart from durations, and an aware instant matches a naive one at its UTC or its own wall clock. Text matches a non-text cell only when it is a listed export spelling of it (`str`, `repr`, a plain numeral of the same value, ISO and pandas date text, or JSON), so a Decimal written as its exact text, or UTF-8 bytes written as their text, now count as unchanged. Equal sets in another order are one value. A NumPy record at any depth, a container that holds itself, or an unhashable object of no known kind is refused with `CellNotComparableError` (a `DecoyError`, fixed text, classified as `post_scan/check_error`): only that column gets an `error` finding, and its other columns and tables are still checked. A policy column whose source holds one value passes as unchanged only when its output holds one value too.
