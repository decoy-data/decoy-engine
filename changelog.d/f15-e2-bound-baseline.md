Breaking: `scan_baseline.on_drift: fail` now needs `scan_baseline.sha256`, the SHA-256 of the baseline file. Without it the config is refused with `config/scan_baseline_unbound`.

### Added (bound scan baseline, F15 E2, 2026-11-18)

`scan_baseline.sha256` pins the baseline file's bytes. `decoy_engine.profiling.bind_baseline` checks the digest before it parses, then reads the file with the strict JSON parser; a changed file raises `BaselineBindingError` with `pre_scan/baseline_digest_mismatch`, and a file that is not a readable `scan-set/v1` scan with `pre_scan/baseline_unreadable`. The config refusal for `on_drift: fail` without a digest is `config/scan_baseline_unbound`. `evaluate_drift` returns a `DriftVerdict` (`passed`, `warned`, `failed`) that names each drifted table and column and holds no cell value. `starter_config` takes `baseline_sha256`. The strict JSON parser now also refuses a number that overflows to infinity, such as `1e999`. The digest is part of the plan hash when `on_drift` is set. The new names are exported from `decoy_engine.profiling`.
