### Added (native text span splice core, TEXT-REDACT-RUST-SPLICE S1a, 2026-11-24)

The native companion gains an additive entry, `text_span_splice`, with a contract getter, `text_span_splice_contract_version`. It stays on ABI 3, so an older core keeps working with a newer wheel and a newer core falls back when the entry is missing. The entry reads one `string` or `large_string` Arrow column and detects the requested built-in detectors per cell. Each detector has its own replacement (or keeps its text), and unmatched gaps have a separate replacement. It returns pieces of a string array and a Boolean mask. The mask is true for a non-null cell that Rust could not handle, so the caller repairs that cell in Python. A cell whose byte length does not fit the detector's 32-bit offsets is declined the same way. Overlaps follow the existing leftmost-longest rule, and the first requested detector wins an exact tie.

The core now reads one compatibility result per companion for the candidates loader, the legacy text_mask splice loader and the new entry. The result checks the ABI tag, the catalog version, the detector order and a known-answer test on synthetic cells. No job calls the new entry yet, and masked bytes do not change.
